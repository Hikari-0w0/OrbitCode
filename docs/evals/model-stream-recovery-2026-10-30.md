# 模型流式异常诊断与恢复（2026-10-30）

历史评测中出现“无效的增量结构”。当时没有保存异常帧，不能判断是上游错误包、非兼容增量，还是其他响应异常；本次没有宣称还原该次服务端响应。

本地 HTTP 模拟流可确定复现三个问题：流内错误对象被当作普通增量、SSE `event: error` 名称丢失、首个无效增量不可重试。改动不依赖评测题号、仓库或模型名称，不新增运行时依赖，也未调用真实模型。

## 行为

- SSE 同时提供保留事件名的接口，原仅返回 data 的接口继续兼容。
- 明确的错误包优先于正常增量解析，提取可验证的 HTTP 状态和常见服务错误代码；未知错误不猜测可恢复性，消息不包含上游正文。
- 早期无效 JSON/增量结构允许使用既有 `transport.maxRetries`、退避和请求接纳预算重试；已产生正文、推理片段、完整工具调用或完成事件时不自动重放。空内容完成后的异常同样保留失败诊断并停止，避免向已完成的调用方投递第二次请求。未完成工具参数随失败请求丢弃。
- 异常结束会取消响应读取并关闭旧请求；用户取消立即传播，不被诊断进度事件延迟。
- 明确的流内额度不足不按普通限流重试；Retry-After 继续沿用现有处理。

## 证据

`progress.model.failure` 经 Agent Loop 和运行跟踪器进入 `modelAttempts[].failure`：包含 kind、status、retryable、action、retryAfterMs，以及可选 frame。frame 仅记录异常原因类别、事件序号、字符数和固定字段类型，不记录任意键名、服务端文本、工具参数或凭据。

含 failure 的日志采用 schemaVersion 7，读取器兼容旧 3–6 版；不含诊断的记录维持现有版本选择。完整运行导出保留诊断。request-progress 的 stage 仍表示异常发生前最近可见阶段，不等于服务端没有发送任何字节。

回归覆盖流内 HTTP 错误、命名 error 事件、早期结构异常后成功、重试耗尽、输出后禁止重放、未完成工具参数隔离、响应读取取消、日志脱敏与旧日志读取。本地 tmux/CLI 链路覆盖异常帧恢复、无效工具参数、修正参数后读取及完整导出；该链路使用本地 HTTP 替身，不能证明真实服务稳定性或解题通过率改善。

## 评测边界

本次变更只包含运行时异常处理、脱敏诊断及对应回归，不包含外部评测执行器或新的真实模型评测结果。

旧实验和其冻结脚本不更改。修复版评测必须建立新实验，不能将旧 `resume` 当作新版 Agent 复测。原始与恢复后结果、失败请求的未知用量分别保留。
