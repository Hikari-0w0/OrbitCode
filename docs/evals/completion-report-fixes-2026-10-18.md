# 完成报告修复与验证（2026-10-18）

## 问题与行为变化

历史运行 `f08e6ce6-5daa-4f25-809b-23d0943c2bc3` 的任务是生成简易登录注册系统。记录包含成功的测试和 HTTP 冒烟命令，但 `report_completion` 五次被拒绝，最终触发 `repeated-tool-failure`，没有正常交付总结。运行记录不是工作区快照，本次没有对生成项目做独立验收。

本次调整共享核心，Web 和 CLI 使用相同规则：

- 报告只需提交 `checks` 和 `blockers`；运行时计算汇总状态，旧 `status` 字段保留兼容。旧声明 `complete` 无法覆盖 `failed` 或 `not-run`。
- HTTP 检查允许引用成功的脚本或 Node 测试，不再要求顶层命令包含 `curl`。显式 curl 命令的已知本地端口冲突仍拒绝；接受命令证据不代表独立验证脚本断言、响应语义或全部需求。
- 报告参数或证据校验失败不再进入普通工具失败预算。首次失败允许修正一次，再次失败进入无工具收尾；不增加既有时间或迭代预算。
- 收尾请求使用 `toolChoice=none`。模型仍返回工具调用或协议异常时，运行时提供保守总结，不执行新工具。
- 被拒绝报告保持 `unverified`，保留合法检查；引用无效等存在问题的检查降为 `not-run` 并清空引用。新写入会使先前完成评估失效。
- 跨轮或不存在的引用、失败证据、写入替代验证、缺少写入后验证以及未收敛的质量门禁继续受限制。
