# 子 Agent 接纳契约与上下文清单（2026-10-21）

## 本轮交付

用户要求继续改善。本轮落实[架构路线](../specs/sub-agents/architecture-roadmap.md)中不可变接纳计划与上下文来源清单，保留既有Agent Loop、调度器、工作区协调器和权限网关，没有增加运行时依赖或Agent框架，也没有提交或推送。

过去的委派准备闭包分别读取任务、角色、模型、工具集合、历史和预算。本轮将它们统一为版本化内部规格与运行时执行计划：

- `ChildTaskSpecification`记录任务目标文本、所选Provider/model、有效工具及必需MCP集合、角色指纹、父/角色权限基线、权限规则指纹、工作区访问模式、预算与交付方式。
- `createChildTaskPlan`复制并递归冻结角色、配置、历史、继承Skill、权限规则和系统提示上下文；集合先转换为数据数组。完整凭据配置只在执行计划内存中持有，不进入公开摘要。
- `BackgroundTaskManager`接纳后绑定taskId、scope、epoch、父turn/call和绝对deadline；准备接收这份契约。最终收窄预算同时用于执行和TaskView，删除旧生产start的位置参数及重复预算字段。测试适配仅位于夹具，不保留第二条生产接纳路径。
- `TaskView.admission`公开非凭据摘要；`preparedContext`记录实际准备结果。Web任务接口直接提供同一份信息，CLI评测从共用Runtime读取；本轮没有新增CLI显示命令或页面组件。

这完成了接纳与执行快照收敛，不代表完整的结构化制品/验收契约或任务组总预算已经实现。任务目标仍来自既有prompt，交付仍是回复与工具事实，验收需要独立检查。

## 一致性与权限

`childToolNames`统一计算父工具上限与角色允许/禁止集合的交集。工作区模式、子工具策略及MCP要求使用同一有效能力。角色同时允许和禁止某个MCP工具时，禁止优先，不再错误地要求发现或初始化该工具；未被禁止但缺失的必需工具仍拒绝。

`ChildToolPolicy`复制接纳时工具集合，源Set后续新增不能扩权。执行PreparedToolCall时仍检查当前工具授权，权限网关仍检查当前父模式、规则和Plan模式，冻结快照不会冻结动态授权。无角色Fork的继承MCP只是工具上限，保持既有可选能力语义。

新增的实际Runtime跨Provider回归还确认了原有归属错误：子请求使用角色指定的secondary-model，接纳摘要也选择secondary，但子运行日志仍记为父primary。日志现在从接纳契约读取Provider。有效修复前失败在`provider-before.txt`，退出1；修复后同一用例通过，`provider-after.txt`退出0。此用例使用HTTP模型替身，未调用另一真实付费Provider。

## 上下文证据

接纳清单记录可用历史的消息数、序列化字节数/SHA256、卸载引用数量、是否含压缩摘要、继承Skill定义与激活指纹，以及系统提示上下文指纹。defined的继承历史为空；Fork使用接纳时已经可用的完整配对快照。

准备阶段先验证历史与接纳哈希一致，再使用原共享history迁移路径复制卸载正文。成功复制后记录实际存储正文的UTF-8字节数和SHA256、源/子引用映射；最多列16个映射，完整复制数、字节总数和省略数始终保留。实际迁移后的历史另有消息数、字节数和哈希，不混淆接纳原引用与新引用。

这些数值不是模型服务端token计数，也不包含整份最终系统提示或工作区文件。已压缩/丢弃的历史无法恢复；原引用正文在准备阶段读取，父存储删除或读取失败会使准备失败，不能据此承诺接纳时已复制正文。单次来源历史仍受既有1MiB迁移上限限制，准备失败沿用一次清理协议。引用映射本身不授予跨会话访问权。

本阶段契约与清单在当前运行时存活，不提供重启后的任务恢复、完整契约持久化或跨进程exactly-once保证。完整凭据配置没有被放进TaskView、清单、父结果摘要或运行日志。
