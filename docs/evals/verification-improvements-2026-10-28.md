# 通用验证闭环改善（2026-10-28）

本次改善针对命令失败传播、修复前后验证和完成声明的证据一致性。实现不读取评测数据、题号、目标仓库、gold 补丁或隐藏测试，也没有针对特定模型的行为分支。

## 实现

1. macOS Seatbelt 与 Linux bubblewrap 的单次命令、受管进程统一通过系统 Bash 启用 `pipefail`，不加载个人配置。失败命令经过输出管道后仍返回非零状态；保留 stdout、stderr、退出码、信号、超时、取消和截断字段。不启用 `errexit`，显式错误处理和多命令顺序保持 shell 语义。
2. `CompletionTracker` 生成每轮请求的执行证据摘要：最近八项文件写入或命令事实，包含轮次、批次位置、证据 ID、工具成功/失败、可用退出码、超时/取消及截断标记。并行结果按调用顺序排列，摘要不包含原始命令、路径、输出或模型推断。摘要计入上下文预算，不写入对话历史，下一轮用户请求重新开始统计。
3. 通用执行提示要求缺陷修复前优先复现、修改后复验同一入口，依据公开契约和故障机制选择边界；区分新增、修改过和原有测试；最终依据实际差异与最后修改后的检查报告结果。无法复现或缺少条件时保留限制，允许有依据地继续工作。

证据摘要不解释测试断言，不把退出0、写入成功或最终回复升级为验收通过，不阻止模型结束或改变预算。只读任务不要求制造改动或运行固定测试集合。

## 边界

Linux 运行镜像现在需要 `/bin/bash`；macOS 使用系统自带版本。`pipefail` 返回管道最右侧非零状态，输出消费者提前关闭导致的 SIGPIPE 也可能使管道失败。分号后的成功命令、显式错误吞掉、嵌套 shell 或项目脚本仍可能覆盖内部状态，因此 shell 退出0只能证明 shell 返回成功。

输出达到配置容量时仍会截断；摘要提示证据缺失，但不会恢复未保存的输出。需要完整输出时应在执行前重定向到工作区日志，并保留检查退出码、读取失败正文。

复现选择、测试覆盖和最终表述仍需要模型执行通用指导。没有重跑 SWE-bench-Live 或调用真实模型，因此当前只确认机制与确定性链路，尚不能宣称修复通过率提高。
