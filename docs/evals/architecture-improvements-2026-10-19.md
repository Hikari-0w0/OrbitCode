# 现有功能效率与架构收敛（2026-10-19）

## 改善范围

本轮保留 Web/CLI 共用的 Agent Loop、工具、权限、上下文和会话持久化，完成以下改动，没有新增运行时依赖。

1. `npm test` 通过固定入口收集 `src/`、`tests/` 下的 `.test.ts` 和 `.test.tsx`，保留指定文件的定向运行。原默认发现漏掉 25 项 TSX 测试，同时收集了临时注册登录项目的 8 项测试；此前默认的 611 项与明确仓库范围的 628 项并非相同集合。
2. 模型设置支持最大输出 Tokens、思考模式、DeepSeek/SiliconFlow 参数格式和适用的思考预算。省略修改字段保留已有值，显式 `null` 清除覆盖、恢复服务商默认值。服务端检查整数、窗口上限和格式约束，编辑窗口时也检查保留的输出预算。
3. 文本增量按 32 ms 合并，轮次变化、工具、审批、终止、异常和清理之前刷新；积累达到 8192 字符时立即刷新。已完成消息单独缓存渲染，工具结果序列化随结果缓存，自动跟随使用即时滚动，用户主动跳转仍保留平滑滚动。
4. 独立 Skill 的模型、上下文、工具、资源和进程装配集中在 `src/runtime/skills/session-factory.ts`；启动失败会释放已创建的进程控制器。仍复用共享会话工厂、权限及模式策略，子执行不新增递归能力。
5. 运行记录保留工具 `callId`，新增按用途区分的模型用量记录；旧 schema 3/4/5 仍可读取，新用途统计使用 schema 6。后台记忆任务的用途统计随任务状态保存。

## 用量统计口径

`modelUsage.scope=self` 只覆盖当前执行本身。`categories` 区分 `agent`、`summary`、`memory`，保存请求数、已报告用量的请求数、失败/未完整结束请求数、请求耗时累计及已报告 Token 小计。

- `requests` 统计 Provider 流调用次数，不代表内部 HTTP 重试次数；既有请求阶段记录继续描述 Agent 请求尝试。
- `reportedRequests < requests` 表示存在用量缺失，Token 小计不能作为完整账单。不会以估算补齐。
- 耗时是调用耗时之和，不冒充并行任务墙钟耗时，也不包含全部排队、授权和持久化时间。
- 独立 Skill 使用独立统计，并通过 `parentRunId`、`parentCallId` 关联父运行；父记录不重复累加子执行。
- 记忆提取发生在主轮保存之后，统计保存在记忆任务状态中，通过来源的会话、turnId、savedRevision 关联。主运行停止时不能宣称已包含尚未完成的后台提取消耗。
- 既有页面累计 usage 保持其原有主执行口径；新增统计供诊断和导出使用，不将不同模型的 Token 直接折算为费用。
