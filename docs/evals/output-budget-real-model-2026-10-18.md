用户明确授权后，使用当前 `deepseek-flash`、DeepSeek 官方 API、非思考模式和 `max_tokens=32768` 运行两项真实模型用例。通过 CLI 调用共享 Agent Runtime；本次没有复跑 Web 的 Agent HTTP/SSE 入口。

两项均以 `final-response` 结束、CLI 原始退出码 0、会话保存成功，独立验收通过。定向用例在**一次模型响应中输出 14007 completion tokens、42595 字符的 write_files 参数**，以 `tool_calls` 正常结束并成功写入两个文件，实测超过原默认 8K 输出边界。没有实际生成满 32768 tokens，不把本结果表述为已验证所有最大长度或通用成功率。

## 执行条件和证据

- 两项分别使用全新空工作区、独立托管设置、会话、日志和用户配置根目录；未加载日常 MCP 配置，未修改日常任务工作区。
- 每项预算为300秒、32轮，权限模式为permissive；原有路径、敏感文件、命令沙箱和结构化参数校验仍有效。
- 本地透明转发器只向实际官方端点转发请求，记录非敏感请求字段、实际结束原因、工具参数字符数及服务端usage，不替换模型响应。实际API Key只在转发进程内存中，子CLI仅持有临时代理令牌，令牌不落盘。
- 全部24次请求显式携带 `max_tokens=32768`，均返回HTTP 200，结束原因为 `tool_calls` 或 `stop`，无 `length` 或其他非成功终止。
- 对两个隔离证据目录的54个文件进行当前实际API Key的精确匹配扫描，0处匹配；扫描结果仅记录文件数和匹配数。
- 注册登录任务请求原文为“写一个简易的注册登陆系统”；模型自主分批实现，最大单次输出3718 tokens。因此额外执行单次长输出用例，要求一次write_files写出两个各240行的确定性TypeScript夹具，避免仅凭较短输出宣称预算边界已验证。
- 请求与运行元数据保存源码指纹、模型配置、请求预算、开始/结束时间；没有把当前历史文件状态冒充过去任务的可重放初态。

## 失败与恢复

1. 注册登录任务第一次批量写入在同一批次重复指定路径，被参数校验拒绝；模型随后调整批次继续完成。该失败没有产生部分写入。
2. 注册登录任务首次测试命令失败，模型修改测试脚本入口后重跑成功；独立重跑生成项目的 `npm test` 仍为8/8。不能将本轮描述为“所有工具首次均成功”。
3. 长输出用例的首次完成报告把写入结果当作过程验收的验证证据，被拒绝。一次修正后接受为partial，无重复生成或整轮失败。独立检查随后从真实调用轨迹确认了单次写入行为。

注册登录任务的模型报告因“无浏览器工具”保留前端交互not-run及blocker，因此原始状态为blocked。外部验收另外用真实浏览器完成注册页切换、注册后带回用户名、登录显示用户、刷新保持会话及退出返回登录，页面错误和控制台记录均为0。外部验收不回写或改造原始报告状态。

长输出验收脚本首次误选revision 0，得到“0次写入”的夹具错误；首次结果单独保留，改为选取最高修订revision 1后确认一次写入成功。该验收器错误与Agent自身工具失败分开记录。

## 独立验收与边界

注册登录项目另外启动新的服务进程和独立数据文件，使用验收器自己的测试数据验证：静态页面与资源、未登录401、输入校验400、注册201、重复用户名409、错误密码401、HttpOnly/SameSite Cookie、有效会话、登出失效及无明文密码落盘。验收没有依赖模型自报的“完成”结论。服务、浏览器及tmux会话测试后均关闭。

两项日志累计reported usage为456496 tokens（注册登录358575，长输出97921），是本次记录值，不是历史任务的性能对照或独立账单。只有两项样本，且入口、权限和MCP条件与原Web运行不同，不能据此断言历史中断一定由8K限制引起，或推导普遍性能提升。
