# 子 Agent 生命周期阶段诊断与复测

日期：2026-10-21。用户授权继续测试和开发。本轮在现有生命周期、工作区协调、接纳契约和共享请求预算之上补齐稳定的阶段诊断；没有增加运行时依赖，也没有提交或推送。

## 结论与架构选择

原有有界活动日志可能被等待、查询事件挤出，无法稳定回答任务时间花在准备、资源竞争、执行还是清理。新增纯领域模块 `TaskPhaseTimeline`，由现有任务管理器在真实生命周期边界记录，不从日志反推，不接管状态转换、取消或资源释放。它是独立的被动观测记录，避免形成第二套调度状态机。

执行阶段固定为：准备排队、准备、资源等待、执行排队、执行、清理、终态发布。使用单调时钟的相对毫秒偏移；未经历的阶段可跳过，各阶段连续分割总耗时。首次有效停止请求保留原因、阶段和偏移，终态记录停止至终态的耗时。终态计时固定，重复等待和状态查询不能使它继续增长。

投递另有 `deliveryTiming`：记录暂存次数及首次/末次暂存、提交、失效偏移，提交延迟从执行终态计算。投递不会重写执行计时或执行结果。任务完整视图、HTTP 与 CLI 共用投影；模型的状态查询只返回当前阶段、总耗时和停止摘要，避免反复注入完整阶段表。压缩的子结果交接也保留固定长度的执行计时。

## 实现与证据边界

- `src/core/sub-agents/task-timing.ts`：阶段模型、单调偏移、停止和投递计时；不含 IO。停止原因复用 `types.ts` 的领域联合类型。
- `src/runtime/background-task-manager.ts`：在准备、资源接纳、FIFO入队/启动、清理和终态发布的实际所有权边界记录。测试可注入时钟。
- `src/runtime/agents/delegation.ts`、`child-result-delivery.ts`：紧凑状态与有界结果交接，缺失停止字段显式为 `null`。
- `scripts/evals/assert-task-timing.ts`：复用确定性判据检查阶段有界、顺序、连续、总和、终态固定及停止/提交延迟算术，接入四套已有评测，不削弱原有验收。

准备函数内部失败回滚仍计入准备阶段，管理器无法观察其内部每一步；执行阶段包含会话/MCP初始化、模型/工具与结果存储，进一步归因需结合子运行日志。没有为独立 Skill 新建同类计时存储。

已投递的执行计时可随父会话检查点保存；当前管理器的投递计时不持久化。未投递或未保存的记录不保证运行时关闭后仍可查，子原生日志和正文文件也没有新增这套计时。它不构成重启恢复或文件快照能力。
