当前自主执行策略见[2026-10-22 全运行时移除人工审批](approval-removal-2026-10-22.md)：用户明确要求主Agent与子Agent都移除；共享门禁仅允许/拒绝，Web/CLI、独立Skill及MCP不再等待批准。最终792/792回归，9次真实模型尝试7通过/2次MCP失败保留，补测及实际浏览器通过；此前同日审批生命周期方案已被替代。

默认角色在30秒转后台后审批失效的问题、任务审批与前后台解耦及默认权限复测，见[2026-10-22 子Agent审批生命周期改善](sub-agents-permission-lifecycle-2026-10-22.md)：802/802自动回归、5个真实模型样本通过，另保留1次未调用模型的浏览器夹具准备失败。此记录补充此前宽松自定义角色矩阵的覆盖缺口。

在 OrbitCode 完成任务后，向能够访问本项目和本地数据的 Codex 提交：

```text
按 docs/evals/README.md 分析 Workspace <workspaceId> 最新一轮已结束运行。
先定位并报告 runId、conversationId、开始时间和任务摘要，再分析必要证据。
使用本文诊断模板，最多给出三个主要问题，区分事实、原因假设和证据缺失。
只诊断，不改代码，不重跑任务，不调用真实模型。
```

也可以直接指定 runId 或 conversationId。同一会话多轮共同完成一个任务时，明确分析范围为整段任务，并分别列出每轮；一轮停止不等于整个任务结束。

## 操作步骤

### 1. 定位运行

按用户指定 runId，或在指定 Workspace/会话内筛选已结束记录并按 finishedAt 排序。先只读取必要摘要字段；不用整份日志、配置或全部会话正文填充分析上下文。

报告 runId、source、conversationId、Workspace、开始/结束时间、停止原因及所选范围。能唯一定位时直接继续；存在多个合理候选时展示候选，请用户选择。没有记录时报告缺失，不自动启动任务。只有运行结束才落盘的摘要不能证明不存在正在运行的任务，也不能排除进程崩溃导致的日志缺失。

### 2. 按需读取证据

优先使用现有 CLI 导出指定运行，无需运行 Web 服务或加载模型配置：

```bash
mkdir -p tmp/agent-evals
npm run cli -- export-run <run-id> --output tmp/agent-evals/<run-id>.json --without-context
```

完整会话也可通过 `npm run cli -- export-conversation <conversation-id> --output <path>` 导出，无需 Web 服务或有效模型配置。

上述尖括号是待替换占位符。第一次省略卸载的上下文对象，仍会包含检查点和正文，不能把 `--without-context` 当成脱敏开关。

若问题依赖卸载内容，改用另一个文件名导出：

```bash
npm run cli -- export-run <run-id> --output tmp/agent-evals/<run-id>.full.json
```

导出器拒绝覆盖已有文件；已有结果可以复用，需要重新导出时使用唯一后缀。产物保存在已忽略的 `tmp/`，不提交完整对话、代码正文或凭据。检查 `warnings`、检查点 availability 和 persistence；保存失败、旧引用被删除时，明确证据不完整。

从 before/after 检查点识别本轮增量，用工具 callId、iteration 和 sequence 关联事实。若无法可靠确定差量，就标注限制，不假定所有 after 消息都是本轮内容。读取当前源码只能解释当前实现，不能证明历史运行也使用相同代码。

展示时间线中的 argumentsJson 可能为安全摘要；需要实际调用参数时，按 callId 查找 checkpoint.context.messages 的 assistant-tool-call。若已被压缩或卸载，再查可用上下文对象；仍缺失则标注无法还原，不把空摘要当作模型实际传入空参数。

### 3. 先提取事实，再作诊断

| 维度 | 当前可提取的事实 | 不能直接推导的结论 |
| --- | --- | --- |
| 任务结果 | 用户请求、最终回复、verification、实际工具验证结果 | final-response 或模型自述不等于任务成功 |
| 效率 | 迭代数、工具调用/失败次数、运行耗时、授权等待 | 并发工具耗时不能直接求和当作墙钟耗时；阶段总时长不可从最后 progress 精确还原 |
| 模型响应 | firstModelOutputMs、请求尝试的阶段摘要 | 首次输出不是网络首字节；工具调用要收集完成才产生对应事件 |
| Token | 日志累计 usage 或 unavailable，必要时查看检查点 | 缺失不是 0；该值来自 Agent 普通调用事件，不代表已统计独立摘要请求等全部计费用量 |
| 决策质量 | 参数错误、失败后动作、重复读取/调用、验证是否在修改后 | 重复读取可能合理；少调用几次不必然意味着质量更高 |
| 可恢复性 | persistence、前后 revision、中断标记、后续轮次 | 对话恢复不保证文件副作用回滚或可无损重放 |

每个问题写出“观察到什么 → 在哪里 → 影响什么”。再提出原因假设，并说明如何证伪。优先检查工具契约、执行结果与上下文，不把所有失败归结为 Prompt。

### 4. 统一报告模板

```markdown
# 运行诊断：<runId 或明确的多轮范围>

## 范围与结果
- 会话 / Workspace / 时间：
- 任务及验收标准：
- 结果：通过 / 部分通过 / 失败 / 无法判断
- 证据完整性：检查点、引用、源码版本、文件初态是否可用

## 事实指标
| 轮次 | 迭代数 | 工具调用 / 失败 | 耗时 | 授权等待 | Token | 停止原因 |
| --- | --- | --- | --- | --- | --- | --- |

## 主要问题（最多三个）
### <问题标题>
- 分类：明确缺陷 / 维护问题 / 效果假设 / 证据缺失
- 事实及影响：
- 证据：runId、iteration、callId 或导出 JSON 字段路径
- 原因假设及置信依据：
- 最小改进建议：
- 如何验证 / 什么结果会否定该假设：

## 保留的有效行为
记录合理恢复、必要验证等，不为了减少轮数而删除正确行为。

## 下一步
优先处理项、仍需的数据、本次没有执行的验证。
```

报告本身可以写入 `tmp/agent-evals/<run-id>.review.md`。只有经过检查且不含敏感内容的通用发现才整理进受跟踪文档。

## 优化后如何比较

先从历史 E1–E6 中选定目标任务，固定任务文本、文件初态、独立验收标准、模型与配置，并记录代码/Prompt 版本。原始运行若没有可恢复的文件初态，只能用于诊断，不能冒充受控基线。

后续获得修改授权后，一次调整一个主要因素，在相同条件下多次复测，记录结果分布、失败类型和人工干预。独立验收优先于模型完成声明；效率比较要同时报告质量，不能通过少做验证获得虚假的加速。具体任务预算、模型调用和工作区修改属于复测阶段，当前整理不自动执行。
