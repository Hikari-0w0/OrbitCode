## 架构决策与实现

### 引用访问统一承担读取与搜索

`read_context` 保留 offset/limit 定位和连续分页，新增可选 query。搜索是区分大小写的字面量匹配，对已授权引用的原始正文全文扫描，返回 searchedFrom=0、searchedUntil、totalCharacters、complete、精确 matchCount、最多4段摘录和 matchesOmitted。缺失仅证明该字面量没有匹配，不证明语义事实不存在；搜索原始工具结果，不自动解析 JSON 字段。

`LocalContextStore` 与 `LocalConversationStore` 的读和搜共用各自同一条私有正文加载路径，沿用会话绑定、引用语法、符号链接检查、16 MiB 对象上限和取消检查。全文只加载一次；共用 Unicode 码点 KMP 扫描，支持重叠匹配，不引入正则执行或任意文件访问。父级、子级和独立 Skill 的共用子会话工厂接入相同能力。

低预算下只缩减搜索摘录，保留精确计数和扫描范围；连覆盖元数据也容纳不下时明确报告 capacity，不伪造扫描成功。普通分页仍按实际展示内容校正游标，按已知偏移定位阅读合法；读到末页不能证明前面的区间读完。

`ChildHandoff` 从成功工具结果记录最多4条完整搜索事实（引用、query、callId、计数与总字符数），沿用 reads.omitted 表达省略。事实进入既有正文/工具事实存储和结果交付；极端交付压缩时保留省略计数，不把模型文字报告作为扫描事实。

### 类型选择成为逐轮输入契约

现有 version=1 的 ParentExecutionContract 增加可选 delegationKind，合法值为 defined/fork；省略保持模型自行选择。Web 请求、运行时校验和历史检查点统一接受该字段。输入区新增“子任务类型”；CLI 支持 `/delegation delegate-only fork`、`/delegation collaborate auto`，单次运行支持 `--delegation-kind fork`。

契约收窄 agent 工具 Schema 中的 kind 枚举，并在参数解析和执行入口拒绝不匹配类型，错误调用不创建任务。用户可在后续轮次切换；旧任务的 status/wait/cancel/result 仍可操作。不识别自然语言关键词、不替换模型参数，也不保证模型一定调用工具或完成任务。父级分工、子角色权限及 Workspace 限制继续各自生效。

### Fork 快照维护受限引用别名

真实复测发现父模型可能把父引用写进子 prompt。历史迁移原先复制正文并生成新引用，子 prompt 中的旧引用因此读取失败。

现在只对本次历史快照中已成功复制的对象登记父引用到子副本的映射，并由子会话的读/搜入口解析。它是执行内的受限别名：不回读父存储、不解析或改写自然语言 prompt、不接纳未复制的其他父引用、不跨任务共享，也不增加定义式空历史权限。失败/取消仍按既有生命周期清理子副本。

## 失败归因与剩余限制

1. 已修复的引用问题：父 run `6417c93d-e15c-4edf-b0a4-91ce3c60d55f`，子 run `65a61c52-8e32-4a04-805c-95cae1ffcb22`。子实际请求旧父引用后得到 context-reference，未伪称没有匹配。受限别名修复后增加确定性回归，并保留后续全部模型样本。
2. 尚存语义失败：父 run `ed953bbb-adbc-4678-8012-caa937f3dd61`，子 run `7522727a-1a99-4bf4-a55c-a34557593b9e`。运行时全文扫描70239字符，matchCount=1，摘录包含完整 `RELIABILITY_NEEDLE_😀_740`；模型却只交付 `RELIABILITY_NEEDLE_`。该样本按独立标准判失败，未扩大轮数或加入标记专用提取规则掩盖问题。

本轮保证的是运行时有确定的全文搜索能力、可核对的覆盖事实与明确的创建类型限制；不能保证模型总选择正确 query、理解语义、准确引用全部文字或完成任意任务。若后续任务需要精确结构化抽取，应另外定义可验收的抽取协议，而非给当前通用子 Agent 添加字符串补丁。
