## 主要发现

### 1. 提取提示与严格协议不一致：已修正提示，保留校验

A 组后台任务显示候选校验失败。对保存的首轮 checkpoint 进行受控提取重放后，模型输出 evidence 为对象；原提示写“evidence 为 {...} 或 {...}”，而实现要求非空数组。所有候选均被字段校验拒绝。

B 组纠正重放则输出 project-knowledge + replaces；实现只允许 category=correction 替代旧笔记。提示原先仅写“明确纠正可使用 replaces”，没有明确要求改类别。

本轮仅修正 memory-extractor 的提取提示：明确数组、合法示例、字段长度、可选字段省略规则、correction 与用户纠正证据，以及不重复保存既有内容。没有容忍非法对象、降低凭据/来源校验、自动转换类别或自动重试模型。真实协议反例已加入 memory-validation 回归测试。

### 2. 候选语义与纠正目标仍不稳定：未通过质量验收

C 组初次只提取用户偏好，遗漏了已实际读取的项目标记。纠正候选虽使用 correction，却将用户偏好的 id 用作项目笔记的 replaces；项目作用域不存在该笔记，存储正确拒绝 conflict。因此项目知识仍为 0 条。

C 组其他输出包括：将本地文件观察分类为 reference 却没有 reference-only 来源；将从 read_memory 读出的旧偏好当作新用户偏好；B 组产生同义的用户偏好重复。schema 与作用域校验可以拒绝非法结构/目标，但不能保证提取完整性、语义去重或事实真伪。

### 3. 最终回复的“已记住”不能当作后台成功证据

A 组首轮回复声称长期偏好已记录，但后台实际失败、笔记数为 0。B 组纠正回复说旧值失效，后台未提交，后续新会话仍回答 MARBLE-82。C 组新会话缺少项目标记笔记时，把项目代号蓝鹭当作真实标记。这些是模型语义与表达问题，不能用 final-response 或 saved 修订掩盖。

真实笔记结果以管理面板任务状态、实际 scope 笔记和后续读取得到的内容为准。后续改进应单独验证“前台不提前确认异步写入”和“无事实记忆时明确未知”。本轮没有为凑通过数继续反复调整提示。
