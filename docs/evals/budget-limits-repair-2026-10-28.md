## 工程改动

### 调度预算统一

命令调度不再固定压到120秒。共享 Runtime 从本轮沙箱快照取得命令/进程就绪预算，传入 Agent Loop 和调度器；子 Agent 和独立 Skill 使用相同配置。实际执行仍受命令自身的 timeout_ms、配置最大值、本轮总截止和取消约束。调度器只创建一次截止时间，等待工作区许可也消耗同一预算，不在取得许可后重新开始计时。未提供配置的独立调度调用保留原默认值。

### 可配置工具失败策略

托管设置新增 `toolFailurePolicy`，可在“设置 → 运行偏好 → 工具失败处理”保存：

|值|行为|
|---|---|
|`strict`|保留原有精确重复、同工具同类及连续失败预算|
|`exact`|只有相同工具/错误类别/参数重复达到阈值才硬停止，换参数可继续诊断|
|`warn`|保留策略提醒，不因这套失败预算终止|

旧设置默认 strict。warn/exact 不改变权限、路径隔离、未知工具处理、总时限、模型轮数或任务组预算。失败指纹最多保留512项，避免长循环无限积累。Web/API/本地存储严格校验，共享 Runtime 将策略传给主执行、委派子任务及独立 Skill。外部评测入口明确使用 warn；日常用户设置没有自动修改。

### 短临时目录与依赖缓存

`commandSecurity.temporaryDirectory` 新增 `short`，命令评测预设改用该模式：按规范工作区路径哈希，在系统 `/tmp` 下创建当前用户专属目录，检查所有者、0700权限、符号链接与真实路径。路径长度不随工作区深度增长，避免 Unix socket 的路径长度限制；不会授权整个 `/tmp` 或兄弟工作区。

临时目录中通过 `npm_config_cache`、`PNPM_HOME`、`BUN_INSTALL_CACHE_DIR` 和 `XDG_CACHE_HOME` 指向各自缓存。workspace/short 模式支持同工作区跨命令复用，isolated 模式仍随每条命令清理。短目录不会随单命令退出自动删除，需要按需清理；文件工具仍限制在原工作区，外部临时文件应由命令通过 `$TMPDIR` 使用。

评测 runner 仅从前一次隔离评测的包缓存做 APFS 副本，排除 npm 日志，不复制旧业务源码、会话、测试答案或日常用户缓存。已有依赖树继续按原方案复用。缓存不可用时保持空目录运行，不声称已经命中缓存。

### 受管进程状态等待

`process_status` 新增可选 `wait_ms`（0–60000）和 `wait_for`（output/exit）。缺省仍即时返回；等待到新输出、退出、超时或取消时返回/结束，等待超时返回 running 不代表进程失败，取消等待不自动终止进程。等待受父运行截止约束，不再被文件读取的10秒调度预算提前截断。

通用执行指导要求先检查已有进程，再使用状态等待；依赖安装核对已有工具、锁文件和最小包范围，避免多次全仓安装或用长 sleep 代替状态观察。这是能力与指导改动，不保证模型一定使用该接口。
