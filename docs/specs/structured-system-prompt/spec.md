# 结构化系统提示与缓存可观测性 Spec

状态：已批准

## 背景

OrbitCode 当前只在每个 Agent 请求开头加入一段简短的 Plan 或 Do 模式说明。身份、系统约束、行动策略、工具选择、语气和输出要求没有形成稳定且可审查的层次；环境信息与会话级指令也没有独立的 system 级注入边界。模型虽然已经能够循环调用工具，但在工具选择、编辑前读取、计划模式约束和最终输出质量上主要依赖模型自身习惯，难以稳定复现。

OpenAI 兼容服务通常按重复请求前缀复用提示缓存。若固定规则、动态环境、模式状态和历史没有清晰分层，后续功能很容易把每轮变化的内容混入固定前缀，降低缓存复用并增加维护风险。当前 Provider 已解析输入、输出和总 Token，Web 也能展示累计用量，但尚未保留上游报告的缓存 Token 或缓存命中状态。

本阶段建立一套入口无关的结构化系统提示契约：固定规则以确定顺序组成稳定前缀，环境、可选上下文和会话级状态通过带明确标签的 system 消息在其后注入，普通对话历史继续作为对话消息追加。与此同时扩展用量可观测性，并准备可重复的人工对比任务，用真实行为检查提示是否改善 Agent 的指令遵守情况。

## 目标

- 以七个职责单一、顺序固定的模块取代现有简单全局指令，使冲突规则有明确优先级并可独立维护。
- 保持固定系统提示和同一模式下的工具定义内容及顺序稳定，把会变化的信息放到稳定前缀之后，兼容 OpenAI 风格的自动前缀缓存。
- 用真正的 system 级补充消息向模型提供环境、可选上下文和当前会话指令，并确保这些内容不会被误当成用户问题回答。
- 按对话轮次强化 Plan/Do 等会话级指令，在约束可靠性和重复 Token 成本之间取得可测试的平衡。
- 解析并展示上游实际报告的 Token 用量与缓存信息，同时兼容不报告缓存字段或完全不报告用量的 OpenAI 兼容服务。
- 通过一组固定的典型任务人工比较改造前后在工具选择、编辑前读取、Plan Mode 和输出风格方面的表现。

## 假设

- “稳定”指在程序版本、Provider 配置、Agent 模式和可用工具集合不变时，固定系统提示与工具定义的内容、顺序和序列化结果保持一致；不会为了伪造稳定性而让 Plan Mode 向模型公开其无权执行的副作用工具。
- 继续保留现有 Plan Mode 服务端权限边界：模型只看到读取文件、查找文件和搜索代码三个只读工具，Do Mode 看到当前完整工具集；每种模式各自形成稳定的工具定义序列。
- 环境信息采用最小必要白名单，至少能够让模型识别当前授权 Workspace、路径语义和可用运行环境，但不包含 API Key、完整环境变量、受保护文件内容或不必要的 Workspace 绝对路径。
- 会话级指令的强化节奏按用户对话轮次计算，而不是按同一用户请求内的 Agent 模型迭代计算；进入一个新的连续模式阶段时使用完整版本，之后按一个固定且可测试的间隔再次使用完整版本，其余轮次使用精简版本。具体间隔在技术计划中确定，模式切换后重新开始计数。
- 七个固定模块中的“任务模式”只定义 Plan/Do 等模式的共同规则和动态注入契约；当前实际模式及其本轮完整或精简约束属于会话级动态补充，不写入固定模块。
- 自定义指令、已激活 Skill 和长期记忆在本阶段只有组装扩展点：调用方实际提供内容时才能注入，没有内容时不产生空标签、占位消息或虚假能力。本阶段不新增这些内容的发现、加载、激活或持久化来源。
- 上游数值型缓存 Token 以 OpenAI Chat Completions 的 `usage.prompt_tokens_details.cached_tokens` 为基准；其他兼容服务只有在返回本阶段明确支持且可验证的等价字段时才显示缓存信息，不从耗时、文本长度或重复请求推测命中。
- CLI 当前仍使用纯文本会话且不执行 Agent 工具；本阶段保证系统提示组装能力入口无关，但只要求现有 Web Agent 流程完成动态模式、缓存指标和人工对比闭环。

## 功能需求

- F1：固定系统提示必须由七个独立职责模块组成，并严格按“身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出”的优先级从前到后拼装。模块之间以一个空行分隔，不得因环境、模式、历史或单次请求内容改变顺序。
- F2：七个固定模块必须共同给出足以指导编程 Agent 的完整行为边界，包括身份与职责、不可被低优先级内容覆盖的系统约束、模式遵守、先理解再行动和持续验证、专用工具选择及失败恢复、专业自然的语气，以及简洁可核验的最终文本要求。重复规则不得产生相互矛盾的指示。
- F3：固定系统提示必须作为请求的第一个 system 消息；其后依次注入环境信息、自定义指令、已激活 Skill、长期记忆和本轮会话级动态指令，最后才是既有对话历史与当前用户消息。可选内容缺失时直接省略，剩余项仍保持相对顺序，不生成空模块。
- F4：环境信息和每类动态或可选补充内容必须分别使用 `<orbitcode_environment>`、`<orbitcode_custom_instructions>`、`<orbitcode_activated_skills>`、`<orbitcode_long_term_memory>` 和 `<orbitcode_session_instructions>` 这组稳定的特殊开始与结束标签，并保持 `system` 角色。固定规则必须告诉模型这些消息是运行上下文或约束，而不是用户提问；模型不得直接回答、复述或假装收到一条新的用户请求，也不得把补充消息计入普通用户对话历史。
- F5：环境补充消息必须只包含当前请求所需且允许披露的信息，并与实际授权 Workspace 和运行状态一致。环境缺失、非法或无法安全序列化时，请求必须在调用模型和产生工具副作用前失败；任何动态内容都不得通过标签闭合、角色伪装或消息拼接突破 system 与用户消息边界。
- F6：会话级模式指令必须按轮次选择完整或精简版本。一个连续模式阶段的首个用户轮次和达到固定强化间隔的轮次使用完整版本，其余轮次使用精简版本；同一用户请求中的所有 Agent 迭代必须看到一致版本。切换 Plan/Do 后，新模式的下一用户轮次重新使用完整版本，历史计数不得由模型输出或伪造消息操纵。
- F7：完整与精简模式指令都必须明确当前模式和权限边界。Plan Mode 必须要求只分析、读取必要上下文、必要时澄清并给出可执行计划，禁止声称已修改或自动执行；Do Mode 必须要求围绕用户目标自主行动、读取工具结果、验证成果，并在成功、可恢复失败或安全停止时给出真实说明。提示约束不能替代现有服务端工具权限、最大迭代和停止条件。
- F8：固定全局工具规则与相关具体工具描述必须同时强调关键行为：能够由读取、查找、搜索、编辑等专用工具完成时优先使用专用工具，不以通用 shell 命令替代；修改或覆盖已有文件前必须先读取其当前内容并基于最新内容操作。工具描述不得混入 Workspace 名称、当前模式、轮次或其他动态数据。
- F9：对同一程序版本、Provider、Agent 模式、工具集合和固定配置发起多轮请求时，请求中的固定系统提示与工具定义必须逐项保持相同内容和顺序；环境、当前模式强化版本、会话状态、历史和用户输入只通过后续消息变化。不得发送 Anthropic 专用的 `cache_control`，也不得依赖供应商托管的文件或代码执行能力实现缓存。
- F10：OpenAI 兼容 Provider 必须在保留输入、输出和总 Token 的同时，解析上游实际提供的缓存 Token 或明确缓存命中字段。缺失、为 `null`、未识别或当前服务不支持缓存字段时，仍须正常完成响应并把缓存信息标为不可用；不得伪造为零、未命中或协议失败。可识别字段中的数值必须为非负安全整数，并与总输入 Token 保持合理关系；无效缓存值不得污染已验证的基础 Token 用量。
- F11：Agent 过程事件必须为每次模型迭代携带可用或不可用的基础 Token 和缓存信息，并提供语义明确的累计值。只有上游提供足够数值时才能累计缓存 Token 和计算命中比例；某次迭代缺少缓存数据时，累计缓存数值不得伪装为完整精确值。缓存信息的加入不得改变最终回复、工具调度、停止原因或历史提交语义。
- F12：Web 页面必须在对应助手轮次中展示上游报告的输入、输出、总 Token 和缓存信息；数值型数据可展示缓存 Token 及命中比例，仅有命中状态时展示状态，未报告时明确显示不可用。展示逻辑不得参与系统提示组装，不得把缓存缺失显示成错误，也不得把模型或 Provider 的原始未校验字段直接注入 DOM。
- F13：项目必须提供一组版本化、可重复执行的典型人工对比任务，至少覆盖：代码搜索时优先专用工具、编辑已有文件前先读取、Plan Mode 只规划不执行、Do Mode 在行动后验证、工具失败后的恢复或如实停止、最终回复的简洁与证据导向。对比应固定任务输入、Workspace 基线、模式、Provider 与模型配置，分别记录改造前基线和改造后观察结果，不使用自动评分冒充人工判断，也不得记录凭据或敏感文件内容。

## 非功能需求

- N1：系统提示的模块定义、确定性拼装、动态补充消息构造和轮次策略必须位于独立、入口无关的严格类型 TypeScript 核心能力中，不依赖 React、浏览器、Next.js 路由或具体页面状态。
- N2：模型适配层只负责把已组装消息与稳定工具定义映射到 OpenAI 兼容请求，并解析流与用量；页面和 Route Handler 只负责输入输出适配、依赖组装和展示，不复制固定提示文本或实现提示优先级。
- N3：固定模块、动态消息、可选模块和用量信息使用明确的判别结构表达；消息角色、顺序、标签、轮次计数、缓存数值和 Provider 响应均需接受运行时或边界校验，避免无必要的 `any`、类型断言和字符串位置猜测。
- N4：系统提示和工具定义的稳定性必须可由自动化测试按规范化请求内容直接比较；测试不得以真实缓存命中作为唯一判定，因为是否命中仍由具体 Provider、模型、前缀长度和服务状态决定。
- N5：不得新增运行时依赖，不引入 Agent 框架、Agent SDK、Anthropic 专用缓存字段、托管文件工具或托管代码执行；优先复用现有消息协议、工具注册中心、Provider 流、Agent 事件和 Web SSE 契约。
- N6：动态环境、自定义指令、Skill 和记忆内容均视为可能包含不可信文本；必须有长度或数量上限、安全标签边界和明确的缺失行为。API Key、认证头、完整环境变量、受保护内容、内部堆栈和不必要的绝对路径不得进入模型请求、事件、页面、日志或人工对比证据。
- N7：新增提示不得削弱 Workspace 相对路径、路径穿越防护、敏感文件保护、命令沙箱、工具参数校验、Plan 权限、取消、超时、最大迭代、结构化错误和唯一停止事件等既有边界。
- N8：缓存字段解析必须宽容兼容、保守展示：未知附加字段被忽略，缺失可选字段不使响应失败，只有经过验证的上游数据才能进入事件与 UI；既有只报告基础 Token 或完全不报告用量的服务继续可用。
- N9：固定提示内容应避免无必要重复和易变信息；相同输入的组装结果必须确定，模块间只使用规定的空行，工具定义排序不能依赖不稳定枚举或请求时状态。
- N10：新增用量与缓存展示在桌面和窄屏下均可辨认，并使用纯文本或安全结构化内容；不可用、零缓存和实际命中必须在语义上可区分，页面无控制台错误和状态错位。
- N11：现有 Agent Loop、Plan/Do、Provider SSE、多工具调度、会话历史、取消、Web 契约、工具安全和构建检查必须继续通过；新增测试与人工对比不得使用或泄露真实凭据。

## 不做的事

- 不实现项目级指令文件的发现或加载，包括但不限于自动读取项目中的 `AGENTS.md`、其他规则文件或递归目录指令。
- 不实现自动长期记忆、记忆抽取、向量检索、数据库或跨会话持久化；长期记忆仅保留有真实输入时可注入的顺序契约。
- 不实现 Skill 的发现、安装、激活或执行机制；已激活 Skill 仅保留有真实上游内容时可注入的扩展位置。
- 不接入真实 MCP 服务，不增加远程工具、远程资源发现或新的工具种类。
- 不实现自动化模型评估、LLM-as-judge、分数门禁、线上 A/B 测试或自动选择“最佳提示”；本阶段只准备并人工执行典型任务对比。
- 不实现显式缓存预热、缓存键管理、缓存生命周期配置、跨 Provider 缓存统一、费用估算或对缓存命中的承诺；只优化稳定前缀并展示上游实际报告的数据。
- 不实现上下文压缩、自动摘要、历史裁剪、Token 预算分配或会话持久化。
- 不把“编辑前读取”等提示规则升级为新的持久化授权或通用事务系统；现有服务端安全校验继续作为不可绕过的最终边界。
- 不为 CLI 增加 Agent 工具循环、Plan/Do 交互控件或缓存用量视图；仅保证核心提示能力不依赖 Web，以便后续入口复用。

## 验收标准

- AC1（覆盖 F1、F2）：在不提供任何动态或可选内容时组装固定提示，结果恰好包含七个非空模块，顺序为身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出，模块之间只有规定的空行；重复组装得到相同结果，内容不存在相互矛盾的行动或输出要求。
- AC2（覆盖 F3、F4、F5）：给定环境、自定义指令、Skill、记忆、会话状态、既有历史和当前用户输入，模型请求依次出现固定 system、带独立特殊标签的各项 system 补充、普通历史和当前用户消息；移除任一可选项后没有空标签或占位消息，环境与动态文本无法闭合标签、伪造角色或作为用户问题进入历史。
- AC3（覆盖 F6、F7）：在 Do 模式开始多轮对话、保持模式跨过一个完整强化周期、切换到 Plan 再继续多轮；捕获的请求显示每个连续模式阶段首轮和固定间隔轮使用完整指令，其余轮使用精简指令，同一用户请求内所有 Agent 迭代版本一致。Plan 全程只读规划，Do 明确执行、验证并如实报告结果。
- AC4（覆盖 F8）：检查固定全局工具规则及读取、查找、搜索、写入、编辑和命令工具描述，关键规则在全局与相关工具两层均存在且不含动态信息；用可控模型和人工任务验证代码搜索优先使用专用搜索工具，已有文件的编辑或覆盖调用前先出现针对当前内容的读取调用，而不是直接使用 shell 或盲写。
- AC5（覆盖 F9、N4、N9）：对同一 Provider 和模式的多次请求做规范化快照比较，固定 system 消息和工具定义逐项、逐字符、逐顺序一致，动态环境、强化版本、历史和用户输入只出现在后续消息；Plan 与 Do 各自保持稳定工具集合，所有请求均不包含 `cache_control`。
- AC6（覆盖 F10、N8）：用可控 OpenAI 兼容流分别返回标准缓存 Token、明确缓存命中状态、零缓存、缺失缓存字段、`null`、未知扩展字段以及完全缺失 usage；Provider 对受支持且合法的数据产出准确缓存信息，对其余情况标记不可用并继续完成响应，不把缺失解释为零或未命中，基础 Token 仍按已验证数据保留。
- AC7（覆盖 F10、F11、F12）：完成包含多次模型迭代的请求，其中各迭代分别报告数值缓存、零缓存和不报告缓存；核心事件与 Web 依次显示准确的本次 Token、可用缓存信息及符合完整性语义的累计信息，零与不可用可区分，命中比例只由合法数值计算，最终回复、停止原因和成功历史不受影响。
- AC8（覆盖 F5、N3、N6、N7）：向所有动态输入注入超长文本、标签片段、类似角色前缀、绝对路径和凭据哨兵，并触发无效轮次状态；系统在模型请求和工具副作用前安全拒绝或转义，模型请求、事件、页面、日志和测试证据不泄露哨兵值，既有 Workspace、Plan 权限、工具与停止边界保持有效。
- AC9（覆盖 F13）：人工对比清单至少包含六类典型任务，并为每项记录固定前提、预期指令行为、改造前观察、改造后观察和人工结论；实际运行结果能够逐项判断工具选择、编辑前读取、Plan 不执行、Do 验证、失败恢复和输出风格，不以未执行的自动评分或主观总分替代证据。
