# CLI 与 Web 功能对齐 Spec

状态：已批准

审批记录：用户于 2026-09-17 批准本规格，并授权连续生成其余三份文档后统一审核；随后用户明确批准四份文档并授权开始开发，实现门禁已通过。

## 背景

当前 CLI 只提供流式多轮文本对话和运行记录导出，交互会话仍仅保存在内存中。Web 已具有自主工具循环、权限审批、Plan/Do、上下文管理、会话持久化与恢复、完成证据和运行诊断。仅为 CLI 增加工具调用不足以实现功能一致，需要同时对齐会话生命周期、安全边界和可观察结果。

本规格取代旧 CLI 流式对话规格中对工具、持久化和上下文管理的阶段性排除项；旧规格仍作为历史记录保留。功能基线为本次调研时现有 Web 行为，不将历史文档中的设计意图视作已经实现。

## 目标

- 在终端完成与 Web 等价的编程任务：规划、审批、执行、验证、继续对话和恢复历史。
- 两个入口使用一致的 Agent 行为、工具安全策略和会话数据语义，后续核心能力更新可同时生效。
- CLI 独立启动，不要求先运行 Web 服务；终端交互不要求复刻浏览器布局。

## 假设

- 本轮覆盖现有 Web 的全部用户可操作能力，按运行闭环、交互控制、持久化互通分步实现，最终统一验收，不以第一步完成代表整体完成。
- 默认共用本机用户的会话库；在相同 Provider 和 Workspace 配置下，Web 与 CLI 可先后继续同一会话，同时写入必须被保护。
- Provider、Workspace 和凭据配置保持现有模型；CLI 启动目录用于定位默认配置，选择 Workspace 不隐式切换凭据来源。
- 工具可用性遵循现有平台限制，命令沙箱不可用时明确拒绝，不承诺新增平台支持。

## 功能需求

- F1：保留现有配置参数、Provider 选择、帮助、退出和运行记录导出；支持默认配置启动、列出及切换 Provider 和授权 Workspace。启动和切换后明确显示当前绑定、模式与会话标识；切换 Provider 或 Workspace 新建 Do 会话，不混用旧上下文。无效配置在请求前失败且错误不包含凭据。
- F2：CLI 支持与 Web 相同的自主 Agent 循环和当前工具集合，包括文件查找、搜索、读写、编辑、批量写入、命令执行、上下文读取、受管进程操作和完成报告。模型收到真实结构化工具结果后可以继续调用；参数无效、普通拒绝及可恢复工具错误不会直接破坏会话。
- F3：支持 Plan/Do 切换和对最新成功计划的明确执行操作。Plan 只暴露并允许当前 Web 的只读工具；模型输出不能自动切换模式。失败、取消、过期或其他 Workspace 的计划不可执行。执行有效计划时保留上下文并追加用户可见的执行请求。
- F4：支持严格、默认、放行权限模式及本次允许、会话允许、永久允许、拒绝四种决定。展示审批对象与范围；复用 Web 的规则优先级和安全校验。持久规则写入失败需明确提示，不能宣称保存成功。会话授权不因打开相同历史记录而跨进程恢复。
- F5：生成期间支持即时响应审批和取消；多个待审批请求可区分且不会互相误授权。普通输入、控制命令和审批答案不可混淆。Ctrl-C 取消当前运行或审批，空闲时可退出；退出或输入流关闭时回收运行资源。无交互输入时遇到人工审批必须拒绝或明确失败，不能自动允许或无限等待。
- F6：提供流式文本、模型阶段、工具开始与结果、权限状态、当前及累计 Token Usage、停止原因、耗时、副作用状态及完成验证详情。可查看完整工具结果；默认输出可控制体积。缺失 Usage 明确标记未报告，检查通过只代表所列检查通过。
- F7：复用 Web 的自动工具结果卸载、引用读取、自动摘要、失败熔断及手动压缩行为。提供手动压缩入口和压缩前后估算、估算来源及失败原因；上下文引用保持会话隔离，不因换入口失效。
- F8：支持会话新建、列表、查看、重命名、继续、清空、删除和完整会话导出，保留单轮运行导出。恢复会话时恢复 Provider、Workspace、模式、历史与上下文；绑定配置缺失时阻止执行并解释原因，不静默替换配置。清空恢复 Do，清空及删除同步清理相应上下文。
- F9：按 Web 的语义保存完整 transcript、部分输出、工具结果及中断状态，支持已有恢复与重试操作。异常退出后仅恢复有证据的完整检查点，提示可能已发生的副作用，不自动重放写入或命令。Web 与 CLI 或两个 CLI 同时修改同一会话时，冲突不得覆盖已有记录；保存失败明确显示未保存状态。
- F10：CLI 使用与 Web 一致的最大迭代数、运行时长、工具失败预算及上下文停止策略；每轮只有一个终止结果。取消、错误、超时和正常结束均结束待审批并回收本轮受管进程；停止生成不承诺回滚已发生的文件或命令副作用。
- F11：CLI 运行产生可由现有本地评估和导出流程读取的运行记录，包含会话关联、模型阶段、工具执行、终止及持久化状态；可区分 CLI 与 Web 来源。导出失败及记录写入失败有可理解反馈，不把日志成功写入当作任务验收通过。

## 非功能需求

- N1：复用领域核心和运行编排，避免维护两份 Agent 循环、权限判断、上下文算法或持久化协议；核心不得依赖 React、Next.js 或终端展示。
- N2：保持严格 TypeScript，默认零新增运行时依赖，遵守禁止 Agent 框架和托管执行的约束。
- N3：两端均保留路径、符号链接、敏感配置、危险命令和沙箱检查；终端输入或审批不构成绕过安全边界的理由。工具及模型输出不得通过终端控制序列伪造输入提示或审批界面。
- N4：凭据不进入参数、常规输出、错误和运行记录；不打印完整环境变量。导出的用户内容及工具输出按现有敏感数据规则处理。
- N5：兼容已有本地会话和导出流程，现有 Web 能力不得退化。交互终端及非 TTY 输入具有明确行为，不以富终端渲染作为功能前提。

## 不做的事

- 新增 Web 尚不具备的 Agent 能力、模型协议、多模态、云同步、远程服务认证或命令沙箱平台。
- 复刻浏览器的布局、动画、Markdown 富展示及响应式设计；对应信息和操作以终端形式提供。
- 将受管验证进程变为退出后持续运行的服务，或把检查点变成工作区文件快照。
- 自动提交、推送、发布或修改无关文档结构。

## 验收标准

- AC1（F1）：既有启动及导出命令继续可用；默认配置可启动；列出并切换两个 Provider/Workspace 时绑定正确、创建独立 Do 会话，旧会话可恢复；非法配置不发起模型请求。
- AC2（F2）：通过可控模型完成读取→编辑→运行验证→修复→最终回复的多迭代闭环，并对全部当前注册工具提供 CLI 接入覆盖；断言模型后续请求确实含工具结果。无效参数、未知工具和工具失败得到结构化反馈。
- AC3（F3）：Plan 下伪造写入和命令均被拒绝；有效计划经用户明确操作后进入 Do，沿用计划上下文；失败、取消、过期计划拒绝执行，模式命令不产生额外模型调用。
- AC4（F4）：覆盖三种模式和四种审批决定，以及 deny > ask > allow、目标变化、永久规则写入失败、规则重新加载和会话授权隔离；放行模式仍不能绕过硬边界。
- AC5（F5）：真实 TTY 中流式输出时可审批、区分多个审批和取消；取消后的迟到答案无效，下一轮可继续；非 TTY 的审批及 EOF 不挂起、不误授权，退出无遗留子进程。
- AC6（F6）：正常、工具失败、Usage 缺失及有验证报告的运行均有准确可读的阶段和最终状态；长结果可完整查看；所列检查通过不显示为全部需求通过。
- AC7（F7）：触发单结果/批次卸载、自动与手动压缩、摘要失败和熔断；同会话可跨入口读取引用，跨会话拒绝；估算与精确 Usage 清楚区分。
- AC8（F8）：终端完成新建、列表、查看、重命名、继续、清空、删除、会话和单轮导出；重启保留历史、模式与上下文，配置失效不静默换绑，清空删除后引用按规则清理。
- AC9（F9）：Web 创建的会话可由 CLI 继续，CLI 创建的会话可由 Web 继续；两个进程争用时不覆盖记录。强制中断、保存失败、恢复及重试场景可观察到真实状态，不自动重放已有副作用。
- AC10（F10）：分别触发最大迭代数、最大时长、连续工具失败、模型错误、上下文停止及用户取消，每轮只出现一个终止结果，审批和受管进程被清理。
- AC11（F11）：CLI 运行可被现有评估流程定位，单轮导出包含实际模型/工具/停止/持久化信息和来源；记录或导出失败有反馈，输出不泄露测试凭据。
- AC12（F2–F11，N1–N5）：使用同一组可控模型场景对比两端的工具允许集合、权限结果、上下文、停止与持久化行为；运行相关测试及 lint、typecheck、build。共享运行编排变更后进行 Web 浏览器回归，并在 tmux 中验证 CLI 真实终端闭环及异常路径；本地替身验证和真实 Provider 验证分别记录，未执行项不得报告通过。
