# 上下文管理 Spec

状态：已批准

> 本文件已由用户在对话中明确批准，可作为实现与验收基线。

## 背景

OrbitCode 当前能在一次 Agent 轮次中连续调用模型和工具，并能展示模型返回的 Token Usage；但 Web 客户端仍在每次请求中回传纯用户/助手历史，工具调用与工具结果只存在于当前请求的内部 transcript。随着轮次、模型文本和大体积工具结果增加，发送给模型的上下文会持续膨胀，并最终触及模型上下文窗口。现有消息数量和字符数上限只能拒绝请求，不能让 Agent 在有限预算内继续工作。

本功能引入“轻量预防 + 重量兜底”的两层策略：优先把大工具结果卸载到应用私有的本地存储，仅在整体历史接近上限时调用模型生成结构化摘要。用户原始消息保持原文，不以摘要改写；模型需要被卸载的具体内容时，必须通过受会话约束的读取能力重新获取。

## 目标

- 在每次 Agent 模型调用前自动整理上下文，使长工具链和多轮对话尽可能保持在可配置的 Token 预算内。
- 以最近一次普通 Agent 模型调用报告的输入 Token 为锚点，对锚点后的变更使用字符/字节近似估算，不引入精确 tokenizer。
- 让 Web 用户可以手动触发重量压缩，并看到压缩状态、压缩前后估算 Token 和失败原因。
- 将上下文状态、估算、压缩、摘要与熔断规则放在入口无关的 TypeScript 核心能力中。
- 保持已合入当前基线的 Workspace、Plan/Do 和权限规则安全边界，不改变权限系统语义。

## 假设

- “长时间工作”指当前 Web 页面/上下文会话生命周期内的连续工作；刷新页面或清空会话后仍按现状开始新会话，本轮不引入数据库或跨进程会话恢复。
- Web 的模型内部 transcript 将由独立的上下文会话在服务端进程内管理；页面继续保存展示消息，但不再作为模型历史的事实来源。上下文会话与权限会话分别维护状态，只在 Workspace、Provider、清空和页面卸载时同步结束。
- 模型配置必须提供该 Provider 的上下文窗口大小。轻量阈值、近期消息目标、自动/手动安全余量和预览长度可配置，并具有与具体模型无关的默认值；建议默认值为：单工具结果 8K Token、同一工具批次结果总量 12K Token、近期尾部目标 10K Token、自动余量 13K Token、手动余量 3K Token。
- Token 近似采用可测试、偏保守的字符/UTF-8 字节估算。摘要调用自身的 usage 不覆盖普通 Agent 请求的估算锚点。
- 用户消息始终保留原文，不被摘要文本替代。若用户原文、固定系统提示、工具定义和必须保留的近期消息本身已无法放入预算，系统明确停止并报告容量不足，而不是静默删改用户输入。
- 卸载内容保存在 Workspace 之外的应用私有本地目录，引用使用当前上下文会话作用域内的不透明标识，不向模型或浏览器暴露真实绝对路径。
- 手动压缩代表用户明确要求执行一次重量压缩，即使尚未达到自动阈值也会尝试；3K 余量用于扩大本次摘要请求可处理的旧历史范围，而不是放宽后续普通 Agent 调用的 13K 自动安全线。

## 功能需求

- F1: 系统应维护可解释的上下文 Token 估算：优先采用最近一次普通 Agent 模型请求返回的输入 Token 作为锚点，只对锚点之后新增、删除或替换的内容使用近似估算；没有可用 usage 时应明确退化为全量近似估算，不得把估算冒充模型报告值。
- F2: 每次调用普通 Agent 模型前，系统应先检查内联工具结果；单个结果超过可配置阈值时，将完整结果写入未入库的应用私有本地存储，并在模型历史中仅保留安全预览、原始体积信息和可重新读取的引用。
- F3: 同一条助手工具调用消息所关联的全部工具结果在轻量处理后若仍超过可配置总量阈值，系统应按估算体积从大到小继续卸载尚未卸载的结果，直到回到预算范围或没有可卸载结果；工具调用与结果的协议配对和原始顺序必须保持有效。
- F4: 轻量处理完成后，系统应比较整体估算 Token 与可配置上下文窗口。自动流程使用 13K 默认安全余量；达到或超过触发线时，在本次普通 Agent 模型调用前执行一次重量压缩。每个调用点最多尝试一次摘要，失败后不得在同一 Agent 循环中立即重试。
- F5: 重量压缩应从历史尾部按 Token 预算向前选择近期原始消息，目标约 10K Token且至少保留最近 5 条消息；关联的助手工具调用与工具结果必须作为不可拆分组处理。较早历史中的用户消息继续逐字保留，较早的非用户消息由一条固定结构摘要替换。
- F6: 正式摘要必须固定记录任务目标、已完成工作、关键决策、文件变更、工具结果、错误信息和后续计划。摘要请求要求模型先产出分析草稿，再产出正式摘要；系统只解析和保存正式摘要，分析草稿仅存在于本次压缩调用的临时结果中。
- F7: 摘要模型调用必须在核心执行路径中强制禁用工具：不提供工具定义、使用禁止工具的模型选项，并把模型仍返回工具调用视为摘要失败；该约束不能只写在 Prompt 中。
- F8: 重量压缩成功后，模型历史应包含一条系统级边界消息，明确摘要不是代码事实来源；需要具体文件内容或被卸载工具结果时，模型必须重新调用相应读取工具，不能根据摘要猜测代码。
- F9: 摘要失败应返回结构化、可观察的失败原因并保留可继续使用的原历史。连续三次摘要失败后，上下文会话进入熔断状态，停止自动摘要重试；轻量处理仍可继续。后续确需重量压缩时 Agent 应安全停止。用户手动发起的一次压缩仍可作为显式恢复尝试，成功后清除连续失败计数并闭合熔断器。
- F10: 模型应能通过只读的上下文读取工具，按当前会话的不透明引用分块重新读取已卸载内容。伪造引用、跨会话引用、过期引用、越界范围和任意文件路径必须被结构化拒绝；该工具不得读写 Workspace 或放宽现有权限规则。
- F11: Web 页面应提供仅在 Agent 空闲时可用的手动压缩操作，并展示 `idle`、`compressing`、`succeeded`、`failed`、`circuit-open` 状态；成功时展示压缩前后估算 Token，失败时展示安全失败原因且保留现有可见消息。
- F12: 上下文窗口、单结果阈值、同批结果总阈值、近期消息目标、自动余量、手动余量和预览长度应可配置，并在启动时进行范围与相互关系校验。非法配置必须阻止相关会话启动并给出不含凭据的明确错误。
- F13: 上下文会话应绑定创建时选定的 Workspace 与 Provider，拒绝跨绑定复用和并发的 Agent/手动压缩操作；成功轮次提交完整内部 transcript，取消、模型错误或安全停止不提交本轮新增消息。清空、切换 Workspace/Provider、页面卸载或空闲过期时应关闭会话并尽力清理其本地卸载文件。

## 成功、失败与终止行为

- 成功：轻量处理或重量压缩产出协议有效、可发送的 transcript；Agent 继续当前迭代，并在收到普通 Agent usage 后更新估算锚点。
- 可恢复失败：一次摘要请求出现网络、协议、格式或内容校验错误时，本轮不修改历史，记录一次连续失败并以明确原因停止当前 Agent 轮次；用户可稍后重试或手动压缩。
- 熔断终止：第三次连续摘要失败后停止自动摘要；当上下文超过安全线且无法压缩时，以专用上下文停止原因结束，不调用可能溢出的普通 Agent 模型请求。
- 容量终止：没有足够的可摘要非用户旧历史，或必须保留的用户原文与近期组已超过可用预算时，报告容量不足，不删除用户原文、不猜测摘要、不继续调用模型。
- 存储失败：无法安全写入或读取本地上下文文件时返回结构化错误；不得以丢弃完整工具结果作为降级方案。

## 非功能需求

- N1: 上下文核心不得导入 React、Next.js Route/组件或 OpenAI Provider 实现；模型摘要只能依赖通用模型抽象，本地存储只能依赖抽象接口。
- N2: 所有消息、压缩状态、失败和存储引用使用严格 TypeScript 判别联合类型；运行时输入、摘要结构和 Web 合约均需校验。
- N3: 不新增运行时依赖，不使用 Agent 框架、托管文件工具、服务端代码执行或精确 tokenizer。
- N4: 上下文引用应不可预测并绑定会话；路径拼接、符号链接、跨目录读取和引用枚举不得突破应用私有存储根目录。
- N5: 日志、SSE、错误和 UI 不得暴露 API Key、环境变量、真实存储路径、完整工具参数或已卸载正文；预览沿用现有敏感信息最小化原则。
- N6: 压缩算法在相同输入、配置和摘要结果下应确定性地产生相同保留集合；体积相同的卸载候选按原顺序稳定处理。
- N7: 自动压缩、手动压缩、取消和会话关闭必须支持 AbortSignal，且不能留下处于永久 `running`/`compressing` 的状态。
- N8: 现有 Plan/Do、Workspace 边界、危险命令、权限规则优先级和授权 UI 行为保持不变。

## 不做的事

- 不实现精确 tokenizer、不同模型的专用分词器或基于机器学习的摘要策略优化。
- 不实现数据库、云端同步、跨进程恢复、刷新后恢复可见聊天或长期归档搜索。
- 不摘要改写、截断或删除用户原始消息。
- 不让模型直接访问应用私有存储路径，也不把上下文读取扩展成任意文件读取能力。
- 不实现摘要多模型路由、摘要质量评分、向量检索、语义缓存或自动选择最佳压缩策略。
- 不改变现有权限模式、规则语法、规则优先级、人工审批选项或命令沙箱。
- 不把 CLI 切换到 Agent Tool Calling；核心能力保持可复用，但本轮只在 Web Agent 入口完成集成和手动操作。

## 验收标准

- AC1（覆盖 F1）：给定一次带 `prompt_tokens` 的普通 Agent 响应，后续只新增一条消息时，估算结果标明锚点来源并只近似计算增量；usage 缺失时结果标明全量估算。
- AC2（覆盖 F2）：给定超过单结果阈值的工具结果，在下一次模型调用前本地保存完整正文，模型 transcript 仅含有界预览、体积和不透明引用，用户消息字节级不变。
- AC3（覆盖 F3）：给定同一工具批次多个结果且总量超限，系统按体积稳定降序卸载，直到总量不超阈值；发送给 Provider 的 assistant/tool 消息仍合法配对且顺序不变。
- AC4（覆盖 F4）：自动估算达到 `contextWindow - automaticReserve` 时，先轻量处理再且仅尝试一次重量压缩；未达到时不调用摘要模型。
- AC5（覆盖 F5）：重量压缩后至少保留最近 5 条原始消息，尾部目标约为配置预算且不拆分工具组；所有被选为旧历史的用户消息仍逐字存在，旧非用户消息由摘要代替。
- AC6（覆盖 F6）：摘要结果只有在同时包含七个固定章节且格式通过运行时校验时才能提交；分析草稿不会出现在 `getHistory`、Web 响应或下一次模型请求中。
- AC7（覆盖 F7）：摘要调用发出的模型请求不含工具定义并强制 `toolChoice: "none"`；测试替身若返回工具调用，压缩失败且历史不变。
- AC8（覆盖 F8）：每次成功重量压缩后都存在唯一、紧邻摘要/旧历史与近期尾部边界的系统消息，明确要求重新读取具体文件和上下文引用。
- AC9（覆盖 F9）：连续三次可计数的摘要失败后状态为 `circuit-open`，后续自动流程不再请求摘要模型；一次成功的手动压缩把计数归零并恢复自动能力。
- AC10（覆盖 F10）：当前会话可按引用和范围读回原始内容；跨会话、伪造、过期、路径形式或超范围输入均返回安全结构化错误且不触达 Workspace 文件系统。
- AC11（覆盖 F11）：Web 空闲会话可点击手动压缩并看到进行中及成功前后估算；失败显示原因，Agent 运行或已有压缩时按钮禁用且服务端并发请求也被拒绝。
- AC12（覆盖 F12）：不同 Provider 可配置不同窗口与阈值；非法整数、余量倒置、阈值关系或不足以容纳近期预算的窗口会在启动/解析阶段被拒绝。
- AC13（覆盖 F13）：上下文会话不能跨 Workspace/Provider 使用，不能并发启动 Agent 与压缩；成功轮次提交工具 transcript，失败/取消轮次不提交新增消息，关闭后引用不可再读取且清理被调度。

## 草案自检

- F1–F13 均至少被 AC1–AC13 中一项覆盖。
- 成功、可恢复失败、熔断、容量不足、存储失败和取消行为均有可观察结果。
- 用户原文保护、上下文引用、权限隔离和凭据保护均已明确。
- 本轮排除了精确 tokenizer、持久化、CLI Agent 化和权限系统重构。
