# MCP 客户端 Spec

状态：已批准
批准记录：用户批准本规格，并授权连续生成其余三份文档，完成后统一审核；此授权不代表实现代码获批。
修订记录（2026-10-11）：根据后续放行模式行为调整，同步 F11 的默认权限；严格／默认模式询问，用户选择放行模式后默认允许，显式 ask／deny 仍优先。

## 背景

OrbitCode 的 Web 与 CLI 已共用运行编排、Agent Loop、工具注册、权限审批、上下文管理和运行记录。当前工具名称为固定集合，权限目标主要表达文件路径与命令，Plan Mode 使用本地只读工具白名单；尚无 MCP 连接及外部工具适配能力。

本轮通过工作区配置接入外部 MCP Server 的工具，同时保留已有授权、模式限制、取消和完成证据边界。外部进程与远程服务均不天然受 OrbitCode 的本地文件沙箱约束。

## 目标

- 支持 stdio 与 Streamable HTTP，完成 JSON-RPC 通信、初始化、分页工具发现和工具调用。
- 用户以 YAML map 声明 Server，工作区运行环境初始化时，在授权后发现并注册工具；Web 与 CLI 共用行为。
- 外部工具沿用现有工具执行链、审批交互、上下文和运行记录，连接跨对话轮次复用，并可确定性释放。

## 假设

- 本轮选择 MCP `2025-11-25` 作为明确的协议基线，不承诺兼容所有历史及未来版本；不支持的协商版本明确失败。
- 初始化指服务端为已选工作区准备运行能力的阶段。需要审批时先呈现现有审批交互，不能因等待初始化结束才展示审批而产生死锁；拒绝某个 Server 后仍能使用本地工具。
- 本轮将外部工具统一视为可能有副作用，Plan Mode 不向模型暴露且拒绝执行外部工具，也不因进入 Plan Mode 新建外部连接。Server 提供的只读等 annotations 仅作参考，不构成可信授权。
- 连接缓存限于同一个 OrbitCode 宿主进程；Web 和 CLI 共用实现，各自运行的进程不共享活连接。
- 用户级与项目级仅按要求作两层 Server 配置合并；具体配置路径、默认超时、容量上限与权限表达式在技术计划中确定。缺少配置表示不启用 MCP，保持现有体验。

## 功能需求

- F1：加载并运行时校验 YAML Server map。每个 key 为唯一 Server 名，stdio 配置包含 command、args、env，HTTP 配置包含 url、headers。拒绝类型错误、重复键、非法传输组合和无效地址；可选字段的默认值须有文档说明。
- F2：按 Server 名合并用户级、项目级配置；同名时项目级整项替换，不深合并 args、env、headers。只在 env 和 headers 的值中展开 `${VAR}`；缺失变量使对应 Server 不可用，错误只指出字段及变量名，不回显值。无效项目配置不得悄悄退回同名用户配置。
- F3：读取或合并配置不启动本地进程，也不代表允许远程连接。首次连接必须经过独立的 Server 启动／连接授权，审批明确工作区、Server、传输及脱敏后的目标信息。授权与有效配置身份绑定；修改命令、参数、环境、URL 或 headers 后不得沿用旧连接授权。已有文件或命令通配规则不能自动成为外部连接授权。
- F4：stdio 通过本地子进程的 stdin/stdout 收发按行分隔的 UTF-8 JSON-RPC 消息，正确处理分块与多条消息；stderr 不作协议响应。使用明确的命令与参数启动，不额外经过 shell 解释，且不默认传递宿主的全部敏感环境变量。
- F5：Streamable HTTP 支持 JSON 响应与 SSE 响应流、通知发送、适用的会话标识及协商版本请求头；支持服务端通知接收，正确处理不支持独立 GET 流的服务端。不得将配置的凭据随自动重定向发送给新的目标。会话失效或断流有明确失败结果，本轮不自动重连或重放调用。
- F6：按 JSON-RPC 2.0 请求 id 配对异步响应，支持并发、乱序、通知、错误和有界超时。取消或超时清理等待项，适用时通知 Server 取消；迟到、重复和未知 id 的响应不能完成其他请求。对不支持的服务端请求返回协议错误，不启动额外能力。协议格式损坏、连接终止及进程退出必须收敛相关等待请求。
- F7：连接先完成初始化、版本与工具能力协商及 initialized 通知，再进行工具发现。通过 cursor 读取完整分页列表，防止重复游标和无限分页；缺少工具能力或发现失败有可观察结果，不发布不完整工具集合。工具列表变化通知使目录失效，受控刷新后在后续回合生效，不改变正在审批或执行的工具快照。
- F8：将外部工具适配到现有工具中心，支持动态工具身份而保留本地工具的类型约束。模型可见名称含 Server 命名空间，满足模型工具命名限制；不同 Server 的同名工具、名称规范化冲突及超长名称不得互相覆盖。调用保留原始 Server 和工具身份，按此路由。
- F9：外部参数必须按公布的输入 Schema 在本地完成运行时校验，失败时返回结构化参数错误且不发送 tools/call。不能可靠校验的 Schema 不注册该工具并给出原因，不能忽略未知校验约束后声称参数有效；不通过远程引用抓取额外网络内容。
- F10：将文本、结构化内容和工具错误转换为现有工具结果，区分传输失败、协议错误、参数错误与 Server 返回的工具执行错误。无法展示的内容提供明确占位或结构化说明，不静默丢弃，不自动抓取资源链接。确认文本与结构化内容完全重复时，模型视图只保留一份，持久化结果保留脱敏后的两种表示。超长结果走现有截断／上下文引用机制；取消或超时不声称外部副作用已撤销。
- F11：扩展权限目标以表达 Server、工具和有效配置身份，所有外部调用都经过现有权限网关与准备、审批、执行链。保持 deny 优先于 ask、ask 优先于 allow；无匹配授权的外部操作在严格／默认模式下询问，用户主动选择放行模式后默认允许。显式 ask／deny 仍优先，Server annotations 不能降低风险。调用授权不替代启动授权，启动授权不自动批准工具调用。
- F12：Web 与 CLI 复用各自现有审批交互，可批准、拒绝和取消。审批绑定工作区、会话、具体操作和参数快照；跨会话审批、过期审批、参数或配置变化都不能复用。Plan Mode 即使遇到手工构造的调用或已批准操作，也不能越过模式限制。
- F13：外部工具定义与结果接入现有上下文预算、会话持久化和运行记录。用户能定位 Server、原始工具、调用状态、耗时、审批结果与错误类别；Server 描述和输出按外部不可信数据处理，不能提升为系统指令或完成证明。工具返回成功不等于整个任务验收成功。
- F14：由共用运行环境统一编排配置、授权、连接和工具注册，按规范化工作区与有效配置缓存连接，并合并同一连接的并发初始化。跨工作区不误用连接；配置改变后旧连接不接收新调用，在已有使用者结束后释放。连接复用仍须检查当前会话授权，不共享其他会话的一次性批准。
- F15：单个 Server 的配置错误、拒绝启动、握手失败、发现失败或运行故障不影响其他 Server 和本地工具；损坏的配置文件有脱敏诊断并关闭受影响的 MCP 配置范围，不导致整个本地 Agent 无法运行。故障连接不在每轮自动重试；配置变更或应用重新初始化可创建新连接。正常退出释放 HTTP 流与会话、等待请求及所拥有的子进程；先尝试正常关闭，超时后终止。

## 非功能需求

- N1：协议为独立 TypeScript 模块；共用运行编排负责接入，协议层不得依赖 React、Next.js 路由或终端展示，不复制两套客户端。
- N2：复用已有 yaml 与标准库，不引入 Agent 框架或托管代码／文件工具。新增运行时依赖必须先说明标准库和现有依赖不能合理满足的部分及必要性。
- N3：配置原文、展开后的 env／headers、会话凭据、子进程原始日志不得泄露到浏览器、模型上下文、运行记录或诊断。对已知配置秘密作脱敏，错误默认采用安全摘要；不得声称可以识别外部工具任意输出中的所有未知秘密。
- N4：为配置大小、消息大小、SSE 缓冲、分页、工具数量、Schema 复杂度、待处理请求及结果大小设置上限，错误与恶意 Server 不得造成无限等待或无界内存增长。
- N5：取消保证 OrbitCode 停止等待并清理自身资源，不保证远程服务停止执行或外部副作用回滚。系统强制杀死宿主的情形不承诺执行退出清理。
- N6：保持既有本地工具、权限、Plan Mode、Web 与 CLI 行为兼容；验证覆盖双传输、双入口、安全拒绝路径和故障隔离，不以工具单测替代集成验收。

## 不做的事

- MCP resources、prompts、sampling、elicitation、roots 等非工具能力及异步 tasks 扩展。
- Server 健康检查、自动重连、请求自动重试、断流恢复及旧 HTTP+SSE 传输兼容。
- OAuth 登录与凭据管理界面、浏览器直接连接 MCP Server、Server 安装或市场。
- 外部 Server 的通用操作系统沙箱、远程副作用回滚，以及跨 Web／CLI 进程共享连接服务。
- 仅依据外部只读声明开放 Plan Mode，或顺带重构本地工具执行与完成验收体系。

## 验收标准

- AC1（F1、F2）：两层 YAML 中含重名和独有 Server；最终列表正确合并，重名整项覆盖，env／headers 不继承旧值。覆盖缺失文件、重复键、错误类型、非法 URL、缺失变量和无效项目覆盖，不输出测试秘密。
- AC2（F3、F12）：提供一个启动后写入标记的本地测试 Server；仅加载配置不产生标记。Web 与 CLI 都能先看到审批，拒绝／取消后不启动，批准后才握手；变更有效配置后必须重新授权。HTTP 连接同样不得在授权前发送请求。
- AC3（F4、F6）：本地 Server 分块发送、多消息合并和乱序返回；每个调用拿到对应结果，stderr 不作为响应。超时、取消、重复 id、未知 id、非法消息及进程退出均有可观察且有界的处理。
- AC4（F5、F6）：HTTP 测试 Server 分别返回 JSON 与 SSE，并覆盖 202 通知确认、GET 流／405、会话头、版本头、协议错误、会话失效、重定向和断流；无凭据跨目标泄漏，无自动重放工具调用。
- AC5（F7）：握手未完成前没有 tools/list 或 tools/call；不支持的版本明确失败。多页工具只在发现完成后发布；重复 cursor、超限及中途失败不会发布半份列表。列表变化仅更新后续回合，不替换正在审批的调用。
- AC6（F8、F9）：两个 Server 提供同名工具，均能准确调用；规范化冲突、超长名及本地同名不覆盖已有工具。有效参数发送一次，无效参数发送零次；不可可靠校验的 Schema 明确不可用。
- AC7（F10、F13）：覆盖文本、结构化结果、isError、JSON-RPC 错误、不支持的内容、超长结果、超时和取消；现有上下文与记录可识别结果，副作用状态不误报为已撤销，工具成功不自动成为任务验收成功。
- AC8（F11、F12）：覆盖 deny／ask／allow 冲突、无匹配规则、宽松模式、Server 只读声明、过期与跨会话批准、审批后参数或配置改变；无授权时不发工具请求，Plan 中隐藏并拒绝外部调用。
- AC9（F14）：同工作区连续多轮及并发初始化只建立一条对应连接；不同工作区隔离；配置改变使后续调用使用重新授权的新连接；取消一个请求不误取消其他请求或借用别人的批准。
- AC10（F15）：同时配置正常 Server、拒绝启动的 Server 和故障 Server；正常 Server 与本地工具仍可调用。故障不在后续每轮重复启动，宿主正常退出后无其持有的活动连接和遗留子进程。
- AC11（F1—F15、N1—N6）：在 Web 和 CLI 完成“工作区初始化 → 启动审批 → 工具发现 → 调用审批 → 外部执行 → 结构化结果 → 最终回复”的端到端流程，覆盖拒绝、无效参数、工具失败、超时、取消和最大循环次数；记录实际证据。执行相关测试及 lint、typecheck、build，页面变更另做浏览器内容、错误覆盖层与控制台检查。
