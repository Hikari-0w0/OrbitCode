# Agent Loop 与 Plan Mode Spec

状态：已批准

## 背景

OrbitCode 已经具备 OpenAI 兼容的流式对话、六种本地工具、工作目录安全边界，以及 Web 入口中的单次工具调用闭环。当前模型每个用户请求最多只能执行一次工具；即使工具结果表明还需继续读取、修改或验证，模型也不能再次行动，因此尚未形成能够根据执行结果自主调整的 Agent。

本阶段把单次编排升级为受安全上限约束的 ReAct 风格 Agent Loop：模型可反复请求工具、读取结构化结果并决定下一步，直到给出最终回复或命中明确停止条件。同时建立统一异步事件流、多个工具调用的安全调度、端到端取消，以及服务端强制执行的 Plan/Do 两阶段模式，使 Web 页面能够实时呈现整个执行过程而不承载核心循环逻辑。

## 目标

- 让一个用户请求能够在多次模型调用和多批工具执行之间自主循环，最终形成可工作的完整 Agent 闭环。
- 为每次循环提供可配置的最大迭代安全上限，以及完整、可解释、用户可观察的停止原因。
- 通过统一异步事件流同时满足核心编排、Web 实时展示和完整模型响应收集，不让 UI 或路由实现 Agent 状态机。
- 安全处理模型单次返回的多个工具调用：允许适当的只读并发，同时保证可能产生副作用的操作不会并发执行。
- 让用户能在只读规划与完整执行之间明确切换，并由服务端强制实施当前模式的工具权限。
- 保留上一阶段已经建立的工作目录、参数校验、命令隔离、超时、凭据保护和结构化工具结果边界。

## 假设

- 本阶段把 Agent Loop、Plan Mode 和过程展示接入 Web 对话；CLI 继续保持现有纯文本流式对话，但核心契约应保持入口无关，以便后续复用。
- `/plan` 与 `/do` 是当前页面会话中的独立模式切换命令。切换命令本身不调用模型、不执行工具；切换成功后，后续用户请求使用新模式，刷新或清空会话后恢复默认的 Do 模式。
- Plan 模式的目标是分析当前任务并输出文本计划，不自动执行该计划；切换到 Do 模式后，用户仍需明确提交执行请求，避免仅切换模式就触发本地副作用。
- Plan 模式只允许读取文件、查找文件和搜索代码三种只读工具。Do 模式恢复当前注册中心内的全部工具。
- 每次“迭代”指一次完整模型请求与响应。达到迭代上限时，若该响应仍请求工具，系统不启动这一批工具，而是以达到最大迭代次数停止，避免产生没有后续模型解释机会的副作用。
- “连续调用未知工具”默认指连续两个请求工具的模型迭代都没有包含任何可识别、当前模式允许的工具；其中间只要出现一个可识别且允许的工具调用，连续计数即清零。该阈值本阶段固定为二，最大迭代次数则必须可配置。
- 同一模型响应中的工具结果按模型给出的调用顺序写回对话历史，即使部分只读调用实际并发完成，也不按完成先后改变协议顺序。
- Token 用量以模型服务实际报告的数据为准；上游不提供用量时，事件流明确标记为不可用，不通过文本长度估算或伪造数值。
- 只有正常生成最终回复的轮次进入后续普通 Web 对话历史；取消、错误及其他安全停止的未完成轮次不提交，但已经发生的工具副作用不承诺回滚。

## 功能需求

- F1：用户提交普通请求后，Agent 持续执行“调用模型、收集完整响应、执行模型请求的工具、把工具调用及结构化结果写回当前内部对话、再次调用模型”的循环，直到模型返回不含工具调用的最终文本或命中其他停止条件。
- F2：每次模型流式响应都必须一边把文本增量和其他过程事件实时推送给调用方，一边无遗漏地收集本次响应的文本、全部工具调用、完成原因和可用 Token 用量，供 Agent Loop 在流结束后判断下一步；不得为了循环判断而延迟已有文本增量的展示。
- F3：模型适配层必须支持一次响应包含零个、一个或多个工具调用，能够依据调用索引和调用标识正确拼接跨任意流分片到达的名称及参数，并拒绝重复标识、索引冲突、缺失必要字段、无效结构或完成原因矛盾等不确定响应。
- F4：一个模型响应包含多个工具调用时，Agent 必须在执行前依据服务端工具元数据判断其是否只读。彼此不存在写入顺序依赖的只读调用可以并发执行；写文件、修改文件、执行命令及其他可能有副作用的调用必须串行执行，且不得与同批其他工具重叠运行。无论实际完成顺序如何，全部结果都按原调用顺序写回模型上下文。
- F5：单个工具的无效参数、路径拒绝、未找到、命令失败、超时或内部执行异常属于可恢复工具结果；只要没有触发终止条件，Agent 应将其结构化回传给模型，使模型可以修改参数、选择其他工具或生成最终说明，而不是让整个服务崩溃。
- F6：Agent 的最大迭代次数必须可由服务端配置为有效的正整数，并受不可绕过的安全硬上限约束。配置缺失时采用稳定默认值，配置非法时在模型请求前给出安全错误；任何模式、提示词或模型输出都不能提升当前请求的上限。
- F7：每个 Agent 轮次必须且只能以一个明确停止原因结束，至少区分：模型生成最终回复、达到最大迭代次数、用户取消、连续未知工具、模型响应流或协议错误，以及其他不可恢复的 Agent 错误。停止事件必须携带已完成迭代数和副作用状态，不能把安全停止伪装为成功完成。
- F8：用户在模型响应、只读并发批次或有副作用工具执行期间点击停止、关闭页面或断开请求时，同一个取消信号必须传递到 Web 服务端、Agent Loop、当前模型请求和所有尚未完成的工具；系统不再启动后续工具或模型迭代，并释放读取器、进程、计时器和监听器。
- F9：核心层必须提供统一的严格类型异步事件流，至少包含文本增量、工具调用已确认、工具执行开始、工具结果、Token 用量、迭代及阶段进度和最终停止原因。事件带有足够的迭代、调用标识和顺序信息，使 Web、未来 CLI 或测试替身无需读取核心内部状态即可还原执行生命周期。
- F10：Agent 内部对话必须在同一用户轮次内按协议保存每次助手工具调用和对应工具结果，供后续模型迭代使用；正常最终回复完成后，后续普通 Web 历史只保存用户输入和最终助手回复，未完成轮次不得污染后续请求。
- F11：用户可通过 `/plan` 切换到 Plan 模式，并通过 `/do` 切换回 Do 模式；页面必须明确显示当前模式，模式切换期间不得保留含义不清的进行中请求，且模式状态必须随每个后续对话请求显式传给服务端并接受校验。
- F12：Plan 模式下，服务端发给模型的工具定义只能包含读取文件、查找文件和搜索代码；服务端实际执行入口还必须再次按当前模式拒绝写文件、修改文件、执行命令或其他非只读工具。拒绝结果不得产生副作用，并可安全回传给模型；Do 模式恢复注册中心内全部合法工具。
- F13：Web 页面必须实时展示同一助手轮次中的模型文本、每个工具调用的排队或执行状态、结构化工具结果、当前迭代与最大迭代进度、可用的 Token 用量、当前 Plan/Do 模式，以及最终停止原因；多个调用和多次迭代不得相互覆盖或错误归并。
- F14：未知工具调用不得触发任何工具副作用。未达到连续未知工具阈值时，系统把安全的未知工具结果写回模型以允许其纠正；达到阈值时停止继续请求模型，并以“连续未知工具”结束本轮。模式不允许的已注册工具按权限拒绝处理，不伪装成未知工具。
- F15：模型响应流在完整完成事件前中断、返回非法增量、完成后继续输出或产生其他无法可靠收集完整响应的情况时，Agent 必须停止本轮，不执行该不完整响应中尚未启动的工具，并以模型流或协议错误结束；已发生副作用时必须向用户明确提示其可能已应用。
- F16：Agent Loop 必须保持现有会话互斥约束：同一会话同一时间只允许一个进行中轮次。重复提交、空白输入、非法模式、非法历史、非法最大迭代配置或超限请求必须在进入循环或产生工具副作用前被拒绝。

## 非功能需求

- N1：Agent Loop、循环状态、事件定义、停止判定和工具调度必须位于与 React、浏览器和 Next.js 路由解耦的严格类型 TypeScript 核心能力中；页面和 Route Handler 只负责输入输出适配、依赖组装和展示。
- N2：实现不得使用 Agent 框架、Agent SDK、托管代码执行、Files API 或服务端代管文件工具；循环、历史、响应收集、并发调度、权限过滤、停止条件和错误处理均由 OrbitCode 自行实现。
- N3：不新增运行时依赖；优先使用现有 Provider、工具注册中心、Web SSE 契约，以及 Node.js 和 Web 平台已有的异步迭代、Promise、ReadableStream 与 AbortController 能力。
- N4：对话消息、模型流事件、Agent 事件、工具调用、工具结果、进度和停止原因使用明确的判别联合建模；模型、工具参数、Web 请求和 Web 事件均视为不可信输入并接受运行时校验，避免无必要的 `any` 和类型断言。
- N5：并发只用于经服务端确认的只读工具，并应有明确批次边界；任何两个可能产生副作用的工具不得同时运行。取消或批次异常后不得继续启动尚未开始的副作用工具。
- N6：API Key、认证请求头、完整环境变量、受保护文件内容、内部堆栈和未经约束的上游响应正文不得进入 Agent 事件、工具结果、浏览器、DOM、控制台、日志或验收证据。
- N7：最大迭代、单次模型响应中的工具调用数量、并发只读工具数量、工具输出、请求体和历史消息仍需有明确上限；命中上限时以稳定、可观察的拒绝、截断或停止结果结束，不出现无界资源占用。
- N8：取消、流错误、协议错误、工具异常和安全停止不得导致 Next.js 服务崩溃、未处理 Promise、资源泄漏、重复终止事件、僵尸进程或无法开始下一轮对话。
- N9：保留上一阶段六种工具的参数校验、工作目录限制、受保护路径、原子文件操作、命令严格隔离、输出截断和超时语义；不得为支持循环、并发或 Plan Mode 弱化既有安全限制。
- N10：Web 过程展示使用纯文本或安全结构化视图，不把模型文本、工具参数或工具输出解释为可执行 HTML；桌面与窄屏视口都能辨认模式、进度、调用归属和停止状态。
- N11：核心循环、Provider 多工具解析、调度顺序、权限过滤、取消与所有停止条件必须可通过不含真实凭据的可控替身自动验证；真实模型验收只使用用户本地未入库配置，输出不得记录密钥或敏感内容。

## 不做的事

- 不实现上下文压缩、自动摘要、长期记忆、Token 预算裁剪或费用估算；本轮只传递并展示上游实际报告的 Token 用量。
- 不实现完整权限系统、逐次工具审批、用户交互式确认、持久化授权策略、角色权限或可编辑命令白名单。
- 不让 Plan 模式自动切换到 Do 模式，也不在生成计划后自动执行写入或命令；用户必须显式切换并再次提交执行请求。
- 不承诺自动回滚已完成的文件写入、修改或命令副作用；停止或最终回复失败时只准确报告副作用状态。
- 不为 CLI 接入工具执行、Agent Loop、Plan/Do 命令或新的终端过程视图；只保证核心设计不阻碍后续接入。
- 不新增工具种类、工作目录选择、多工作区、会话持久化、数据库、跨刷新恢复或并行用户轮次。
- 不实现模型自评打分、独立反思阶段、计划质量评审或在停止后自动重启循环。
- 不面向不受信任公网或多租户部署补充认证、租户隔离或远程执行能力；现有 Web 本地使用边界保持不变。

## 验收标准

- AC1（覆盖 F1、F5、F10）：给定可控模型依次请求读取文件、根据读取结果请求修改文件、根据修改结果请求验证命令并最终返回文本，Agent 按协议完成所有模型与工具步骤，每次后续模型请求都包含此前完整工具调用和对应结构化结果，最终只把用户消息与最终助手回复提交到普通 Web 历史。
- AC2（覆盖 F2、F9）：让每次模型响应分多批延迟发送文本、工具参数、完成原因和用量数据，调用方在响应完成前即可收到文本增量和进度事件；流结束后 Agent 收集到的完整文本、全部工具调用、完成原因和 Token 用量与上游一致，并据此正确继续或终止。
- AC3（覆盖 F3、F15）：可控 OpenAI 兼容流分别返回零个、一个和多个跨分片工具调用时，Provider 按索引与标识组装出顺序正确的调用列表；重复标识、索引冲突、缺失字段、非法结构、错误完成原因、完成后事件及流截断均成为明确停止，且不执行不完整响应中尚未开始的工具。
- AC4（覆盖 F4、N5）：同一响应按顺序请求多个只读工具、一个写入工具、更多只读工具和一个命令时，执行时间证据表明同一安全批次的只读工具可以重叠，写入与命令彼此及与其他工具均不重叠；回传给模型的结果顺序始终等于原调用顺序。
- AC5（覆盖 F5、F14）：分别让工具收到无效参数、路径拒绝、命令非零退出、超时、内部异常和未知名称；未命中终止条件时这些结果均安全回传并允许模型纠正。连续两个仅含未知工具的迭代在没有副作用的情况下以“连续未知工具”停止，而中间出现合法允许工具会重置连续计数。
- AC6（覆盖 F6、F7）：用不同有效值配置最大迭代次数时，Agent 在对应边界停止；缺失配置采用稳定默认值，零、负数、非整数、超出硬上限或非法类型在模型请求前被拒绝。最后一个允许迭代仍请求工具时，该批工具不执行，最终只产生一个“达到最大迭代次数”停止事件。
- AC7（覆盖 F7、F15）：分别触发最终回复、最大迭代、用户取消、连续未知工具、模型流或协议错误和不可恢复 Agent 错误，每个场景都只产生一个包含已完成迭代数与副作用状态的终止事件；页面显示的停止原因与核心事件一致，不把非成功停止显示为已完成。
- AC8（覆盖 F8、N5、N8）：在模型流、并发只读批次、文件写入前、命令执行中分别取消 Web 请求，模型和所有运行中工具都观察到取消，未开始的工具与后续模型迭代不再启动，命令及子进程、读取器、计时器和监听器均被清理，随后可以正常开始新轮次。
- AC9（覆盖 F11、F12、F14）：默认 Do 模式下模型可见并可执行六个工具；输入 `/plan` 后页面明确显示 Plan 模式，后续请求的模型定义只有三个只读工具，服务端执行入口也拒绝伪造的写入、修改和命令调用且工作目录无变化；输入 `/do` 后全部工具恢复。两次模式切换本身均不产生模型请求或工具执行。
- AC10（覆盖 F13、N10）：真实浏览器中完成至少三次模型迭代且包含多个工具调用的请求时，页面按调用标识显示模型文本、各工具的排队/运行/成功或失败状态、结构化结果、当前与最大迭代、可用或不可用的 Token 用量、当前模式和唯一最终停止原因；桌面与窄屏均无状态错位或内容覆盖。
- AC11（覆盖 F10、F16）：完成一次成功轮，再分别执行失败、取消、最大迭代和连续未知工具轮，下一次上游请求只包含此前成功轮次；空白输入、重复提交、非法模式、非法历史和超限请求均在进入循环或产生副作用前被拒绝，服务仍可继续处理合法请求。
- AC12（覆盖 N1、N2、N3、N4）：类型、依赖和构建检查证明核心循环与事件不依赖 React、浏览器或 Next.js 路由，Route Handler 不实现循环状态机，依赖清单没有新增运行时包，且未引入被禁止的 Agent 框架、SDK 或托管执行能力。
- AC13（覆盖 N6、N7、N8、N9、N11）：自动化场景覆盖工具调用数量、只读并发数、历史、输出与请求体上限，以及流错误、工具错误、取消和安全停止；既有路径、敏感文件、命令隔离、超时与截断测试继续通过，浏览器事件、DOM、日志和测试输出不包含哨兵凭据、内部堆栈或未经约束的上游正文。
- AC14（覆盖全部需求）：`npm run test`、`npm run lint`、`npm run typecheck` 和 `npm run build` 均以退出码 `0` 完成；开发服务器下使用真实浏览器和用户本地未入库模型配置完成多迭代工具闭环、混合多工具调用、Plan/Do 切换、工具失败恢复、最大迭代、连续未知工具、模型流错误及各阶段取消，测试后无残留浏览器、服务器、读取器或子进程，证据不含凭据。
