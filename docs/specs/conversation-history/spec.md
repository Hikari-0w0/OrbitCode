# 本地持久化对话历史 Spec

状态：已批准

> 用户已授权连续完成四份规划文档；最终实现仍等待整套文档审核。

## 背景

OrbitCode 当前的 Web 对话由页面内展示状态和服务端进程内 Context Session 共同维护。刷新页面、切换 Workspace 或 Provider、页面卸载、Context Session 空闲过期以及项目重启都会销毁会话；因此已经完成的用户消息、助手回复、工具调用、工具结果、中断记录和压缩状态无法在之后重新打开，也不能基于原上下文继续开发。

本功能把一次开发对话提升为可长期保存和重新打开的本地资源。用户可以维护多个彼此隔离的对话，在页面刷新或 OrbitCode 重启后重新选择旧对话，并让可见记录与模型实际继续使用的上下文保持一致。

本规格替代“上下文管理”阶段中关于刷新后清空、页面卸载即删除、空闲 TTL 删除和不支持跨进程恢复的阶段性边界；原有上下文压缩、工具权限和 Workspace 安全约束继续有效。

## 目标

- 在本机持久保存多个 Web Agent 对话，并在页面刷新或项目重启后恢复。
- 让用户能够新建、查看、切换、重命名和删除对话，并从任一可用旧对话继续开发。
- 同时恢复用户可见时间线与模型内部上下文，避免“页面看得到但模型不知道”或相反的分裂状态。
- 保持 Workspace、Provider、上下文引用、权限审批与敏感信息的现有安全边界。
- 对保存失败、记录损坏、绑定不可用和并发修改给出明确且可恢复的行为。

## 假设

- 本轮实现多个独立对话，而不是每个 Workspace 只有一条自动覆盖的固定会话。
- 每条对话固定绑定创建时的 Workspace 和 Provider。打开旧对话时恢复这两个选择；修改 Workspace 或 Provider 会开始一条新对话，不会静默改写旧对话的绑定和历史。
- 对话标题默认从第一条非空用户消息生成一个有界本地标题，不额外调用模型；用户可以之后重命名。
- 对话正文只保存在运行 OrbitCode 的本机，不进行云端同步。持久记录包含继续对话所必需的用户/助手正文和结构化工具历史，因此可能包含用户项目内容。
- 对话不会因空闲或应用重启自动删除；只有用户明确删除或清空时才移除对应内容。
- 页面刷新后优先恢复最近一次打开且仍有效的对话；没有可恢复记录时创建空白对话。
- 权限系统的“本次允许”和“本会话允许”不随页面刷新或项目重启恢复；永久规则仍按现有本地权限文件生效。恢复对话后发生的新工具调用必须重新经过当前权限判断。
- 正在流式运行的 Agent 不允许直接切换、删除、清空或重绑定对话；用户需先停止当前运行。

## 功能需求

- F1: 系统应持久保存每条对话的稳定标识、标题、创建时间、最近更新时间、Workspace/Provider 绑定、当前 Plan/Do 状态、用户可见消息时间线以及模型继续对话所需的完整已提交上下文。
- F2: 页面加载时应列出本机已有对话的安全摘要，并按最近更新时间排序；列表加载不得要求先读取每条对话的完整正文。
- F3: 用户应能创建空白对话。发送第一条非空用户消息后，系统应生成默认标题；用户可重命名对话，空白、超长或非法标题应被明确拒绝。
- F4: 用户应能在 Agent 空闲时切换对话。成功打开后，页面应恢复该对话的可见消息、工具卡、停止原因、Token 用量和运行时间，并恢复对应 Workspace、Provider、Plan/Do 状态及可继续使用的模型上下文。
- F5: 页面刷新、开发服务器重载或 OrbitCode 进程重启后，系统应重新发现持久对话并恢复最近一次打开的有效对话；若该记录已删除、损坏或不可用，应展示明确状态并允许选择其他对话或新建对话，不得用空白历史冒充恢复成功。
- F6: 每个 Agent 轮次达到唯一终止状态后，系统应一致地保存可见时间线与模型上下文。最终回复、用户取消、最大迭代、安全停止、模型错误和 Agent 错误所形成的已提交记录都必须在重新打开后保留。
- F7: 对话继续时必须使用该对话最后一次成功保存的完整 Agent transcript，包括用户和助手消息、助手工具调用、对应工具结果、推理协议字段、结构化中断、摘要和上下文边界；不能只使用页面展示的纯文本历史重建模型上下文。
- F8: 已卸载的大工具结果及其不透明引用应与持久对话具有相同生命周期。刷新、进程重启和普通空闲不得使有效引用失效；删除对话或清空其上下文时应清理该对话独占的卸载内容。
- F9: 用户应能明确删除一条空闲对话。删除前必须确认，成功后移除对话正文、索引记录和独占上下文引用；删除失败时不得让列表和实际存储产生“看似已删除”的不一致状态。
- F10: 清空当前对话属于破坏性操作，必须明确提示其会永久删除当前记录中的消息和模型上下文。成功后当前对话变为空白但保留其绑定；失败时保留原记录。
- F11: 若旧对话绑定的 Workspace 或 Provider 在当前配置中不存在或不可用，系统仍应允许用户查看已保存的安全对话记录，但禁止继续运行 Agent，并明确指出不可用绑定；不得自动替换为其他 Workspace 或 Provider。
- F12: 同一条对话同时被多个页面或进程修改时，系统必须检测过期版本或活动运行冲突，拒绝后到的覆盖写入，并引导用户重新加载最新记录；不得静默丢失已保存轮次。
- F13: 若持久化在 Agent 终止后失败，页面必须明确标记当前对话尚未安全保存，并保留当前进程内可见状态供用户重试；不得显示“已保存”或悄悄回退成空白对话。日志写入失败与对话保存失败必须保持独立。
- F14: 若 OrbitCode 在 Agent 运行中异常退出，重启后至少恢复该轮开始前最后一个完整持久检查点，并明确提示上次运行可能中断；不应把未确认完成的工具调用标记为成功，也不得破坏此前已保存历史。
- F15: 切换 Workspace 或 Provider 时，系统应保留当前对话并创建或切换到与新绑定匹配的空白对话；返回旧绑定后仍可重新打开原对话。该行为不得删除旧记录。
- F16: 对话列表和详情接口应严格校验不透明标识、版本和输入边界；浏览器不能提交模型事实历史覆盖服务端记录，也不能通过伪造标识访问其他本地存储路径。

## 成功、失败与终止行为

- 成功保存：Agent 轮次终止后，可见时间线与完整模型上下文作为同一个新版本对外可见；对话更新时间和列表排序随后更新。
- 成功恢复：打开的详情版本与后续 Agent 使用的上下文版本一致；下一轮模型能看到此前已提交的工具结果、摘要和中断原因。
- 可恢复保存失败：保留内存状态并显示“未保存”；用户可重试保存或停止继续产生新轮次，不覆盖磁盘上的最后完整版本。
- 损坏记录：隔离单条损坏对话并显示安全错误；其他对话仍可列出和打开。系统不得把无法验证的部分记录发送给模型。
- 绑定不可用：允许只读查看，禁止继续执行、压缩或审批新工具调用；配置恢复后可重新打开并继续。
- 并发冲突：拒绝过期写入和第二个活动 Agent 运行，保留先提交的版本并要求后到页面刷新。
- 进程中断：恢复最后完整检查点并展示中断提示；本轮不承诺恢复尚未形成终止事件的流式文本或进行中的工具进程。

## 非功能需求

- N1: 持久化格式必须带有显式版本并经过严格运行时校验；未知版本、未知字段、非法消息配对和越界内容不得进入 Agent 上下文。
- N2: 对话保存必须采用崩溃安全的原子提交；任何单次写入失败都不能破坏上一完整版本。并发访问应具有明确的版本检查和单写者约束。
- N3: 不新增运行时依赖，优先使用 Node.js 标准库和现有模块；不得引入数据库 ORM、Agent 框架或托管存储能力。
- N4: 本地存储目录和文件只能由当前系统用户访问。对话 API、错误、普通日志和列表摘要不得暴露绝对路径、API Key、完整环境变量或未请求加载的对话正文。
- N5: 列出对话的成本应与摘要数量相关，而不是反序列化全部 transcript；打开单条对话时才加载并验证其详情。
- N6: 对话正文、工具结果和卸载内容必须设有明确的单项与总体边界。达到容量或磁盘限制时返回可恢复错误，不得静默截断用户消息、工具协议或已保存历史。
- N7: 页面展示记录和模型上下文必须共享同一持久版本号；恢复、保存、压缩、清空和删除不得分别提交造成版本分裂。
- N8: Context Session 的内存 TTL 只能释放运行时资源，不能删除持久对话或仍被其引用的卸载内容。
- N9: 恢复历史不得恢复临时权限决定、活动进程、AbortSignal、待处理授权请求或内存定时器；这些运行态能力必须重新创建。
- N10: 现有 Workspace 路径边界、危险命令硬限制、权限优先级、上下文压缩、安全停止和日志脱敏规则保持不变。

## 不做的事

- 不实现云同步、多设备共享、账号体系或远程数据库。
- 不实现对话全文搜索、标签、文件夹、收藏、导入导出或分享链接。
- 不实现对话分支、Fork、合并或多人实时协作。
- 不实现静态加密口令、系统钥匙串集成或应用层加密；本轮依赖本机用户目录权限保护数据。
- 不保证恢复进程崩溃前尚未终止的流式文本、未完成工具进程或待处理授权决定；只保证最后完整检查点和明确中断提示。
- 不迁移或恢复本功能上线前已经丢失的内存会话；持久化仅对功能启用后创建或明确保存的对话生效。
- 不把 CLI 纯文本会话纳入对话列表；本轮只覆盖 Web Agent 对话。
- 不改变模型上下文压缩算法、Provider 协议、工具权限语义或本地运行日志内容策略。

## 验收标准

- AC1（覆盖 F1、F6、F7）：完成一轮包含模型文本、工具调用和工具结果的 Agent 对话后，关闭页面并重启 OrbitCode；重新打开该对话时可见时间线完整，下一轮模型请求包含协议配对有效的旧工具 transcript。
- AC2（覆盖 F2）：本机存在多条对话时，页面只通过摘要数据列出标题、绑定和时间，按最近更新排序；读取列表不会加载任一完整正文。
- AC3（覆盖 F3）：新建对话后发送第一条消息会得到有界默认标题；合法重命名在刷新后保留，空白、超长和非法标题不会修改旧标题。
- AC4（覆盖 F4、F15）：在两个不同绑定的对话之间切换时，各自的可见消息、模式、Workspace、Provider 和模型上下文正确恢复，旧对话不被清空或重绑定。
- AC5（覆盖 F5）：刷新页面和重启服务后优先恢复最近打开的有效对话；最近记录不存在或损坏时显示可恢复错误，并可打开其他记录或新建对话。
- AC6（覆盖 F6）：分别产生最终回复、取消、最大迭代和模型错误终止，重启后四种轮次的已有文字、工具状态、停止原因和结构化中断仍可见且可供下一轮理解。
- AC7（覆盖 F8）：含卸载工具结果的对话在重启后仍能通过原不透明引用读取内容；删除该对话后引用失效且独占内容被清理。
- AC8（覆盖 F9、F10）：取消删除/清空确认时数据不变；确认后列表、详情和上下文引用一致更新；模拟存储失败时旧版本仍可重新打开。
- AC9（覆盖 F11）：打开绑定已移除 Workspace 或 Provider 的对话时可以查看记录，但发送、压缩和工具审批入口不可用，并显示具体不可用绑定。
- AC10（覆盖 F12）：两个客户端基于同一版本修改一条对话时，先提交者成功，后提交者收到冲突且无法覆盖最新历史；同一对话不能同时启动两个 Agent 轮次。
- AC11（覆盖 F13）：模拟终止后的持久化失败，页面显示未保存状态，磁盘上上一完整版本保持可读，重试成功后状态和版本恢复一致。
- AC12（覆盖 F14）：在已保存历史后模拟 Agent 运行中进程退出，重启后恢复此前检查点并显示上次运行中断，不出现伪造的成功工具结果。
- AC13（覆盖 F16）：伪造对话 ID、越界内容、未知字段、非法版本和工具调用/结果错配均被结构化拒绝，不读取任意路径、不覆盖合法记录。
- AC14（覆盖 F1、F4）：恢复后的消息保留工具卡、停止原因、Token 用量和运行时间；页面记录版本与服务端模型上下文版本一致。
