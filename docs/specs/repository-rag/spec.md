# 仓库知识检索增强（RAG）Spec

状态：已批准
日期：2026-10-24

## 背景

OrbitCode 已具备 Web 与 CLI 共用的 Agent Loop、文件查找、代码字面量搜索、文件读取、项目记忆和上下文管理。现有工具适合已知路径或符号的查询；当用户仅用自然语言描述业务行为时，Agent 仍需要多次探索才能定位设计说明、实现和测试。

本功能为编程 Agent 增加仓库知识检索能力，将授权仓库中的文档、源码和测试作为可追溯证据。检索用于发现候选材料，当前文件读取用于核实事实，原有工具负责修改和验证。项目记忆继续承载背景笔记，上下文管理继续承载会话内容，两者不作为仓库知识的替代来源。

本功能交付可运行的检索闭环、明确的工程边界和可复现的效果评估，以实际对照结果判断准确性、效率和资源成本。

## 目标

- 用户使用中文或英文描述项目行为时，Agent 能发现相关文档、源码和测试，并给出可核对的证据。
- Web 与 CLI 具有一致的配置、索引管理、检索和失败语义。
- 文件变化、权限变化和模型服务失败不会让旧证据被静默当作当前事实。
- 用固定问题集和原有工具基线，说明检索的收益、成本及失败边界。

## 假设与本轮范围

- 本轮面向单个已授权工作区内的 Markdown 文档、TypeScript/TSX 源码与测试；多个工作区分别建立并隔离索引，不进行跨工作区联合检索。
- 功能由用户显式启用，首次构建和后续更新由用户发起。查询不自动触发全量构建；本轮不要求后台文件监听或持续自动重建。
- 默认包含当前有效的项目说明、设计文档、源码和测试。历史归档及历史评估材料默认排除，用户显式纳入后标记为历史资料。
- Embedding 服务可独立于对话模型配置，允许连接用户配置的本地或远程服务。连接现有本地服务属于范围，自动下载模型和部署推理服务不属于范围。
- Web 与 CLI 均提供最小必要的配置及管理入口，不另建独立知识库产品。
- 以下需求是待批准的行为约定；模型、算法、存储格式、模块和接口在后续技术计划中决定。

## 方案比较与范围选择

| 方案 | 满足目标的程度 | 与现有能力的关系 | 安全与复杂度 | 扩展成本 |
| --- | --- | --- | --- | --- |
| 仅检索仓库文档 | 能支持项目问答，对实现定位帮助有限 | 容易接入现有只读工具流程 | 边界较小，但仍需处理敏感信息和过期资料 | 后续加入代码需补充分块与定位规则 |
| 文档、源码与测试联合检索（本版选择） | 能直接支持机制分析、实现定位及修改准备 | 复用工作区、工具、上下文和验证流程 | 需要处理代码边界、版本一致性和权限过滤 | 可在稳定闭环上扩展数据源 |
| 仓库与外部知识库联合检索 | 能覆盖外部技术资料，但超出当前核心需求 | 需要新增导入和来源管理 | 增加网页/PDF 解析、授权、版本及来源可信度问题 | 平台化投入较大 |

## 用户场景

1. **机制分析**：询问“为什么切换工作区会新建会话”，检索得到相关说明、实现和测试，Agent 阅读当前文件后解释机制并引用来源。
2. **修改准备**：询问“为命令超时添加更明确的提示，应检查哪些地方”，检索帮助定位候选实现和测试，Agent 继续使用已有工具核实与操作。
3. **证据更新**：文件已修改或删除，旧片段不再作为有效证据返回；用户更新索引后能检索到当前材料。
4. **证据不足**：仓库不存在问题所需资料时，Agent 说明证据不足并选择继续文件搜索或结束回答，不伪造来源。

## 功能需求

### F1：启用、配置与工作区隔离

用户能启用或停用当前工作区的知识检索，配置文档与代码的索引范围及 Embedding 服务，并查看实际生效配置。服务配置与对话模型独立。未配置或未启用时，原有编程对话仍可运行；模型不能通过工具参数选择未授权工作区或任意服务端点。

远程服务启用前，界面和 CLI 必须说明选定范围内的文本片段及检索查询会发送到所配置服务；仅保存配置不扫描仓库、不构建索引、不发送源码。用户显式启用远程服务并发起构建后，后续范围内请求无需逐次确认。凭据仅来自环境变量或未入库的本地私密配置。

### F2：索引构建与内容范围

用户能构建当前授权工作区的索引，查看构建状态、成功文件/片段数、跳过数量与原因。文档片段保留标题上下文，代码片段保留可识别的所属符号或结构上下文，均保留可定位的原文来源。

默认排除依赖、构建产物、二进制、密钥、本地私密配置、日志、会话和记忆存储、索引自身及历史归档。用户配置不能覆盖已有安全拒绝。超限或不可解析文件可跳过，但必须说明原因；合法范围内无文件与构建失败必须区分。

### F3：增量更新、删除与索引版本

用户能更新、重建和删除索引。未变化的内容可复用已有计算结果；新增、修改、删除及移出范围的文件在成功更新后反映到索引中。

新版本完整成功后才替代上一可用版本；失败或取消不能发布半成品。相同工作区的重叠构建必须有明确的排队或拒绝结果，不允许相互覆盖。影响向量或片段兼容性的配置变化应显示需要重建，不得混用不兼容数据。删除索引后查询不得继续通过缓存返回已删除索引的片段。

### F4：关键词与语义混合检索

Agent 可以按需调用只读检索能力，用自然语言或符号查询文档、源码、测试或全部材料。检索同时支持精确关键词线索和语义线索，融合候选并减少重复片段；保留原有文件搜索和读取工具。

返回数量、查询长度与证据总量受限，截断或省略必须可见。正常检索、无命中、部分结果和降级检索应有可区分的状态。检索未命中只表示当前索引与查询没有找到证据，不证明整个仓库不存在对应行为。

### F5：来源追溯与当前事实核对

每个有效命中包含工作区内的相对路径、行号范围、原文摘录、适用的标题或符号、内容版本标识、索引版本及历史材料标记。排名或相似度不得作为答案正确率展示。

结果返回前重新校验来源的当前访问权限和内容版本；文件已变化、删除或不可访问时，旧正文不作为有效证据返回，并提示刷新或改用文件工具。此校验仅代表该次读取时点，不承诺返回后文件不再变化。Agent 在进行代码修改前继续读取当前文件并遵循原有编辑校验。

基于检索的事实性回答应引用支持结论的文件位置。文档与当前实现冲突时应指出冲突，以当前代码解释实现，以文档解释设计意图；历史材料不得被静默描述为现状。

### F6：Agent 集成与证据预算

检索通过既有工具调用流程提供，在 Plan 和 Do 模式均属于只读能力，不改变模式和修改权限。由 Agent 根据任务按需调用，不在每轮对话自动注入固定数量的片段。

检索证据纳入已有上下文预算与大结果管理，不形成无限增长的隐藏上下文。正文是待核对的资料，不是系统指令；资料内要求执行命令、修改权限或读取密钥的内容不能因此获得授权。检索成功和模型最终回复均不等于任务验收成功。

### F7：失败、降级、取消与终止

无效参数、未构建索引、配置不兼容、权限拒绝、索引损坏、服务失败、超时和取消应返回可区分的结构化结果及可行的下一步。

语义服务不可用且存在可用关键词索引时，允许在原有权限内降级，并显式说明；没有可用索引时返回不可用状态，由 Agent 决定是否改用原有文件工具。错误不能伪装成正常的零命中。

构建和查询均可取消并受时长、输入规模及服务请求预算限制。取消或超时后不得发布新索引或继续安排后续服务请求，已发出请求应尽力中止。重试有界，不能绕过 Agent 的总时限、轮数和任务预算；达到限制时按既有停止语义结束。具体上限在技术计划中明确。

### F8：Web 与 CLI 管理和展示

两端均能完成配置、启停、构建、更新、重建、删除及状态查看；CLI 不依赖 Web 服务启动。展示最近成功版本、构建结果、兼容性和失败原因；“可查询”不意味着自动知道所有尚未扫描的新增文件。

对话中能查看检索状态、结果来源和降级/过期提示。管理动作不自动提交文件、不调用对话模型开始开发任务。停用后停止新检索和新构建，已有进行中的作业取消；保留的索引可由用户另行删除。

### F9：可复现评估与交付证据

建立至少 60 个固定问题，其中开发集 40 个、保留测试集 20 个。标注问题类别、相关证据、答案要点或应判定证据不足的原因；保留测试集不参与参数调优。覆盖精确定位、中文语义定位、跨文件机制分析、无答案、过期/删除、权限及恶意文档内容场景。

检索层比较关键词、向量和混合检索；Agent 层比较原有文件工具与加入检索后的流程。使用相同仓库快照、对话模型、问题和预算，记录配置与失败尝试。检索相关性指标仅在有相关证据标注的问题上计算；无答案和安全问题单独统计。

报告召回与排序质量、延迟、引用支持度、答案正确性、任务通过率、Token 和服务用量；明确样本数、人工判定规则、实际运行次数及未验证项。受控替身验证协议与异常路径，真实模型验证语义质量，两者分开报告。是否有效以实测为准，不设置未经基线支持的提升百分比；没有提升也需交付原因分析，不选择性隐藏结果。

## 非功能需求

- **N1 安全**：扫描、索引读取和结果返回均遵循当前工作区与敏感文件权限，防止路径穿越、符号链接越界、跨工作区引用及旧索引绕过权限。不能宣称能自动识别任意普通源码中的所有秘密；索引范围与远程传输边界必须明确。
- **N2 凭据与数据保护**：凭据不进入源码、文档、索引、日志或截图；本地索引按敏感派生数据管理，不默认加入版本控制。诊断默认记录状态和规模，不记录完整查询、源码或服务请求正文。
- **N3 一致性与恢复**：查询绑定完整索引版本；构建中断后仍可识别最近成功版本。磁盘损坏和不兼容版本不得以空结果掩盖，不能要求依靠删除会话来恢复检索。
- **N4 资源有界**：限制扫描文件量、单文件大小、片段总量、请求并发、服务超时、重试、结果数量和上下文预算；限制命中可观察。技术计划需为每项给出默认值和配置边界。性能报告说明硬件、索引规模及本地计算与服务耗时，不先承诺无依据的延迟目标。
- **N5 架构与兼容性**：遵守自主实现约束，不引入 Agent 框架、服务端托管文件或代码执行能力。Web/CLI 共享核心行为；停用功能时不强制准备向量服务，已有会话、记忆、权限和工具使用保持兼容。新增依赖必须在技术计划中单独说明必要性。
- **N6 可观测与可验证**：记录索引版本、配置版本、召回方式、候选/返回数量、耗时、降级原因和用量来源；未知用量标记未知。评估记录与任务完成证据分离，可追溯实际命令和结果。

## 不做的事

- PDF/OCR、图片、多模态检索、网页抓取、外部知识库连接及跨工作区联合检索。
- 自动部署模型、训练或微调 Embedding、自动选模。
- 本轮必需的重排模型、查询改写、多轮自主检索规划、知识图谱或调用图分析。
- 自动文件监听、每次编辑后后台全量重建、分布式索引与多人共享索引。
- 将对话历史和项目记忆合并为统一知识库，或重做现有上下文压缩与权限流程。
- 新增专门的子 Agent 检索编排；本轮验收以主 Agent 的 Web/CLI 闭环为准，任何已有子执行路径均不得因本功能获得额外权限。
- 把检索命中当作代码事实、把最终回答当作验收通过，或预先声明性能提升。
- 在文档审批阶段实现功能、运行付费模型评估、提交、推送或创建 PR。

## 验收标准

以下为后续验收约定，尚未执行，不代表功能已实现。

| AC2 | F1、F2、N1 | 在含合法材料、敏感配置、越界符号链接、历史材料及索引自身的夹具中构建；仅授权范围被纳入，跳过原因可见。切换工作区及伪造跨工作区输入不能读取另一工作区内容。 |
| AC3 | F2、F5 | 对含多级标题、函数、类和测试的材料构建并检索，命中保留可理解的上下文，返回行号与摘录能逐条对上原文；超限或解析失败文件有可见记录。 |
| AC4 | F3、N3 | 初次构建后分别新增、修改、删除和移出文件，再更新；新版本反映全部变化，未变化内容复用有记录。改变不兼容配置后明确要求重建，不能混用。 |
| AC5 | F3、F7、N3 | 构建途中注入服务失败或取消，旧完整版本保留，新版本不发布；重叠构建有明确结果。删除后旧缓存不再供查询，进程重启后状态仍一致。 |
| AC6 | F4 | 使用精确符号、中文行为描述和限定材料类别查询，分别获得可核对的候选；受控数据证明关键词和语义两路均参与混合检索。重复片段、结果截断和空结果的表现符合约定。 |
| AC7 | F5、N1 | 建索引后修改、删除文件或收紧读取权限，不更新直接查询；旧正文被剔除，显示失效或不可用信息，拒绝信息不泄露未授权正文；刷新后返回新的有效来源。 |
| AC8 | F5、F6 | 完成机制解释和修改准备两个场景；事实结论能追溯到支持它的来源，文档与实现冲突被指出；实际修改前有当前文件读取，检索成功不被记录为整项任务验收通过。 |
| AC9 | F4、F6、N4、N5 | Plan/Do 均可检索但保留原有写入边界；无需检索的对话不自动注入片段。大结果遵循既有上下文管理，输出数量和总量不越界。 |
| AC10 | F6、N1 | 索引夹具包含要求越权读取或执行命令的文本；其只能作为资料出现，运行时不因此放宽权限。分别记录确定性权限测试及真实模型行为，不能以一次模型未越权宣称全面免疫提示注入。 |
| AC11 | F7 | 分别注入无效参数、无索引、损坏索引、服务失败及超时；得到可区分结果。语义不可用时，仅在存在安全可用关键词索引时明确降级；没有索引时不会伪装成正常零命中。 |
| AC12 | F7、N4 | 构建和查询取消后不再安排后续服务请求且不发布新索引；有限重试、超时和规模上限可验证。Agent 达到轮数或总预算限制后停止，不因检索反复重试而延长。 |
| AC13 | F8、N5 | 分别在 Web 与独立 CLI 完成配置到查询的完整流程，并执行更新、重建、删除、停用；状态和错误语义一致，管理动作不自动触发对话模型开发任务。 |
| AC14 | F9、N6 | 评估集达到 60 题并记录 40/20 划分；按固定配置运行检索三组对照和 Agent 两组对照，报告全部尝试、失败、用量和人工判定结果；未运行的真实模型场景明确标记未验证。 |
| AC15 | N2、N6 | 检查配置展示、索引、诊断日志和评估产物；无凭据泄露，诊断默认无完整查询/源码正文，索引未被默认纳入版本控制。状态、版本、耗时及降级信息足以追溯运行。 |
| AC16 | N4、F9 | 在明确硬件和仓库规模下记录首次构建、无变化更新、少量文件变更和查询的耗时与资源数据；区分服务和本地耗时，对超限行为给出证据，不将结果外推为所有仓库的性能保证。 |

## 审核重点

1. 是否接受文档、源码与测试联合检索，以及显式构建/更新、无后台监听的本轮范围。
2. 是否接受独立 Embedding 配置、远程文本发送说明及最小 Web/CLI 管理入口。
3. 是否接受以来源核对、增量一致性、权限隔离及 60 题对照评估作为交付要求。

本规格与计划、任务、验收清单已获批准，作为本轮开发基线；实际执行结果见 checklist.md。
