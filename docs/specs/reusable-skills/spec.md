# 可复用 Skill 需求规格

状态：已批准

流程说明：用户已明确批准四份文档并授权开始开发。

## 背景

OrbitCode 的 Web 与 CLI 已共用 Agent 运行、工具执行、Plan/Do、权限审批和会话持久化。立项时已有 `activatedSkills` 提示位，但尚无 Skill 目录发现、定义管理、激活状态及独立执行闭环。现有提示与工具列表在用户回合开始时形成，新增能力须保证回合内加载 Skill 后，后续模型请求及时获得对应指令及工具限制。

本规格以立项时仓库代码为基线，不把已有提示位等同于已经实现 Skill。现有 YAML 解析依赖可供后续设计复用。

## 目标

用户将重复操作编写为带 YAML 元信息的 Markdown，在 Web 与 CLI 中发现、选择并执行。模型初始只获取名称与简介，需要时加载完整操作指令；共享与独立执行共用现有 Agent Loop 和安全规则。

本轮保留发现与激活、独立执行、双端入口三个实施单元，整体交付用户提出的完整闭环，不提前缩减独立模式或目录型 Skill。

## 假设与方案选择

以下记录已确认的选择及待随整份规格审批的假设，尚不代表实现结论；单项确认不代表整份规格已批准：

1. **已由用户确认：**多个共享 Skill 的白名单取交集，所有已激活 Skill 都允许的工具才可用。`load_skill` 始终豁免 Skill 白名单，但不豁免其他安全规则。对应 F6、AC8。
2. 独立模式隔离对话、上下文、激活状态、执行预算和完成判定，不创建独立文件系统或 Git 工作树；使用当前授权工作区，文件副作用不会自动回滚。
3. 可选模型引用已有可用模型配置，不允许 Skill 内携带凭据或任意连接地址。共享模式沿用当前会话模型，显式指定不同模型时拒绝激活并提示改用独立模式；独立模式可采用所指定模型。
4. 独立模式历史范围提供“不带历史”“最近 N 个完整用户回合”“当前可用全部历史”，默认不带历史；当前调用参数始终传入。全部历史指当前可用上下文，不承诺自动还原已压缩原文。
5. 同名 Skill 不在同一会话中保留多个实例；重复加载相同定义和参数为幂等操作，参数变化产生明确的替换激活。定义刷新不替换现有激活；需要采用新定义时，显式重新激活。
6. 共享激活状态随会话保存、恢复并持续生效，直至显式停用或清空会话。停用作为解除长期工具限制的必要配套能力纳入本轮。
7. 独立执行同步等待结果，主会话暂停推进；本轮不支持独立会话再启动独立 Skill，避免递归任务树。独立会话仍可加载共享 Skill，并继承不可放宽的父级工具限制。

## 功能需求

### F1：定义格式与参数

支持单文件 Skill 和以入口 Markdown 为主的目录型 Skill。入口由 YAML frontmatter 与 Markdown 正文组成，包含唯一名称、简短说明、显式工具白名单、执行模式、独立模式历史范围及可选模型。名称采用统一、可用于命令识别的规则；目录名不替代声明名称。

名称、说明、白名单和模式为必填；独立历史范围缺省为不带历史；共享模式不接受有效的独立历史配置。空白名单表示仅可使用白名单豁免的 `load_skill`，不表示无限制。拒绝未知字段、错误字段类型、空正文及无效模式，返回可定位的诊断。

正文支持明确的用户参数占位符，至少支持完整参数文本及按位置引用。替换作为纯文本操作，不执行模板代码、Shell 展开或递归替换；缺少被引用参数时返回可恢复错误且不修改激活状态。确切字段及占位符语法在技术计划中统一定义并提供示例。

### F2：来源、覆盖与诊断

从项目级、用户级、内置来源发现 Skill，同名优先级为项目级高于用户级、高于内置。同层出现重名时将该名称标记为冲突，不依赖文件枚举顺序静默选择。

单文件读取、解析或校验失败仅报告该文件，不阻断其他名称。目录缺失视为空；不可读来源报告诊断，不伪装为空目录。可识别名称的高优先级无效定义阻止该名称静默回退到低优先级版本；无法识别名称的文件仅报告文件错误。列表可查看有效来源、覆盖及错误信息。

### F3：两阶段加载

未激活 Skill 的初始模型提示只包含名称与简介，不包含正文、附属资源内容或完整元信息。浏览列表、启动会话不执行 Skill 或脚本，也不因此调用模型。

模型通过内置 `load_skill` 指定名称及参数请求加载；用户斜杠命令走同一校验和激活语义。加载前校验定义、参数、白名单及所引用模型，成功后才原子更新状态或开始独立执行。不存在、不可用或无效 Skill 返回结构化可恢复错误，保留原有会话状态。

### F4：共享激活与会话生命周期

共享模式沿用当前会话，在 `activatedSkills` 提示位中保留参数替换后的完整指令。加载成功后的下一次模型请求起，包括同一用户回合的后续迭代、后续用户回合以及上下文压缩后的请求，均包含全部有效激活内容，且不重复堆叠同名内容。

支持同时激活多个不同名称 Skill，显示激活状态并可显式停用。停用只移除相应有效指令和限制，不删除历史执行记录。清空会话同时清空激活状态；取消、清空与迟到结果不得导致旧状态复活。会话恢复采用已保存激活快照，不从当前磁盘静默重建；旧会话兼容为空激活集合。

### F5：独立执行与结果回传

独立模式使用隔离 Agent 会话执行，复用现有循环；主会话激活集合不因子会话加载而改变。按定义选择历史，保留完整消息与工具结果配对，不携带悬空工具调用或直接复用主会话专属上下文引用。无法安全携带的内容须明确报告，不静默扩大读取范围。

子会话继承当前 Workspace、Plan/Do 模式、权限约束及父级工具限制，重新建立自身执行状态；不得自动切换到 Do。历史范围限制不移除系统约束、项目指令和其他必要运行背景。

执行完毕后向主会话返回有界结果摘要，包含执行状态、关键结果、验证证据、文件副作用及未完成事项。失败、拒绝、取消、超时或达到循环上限均如实回传；模型最终文本不等于任务已验证通过。主会话不自动合并子会话全部消息或激活内容。

取消父调用会取消子会话与所属进程；子会话受自身上限和父调用剩余预算共同约束。中断后不自动重新执行有副作用的任务，迟到结果不能写入已清空或已变更的主会话。加载入口可观察子执行状态及待审批动作。

### F6：工具白名单与双重约束

在定义加载时校验白名单格式和工具标识，未知或不合法条目不得忽略或变为全量授权。已配置但尚未完成发现的外部工具只能标记为待验证，不允许激活；连接和发现继续遵守已有审批，不因扫描 Skill 自动发起。

激活时按当前工具目录重新校验可用性。多个共享 Skill 取白名单交集；独立执行同时受父级有效限制约束。模型可见工具和实际可执行工具使用同一有效约束，Plan/Do、Workspace、危险命令限制和权限审批继续独立生效。

`load_skill` 不受 Skill 白名单限制，Plan 中也可加载符合只读限制的 Skill；加载不能使 Plan 获得写入、命令或外部连接能力。除 `load_skill` 外不默认为任何工具设置白名单豁免，内置样板必须显式列出所需完成报告等工具。

激活或停用生效后及时更新下一次模型请求的工具列表；对同批次尚未执行的工具调用以及已准备但未执行的调用，在执行前重新检查有效策略，禁止通过旧列表、缓存调用或手工构造参数绕过限制。审批允许不能覆盖白名单拒绝。

### F7：Web 与 CLI 入口

两端均提供 Skill 列表、简介、来源、可用性、诊断、激活状态和刷新操作；完整正文只在明确加载后进入模型上下文。提供一致的斜杠命令用于调用 Skill、查看列表、刷新与停用。

已有控制命令保持原义，Skill 同名不能覆盖控制命令；提供无歧义的显式调用形式。参数支持带空格文本。运行中禁止会改变当前激活状态的界面操作，或明确拒绝为忙碌；定义刷新可以进行，但不改变当前执行快照。两端展示相同的成功、错误、取消及审批语义。

### F8：刷新与快照

文件新增、修改、删除后可显式刷新目录，后续调用采用刷新后的有效定义。正在运行的会话及已有激活保持原指令、参数、白名单、模式和模型选择，刷新不会覆盖它们。定义内容变化后显示可更新状态，由用户显式重新激活。

待加载的定义在发现后发生改变时，不混用旧元信息与新正文；返回需要刷新诊断，或使用完整一致的已捕获定义。目录型资源读取同样不能混用来源或越界；已引用资源若发生变化，应明确拒绝并要求重新激活，不在执行中静默采用新内容。

### F9：目录型资源与路径边界

目录型 Skill 可按需引用同目录树中的模板、示例、脚本和参考文件。列表不预读全部资源，加载正文不自动展开资源或运行脚本；读取结果有体积限制，过大时明确拒绝或提供有界读取方式。

三类入口的发现与 `load_skill` 读取仅限已配置 Skill 来源，是定义加载能力，不授予通用文件访问权。附属资源的实际读取仍受授权 Workspace 边界和现有权限规则约束；用户级或内置资源在 Workspace 外时，明确说明不可读并提示放入授权工作区，不隐式放宽文件沙箱。

拒绝绝对资源路径、路径穿越、符号链接逃逸及受保护内容访问。脚本只能通过已有命令执行能力按白名单、Plan/Do、审批、超时与取消规则运行；脚本作为文本存在不构成执行授权。

### F10：内置样板

提供 `commit`、`review`、`test` 三个内置 Skill，能被更高优先级同名定义覆盖。样板遵循当前 TypeScript 严格模式、npm 脚本、仓库指令与检查流程，不引入 Agent 框架。

`commit` 检查变更及验证结果，仅提交用户授权范围，使用中文提交说明，不默认推送、改写历史或包含敏感文件；缺乏授权时报告待确认事项。`review` 默认只读审查并给出可定位问题与证据，不自动修复或提交。`test` 按改动选择相关测试，功能完成后依次执行 lint、typecheck、build，报告实际退出状态、失败及未验证项；需要页面和 Agent 端到端验证时遵守仓库规则，不自动调用未经授权的真实模型。

### F11：可恢复失败与终止

区分定义错误、参数错误、工具不可用、权限拒绝、资源失效、上下文超限、执行失败及取消/超时等结果。可恢复错误允许模型修正或解释受限原因；持续失败受既有失败预算、循环与时间上限控制。

激活内容超出可接受上下文预算时拒绝此次激活并保持原状态，不静默截断操作指令或安全约束。独立执行无法启动时不得伪报成功或退回共享模式；指定模型不可用时不得静默改用其他模型。运行记录可区分主会话和独立执行，保留实际工具状态、终止原因及验证边界，不泄露凭据。

## 非功能需求

- N1：实现在 Web/CLI 共用运行层与工具层，复用现有 Agent Loop、模型适配、上下文及权限机制；核心不反向依赖 UI。
- N2：遵守 AGENTS.md，保持严格 TypeScript；默认不新增运行时依赖，不使用禁止的 Agent 框架或托管代码/文件工具。
- N3：Skill 内容与参数不能覆盖系统约束、权限策略及凭据保护。参数插值不声称能完全防御提示注入；真正权限由执行端强制约束。
- N4：目录扫描、文件读取、激活数量、提示长度及子执行有明确上限、取消路径和可观察诊断；具体数值由技术计划明确，禁止静默漏掉已激活内容。
- N5：无 Skill 的旧会话和正常 Web/CLI 工作流保持兼容；状态持久化遵守已有并发、修订号和清空机制。
- N6：验证优先使用安全本地模型替身；真实模型需已有明确授权与未入库配置。检查项记录实际结果，不以最终回复替代验收证据。

## 不做的事

- Skill 市场、远端安装分发、版本管理或自动更新；执行快照只保证本次会话一致性，不构成版本产品。
- Skill 可视化编辑器、任意代码模板引擎、自动脚本执行。
- 新的 Agent 框架、第二套 Agent Loop、独立文件系统、自动回滚文件副作用。
- 并行子任务编排、递归独立 Skill、后台脱离主调用持续运行。
- 借 Skill 改造全部上下文压缩、长期记忆、权限或模型配置产品；仅做本能力所需集成。
- 自动提交、推送或创建 PR；内置 commit 只有在用户明确调用并授权相应范围时才执行提交流程。

## 验收标准

- AC1（F1）：合法单文件与目录型入口均可发现；缺字段、未知字段、类型错误、非法模式、空正文及空白名单分别产生约定结果；完整参数与位置参数按纯文本替换，缺参失败不改变会话。
- AC2（F2）：三层同名时选项目级，其次用户级、内置；同层冲突明确报错；一个坏文件不影响另一个有效名称，可识别名称的无效覆盖不静默回退；缺目录与不可读目录可区分。
- AC3（F3）：检查首次模型请求仅有未激活 Skill 的名称与简介；列目录不调用模型或执行脚本；成功 load_skill 后才出现正文，未知名称或无效模型加载失败无状态残留。
- AC4（F4）：回合内加载后下一次请求、下一用户回合和压缩后均保留完整激活内容；多个不同名称共存，相同加载不重复，参数替换有明确结果。
- AC5（F4、F8）：保存后由 Web/CLI 恢复得到相同激活快照；停用移除有效约束但保留记录；清空后不再出现旧激活，取消和迟到回传不使其复活；旧检查点可打开。
- AC6（F5）：三种历史范围准确携带完整回合，无悬空工具结果或越权上下文引用；子会话激活、消息和完成状态不污染主会话，文件副作用可见；模型选择及共享模型冲突符合假设。
- AC7（F5、F11）：子执行成功、失败、审批拒绝、取消、超时和达到轮数上限均向主会话提供准确有界摘要；父取消传播至子进程，不自动重做副作用，不接受已清空会话的迟到结果；独立递归明确拒绝。
- AC8（F6）：两个共享 Skill 取白名单交集，模型工具列表与实际执行一致；父级限制不能被独立执行或加载其他 Skill 扩大；空交集仍允许 load_skill；审批允许无法绕过 Skill 拒绝。
- AC9（F6）：未知白名单工具阻止激活，待发现外部工具明确待验证；发现不得绕过连接审批；Plan 下加载写操作 Skill 后写入、命令和外部连接仍被拒绝；同批次及已准备调用在策略变化后不能越权。
- AC10（F7）：Web 与 CLI 均可查看、调用、刷新、停用并处理含空格参数；与已有控制命令同名时行为无歧义；忙碌、错误、子执行及审批状态均可观察。
- AC11（F8）：刷新新增、修改、删除定义后新调用反映新目录，执行中及现有激活不被覆盖；明确重新激活才应用新版；发现后入口变化或附属资源变化不能造成混合内容执行。
- AC12（F9）：模板、示例、脚本、参考文件按需读取且不自动执行；Workspace 外资源、符号链接逃逸、穿越和受保护路径被拒绝；合法工作区资源可按规则读取，脚本执行仍需对应工具及审批。
- AC13（F10）：三个内置样板可列出及调用、可被项目定义覆盖；commit 不默认推送或提交无关内容，review 不修改文件，test 使用现有 npm 检查且如实报告失败和未验证项。
- AC14（F11、N4）：解析、缺参、资源失效和执行错误具有可恢复结果；超出激活预算保持旧状态，重复失败按预算停止；模型不可用不静默回退，共享与独立模式不隐式互换。
- AC15（N1—N6）：检查双端共用执行逻辑和安全机制；相关自动化检查通过后依次运行 lint、typecheck、build；页面以真实浏览器检查内容、错误覆盖层及控制台，并结束相关进程；Agent 流程在 tmux 中验证成功、工具失败、无效参数、超时和最大循环路径，保留真实证据。

## 规格自检

F1—F11 均已映射 AC；覆盖成功、可恢复错误、终止、双端一致性及安全边界。本文未决定新增实现文件、函数或类型，确切配置语法、目录约定与预算数值见配套技术计划。实现已按用户开发授权落地；实际验证范围及未覆盖项见 checklist.md，不以批准状态代替验收结果。
