# 单次工具调用系统 Spec

状态：已批准

## 背景

OrbitCode 当前已经具备 Web 与 CLI 的 OpenAI 兼容流式纯文本对话能力，但模型只能生成文字，不能读取项目、修改代码或执行本地验证。用户希望先在 Web 对话入口建立一个最小但完整的工具调用闭环：模型判断是否需要工具，服务端安全执行一次本地工具，将结构化结果回传给模型，再由模型生成最终回复；浏览器只负责发起对话和展示状态，不直接接触凭据或执行本地操作。

本阶段需要同时建立工具统一契约、注册与发现、工作目录与凭据保护、参数校验、执行错误模型、OpenAI 流式 Tool Calling 解析、单次工具编排和 Web 可观察状态。它是后续完整 Agent Loop 的基础，但本轮刻意限制每个用户请求最多执行一个工具，避免提前引入连续自主执行。

## 目标

- 提供读取文件、写入文件、修改文件、执行命令、按模式查找文件和搜索代码内容六种核心能力。
- 让模型通过 OpenAI 兼容 Tool Calling 选择工具并提供参数，由 OrbitCode 服务端完成校验与执行。
- 将工具调用及其结构化结果纳入当前请求的模型上下文，使模型能够基于真实执行结果生成最终回复。
- 在用户授权的单一工作目录内建立可验证的文件与命令隔离，并保护凭据和其他敏感配置。
- 在 Web 页面展示工具名称、执行状态和安全的结构化结果，同时保持现有纯文本对话能力。
- 保持 Agent 编排、模型适配、工具执行与 React 页面解耦，为下一阶段扩展完整 Agent Loop 留出稳定边界。

## 假设

- Web 服务启动时的项目工作目录视为用户本次授权的唯一工作目录；本阶段不在页面中选择、切换或同时授权多个目录。
- 六个文件与搜索工具只处理 UTF-8 文本和路径元数据，不读取或写入二进制文件。
- 写入文件表示创建新文本文件或完整覆盖已有文本文件；目标父目录必须已经存在，不隐式创建目录。
- 修改文件只执行一次“原文到新文本”的唯一匹配替换；原文不存在、出现多次或替换不会产生变化时均不修改文件。
- “严格命令隔离”指命令只能读写授权工作目录内允许访问的项目数据。为启动进程而必需的系统可执行文件、动态库和只读运行时资源可以访问，但不属于可操作的项目数据；无法建立该隔离时命令不得启动。
- 工作目录内的凭据文件、本地秘密配置及模型认证环境变量不属于工具授权范围。文件、搜索和命令工具均不得读取、修改或通过输出暴露这些内容。
- 工具输出会设置明确的大小和条目上限；超过上限时返回带截断标记的有效结构化结果，而不是无界缓冲或使请求失败。具体上限在技术计划中确定。
- 工具调用记录和工具结果必须进入当前用户请求的第二次模型调用；后续用户轮次继续保留用户消息和最终助手回复，但不要求浏览器保存或重新提交可伪造的内部工具消息。
- OpenAI 兼容服务应支持标准 Chat Completions 流式 Tool Calling。模型若不请求工具，现有纯文本流式回复行为保持不变。
- 本阶段只把工具能力接入 Web 对话；CLI 保留现有纯文本交互，不在本轮获得工具执行能力。

## 功能需求

- F1：系统通过统一工具契约描述每个工具的稳定名称、用途说明、参数约束和执行能力，并由一个集中注册中心提供工具枚举、按名称查找及模型可用工具定义；重复名称或无效定义必须在执行前被拒绝。
- F2：读取文件工具接收工作目录内的文本文件路径，成功时返回文件内容及必要元数据；路径不存在、目标不是普通文件、内容不是可接受文本、文件过大、路径越界或受保护时返回结构化失败且不泄露目标内容。
- F3：写入文件工具接收工作目录内的目标路径和完整文本，能够创建新文件或覆盖已有普通文本文件；成功时报告写入结果，校验或写入失败时返回结构化失败，且不得在失败前后产生目录外写入。
- F4：修改文件工具接收工作目录内的文本文件路径、待替换原文和替换文本，只在原文恰好出现一次时完成一次替换；匹配零次、匹配多次、目标无效或写入失败时返回可供模型调整的清晰结构化结果，并避免留下部分写入。
- F5：执行命令工具接收命令及受支持的执行选项，在严格隔离环境中启动进程；成功或失败均保留 stdout、stderr、退出码、是否超时和是否取消，且所有字段以结构化结果返回。
- F6：按模式查找文件工具在授权工作目录内按声明的路径模式查找文件，返回稳定、可预测顺序的相对路径列表；无匹配返回成功的空结果，非法模式、越界访问或执行异常返回结构化失败。
- F7：搜索代码内容工具在授权工作目录内查找文本模式，返回包含相对路径、位置和匹配文本的结构化结果；无匹配返回成功的空结果，非法搜索模式、不可读文件、越界访问或执行异常按稳定规则处理并报告。
- F8：所有工具参数都必须在执行前接受运行时校验。未知字段、缺少字段、错误类型、空值、超限值、非法模式和其他不符合参数约束的输入不得触发工具副作用，并返回可供模型理解的结构化参数错误。
- F9：所有模型提供的路径都相对于授权工作目录解析；绝对路径、路径穿越、符号链接逃逸、路径解析竞态和受保护目标必须被拒绝。对新建目标也必须验证其现有父路径仍位于授权边界内。
- F10：命令执行只能在已成功建立的严格隔离环境中进行；命令及其子进程不得读取或修改授权范围外的项目数据，不得获得模型 API Key 或完整服务端环境。隔离不可用、建立失败或被命令绕过时，系统拒绝或终止执行并返回结构化安全错误。
- F11：每次工具执行都有明确超时并响应当前 Web 请求的取消信号。超时、取消、启动失败、运行失败和意外异常必须被收敛为结构化结果；命令取消时应终止其派生进程，不遗留继续运行的任务。
- F12：OpenAI 兼容模型请求包含注册中心生成的工具定义；Provider 能够从流式响应中识别文本或工具调用，并按调用标识正确拼接跨任意网络分片到达的工具名称和 JSON 参数。
- F13：Provider 兼容单个响应中的说明文本与一个工具调用；对缺失调用标识、冲突名称、参数片段顺序异常、无效 JSON、未知完成原因以及同时返回多个工具调用给出明确协议失败，不执行任何不确定工具。
- F14：用户提交问题后，模型若直接返回文本，系统按现有方式流式展示并完成该轮；模型若返回一个有效工具调用，系统停止把该响应当作最终回复，校验并执行该工具，再把原始工具调用和结构化执行结果按协议顺序回传给同一模型以生成最终文本回复。
- F15：每个用户请求最多执行一次工具。第二次模型调用不得再次执行工具；若模型再次请求工具、返回多个工具调用或未给出可完成的最终文本，系统终止本轮并向页面返回可恢复的明确错误。
- F16：工具失败属于可恢复的执行结果。未知工具、无效参数、路径拒绝、无匹配修改、命令非零退出、超时和工具内部异常均应在不崩溃服务的前提下回传给模型，让模型基于失败原因生成最终回复；用户主动取消除外，取消后不再发起模型跟进请求。
- F17：Web 页面在同一助手轮次中展示工具调用名称、执行中、成功、失败、超时或取消状态，以及经过边界检查和大小限制的结构化执行结果；状态到达顺序与服务端实际生命周期一致，页面不自行推断或执行工具。
- F18：只有最终成功完成的用户消息和助手最终回复进入后续普通对话历史。模型请求失败、协议失败、用户取消或最终回复未完成的轮次不进入后续历史；工具副作用已经成功发生但最终回复失败时，页面必须明确提示副作用可能已发生，不能暗示已回滚。
- F19：Web 请求断开、用户点击停止或页面卸载时，系统中止当前模型流或工具执行，释放响应读取器、进程、计时器和监听器，并将界面恢复为可继续对话的稳定状态。

## 非功能需求

- N1：Agent 编排和工具执行逻辑必须是独立的严格类型 TypeScript 核心能力，不依赖 React、浏览器 API 或 Next.js 页面组件；界面与服务端入口只负责适配输入输出和展示。
- N2：实现不得使用任何 Agent 框架、Agent SDK、托管代码执行、Files API 或服务端代管文件工具；对话历史、工具定义、参数校验、执行、模型输出解析、终止和错误处理均由 OrbitCode 自行实现。
- N3：API Key、认证请求头、完整环境变量、受保护文件内容、内部堆栈和未经约束的上游响应正文不得进入模型工具结果、浏览器事件、DOM、控制台或应用日志。
- N4：工具参数、OpenAI 流式增量、Web 请求和 Web 流式事件均视为不可信输入，使用明确的判别状态和运行时校验；不得依赖无必要的 `any`、宽泛类型断言或隐式字段透传。
- N5：文件内容、命令输出、搜索结果数量、路径长度、参数大小、单次执行时间和 Web 请求体均有明确上限；触发上限时系统以稳定、可观察的失败或截断结果结束，不出现无界资源占用。
- N6：工具异常、模型协议异常和取消不得导致 Next.js 服务崩溃、未处理 Promise、僵尸进程、部分文件写入、资源泄漏或无法继续对话。
- N7：工具定义转换必须保持单一事实来源，注册信息、运行时校验和发送给模型的参数约束不得出现静默不一致。
- N8：不新增运行时依赖；优先使用 Node.js 标准库、现有依赖和目标操作系统已有的隔离能力。若严格命令隔离在目标环境不可用，必须安全拒绝命令而不是降级为仅限制当前目录。
- N9：保留现有 CLI 公开行为、模型配置格式、纯文本 Web 对话路径和已有测试；不要求浏览器获得本地文件系统权限，也不把服务端工具实现打包到客户端。
- N10：工具调用和结果的页面展示使用纯文本或安全结构化视图，不把文件内容、命令输出或模型文本解释为可执行 HTML；桌面与窄屏布局均可辨识状态和长输出截断信息。
- N11：六个工具、Provider 分片解析、单次编排、安全边界和异常路径必须可在不使用真实凭据的情况下通过自动化替身验证；真实模型验收使用用户本地未入库配置，证据不得记录密钥或敏感文件内容。

## 不做的事

- 不实现连续多轮工具调用、并行工具调用、自动规划、反思重试、上下文压缩或完整自主 Agent Loop。
- 不允许一次模型响应执行多个工具；不通过只执行第一个调用来忽略其余调用。
- 不实现工具执行前的逐次用户审批、权限弹窗、持久化授权策略或可编辑命令白名单。
- 不在 Web 页面选择、添加或切换工作目录，不支持多工作区或工作区外文件授权。
- 不为 CLI 接入工具调用，不改变 CLI 当前的纯文本流式交互。
- 不处理二进制文件、图片、压缩包、富文本、文件上传或目录整体写入。
- 不实现创建目录、删除文件、移动文件、重命名文件、应用补丁或版本控制专用工具。
- 不承诺回滚已经成功完成的文件写入、修改或命令副作用；最终模型回复失败时只明确报告状态。
- 不实现面向不受信任公网或多租户环境的身份认证、会话隔离和远程代码执行服务。
- 不新增 Provider 协议，不提供模型参数或工具开关的页面配置。

## 验收标准

- AC1（覆盖 F1、F8、N7）：登记六个合法工具后，可以枚举并按名称找到每个工具，生成的模型工具定义与各自运行时参数约束一致；重复名称、未知名称、缺失字段、未知字段和错误类型均在产生副作用前得到稳定的结构化拒绝。
- AC2（覆盖 F2、F9、N3、N5）：在临时授权工作目录中读取普通 UTF-8 文件可获得受限大小的内容和元数据；绝对路径、`..` 穿越、目录目标、符号链接逃逸、超限文件及受保护凭据文件均被拒绝，返回内容、日志和浏览器事件不包含哨兵密钥。
- AC3（覆盖 F3、F9、N6）：写入工具能创建和完整覆盖工作目录内的文本文件；父目录不存在、目标越界、目标受保护、目标经符号链接逃逸或写入中途失败时返回结构化错误，目录外无文件变化，已有目标不会留下可观察的部分内容。
- AC4（覆盖 F4、F9、N6）：分别对原文唯一、原文不存在、原文出现两次和替换文本相同的文件执行修改；只有唯一且实际变化的场景成功写入，其余场景文件字节保持不变并返回模型可据此调整的原因。
- AC5（覆盖 F5、F10、F11、N3、N5、N8）：在具备严格隔离能力的目标环境中，命令的正常退出和非零退出均完整保留受限的 stdout、stderr、退出码、超时与取消字段；读取或写入工作目录外项目数据、读取受保护文件、访问模型凭据或派生进程逃逸均被拒绝或终止。隔离能力不可用时命令不启动，并返回安全错误。
- AC6（覆盖 F6、F7、F9、N5）：文件查找与内容搜索只返回授权目录内、排序稳定、数量受限的相对路径和匹配信息；正常匹配、无匹配、非法模式、不可读文本、结果截断、符号链接逃逸与受保护目标均产生约定的结构化结果，且不会扫描授权边界外内容。
- AC7（覆盖 F11、F16、F19、N6）：分别让工具正常完成、抛出异常、超过超时和接收用户取消；服务保持可用，超时和内部异常可作为结构化结果进入模型跟进，用户取消不发起跟进，命令及其子进程、计时器和监听器均被清理。
- AC8（覆盖 F12、F13、N4）：可控 OpenAI 兼容 SSE 服务将调用标识、名称和 JSON 参数拆分到不同事件及任意网络分块后，Provider 只组装出一个顺序正确的工具调用；同一响应中的说明文本仍以文本增量展示并继续执行该工具；无效 JSON、冲突名称、缺失标识、异常片段和多个调用均成为协议失败且没有工具执行。
- AC9（覆盖 F14、F16）：模型请求工具时，上游记录显示第一次请求包含六个工具定义，第二次请求按协议顺序包含原用户消息、助手工具调用和对应结构化工具结果；工具成功与可恢复失败两种情况下，页面最终都能收到模型基于结果生成的文本回复。
- AC10（覆盖 F14、F15、F18）：模型直接回复文本时不执行工具且保持现有流式体验；模型首次请求一个工具时最多执行一次；第二次响应再次请求工具、缺少最终文本或违反协议时立即终止本轮，后续对话历史不包含该失败轮次。
- AC11（覆盖 F17、F18、F19、N10）：真实浏览器中发起会触发工具的请求，可依次看到准确的工具名称、执行中和终态、受限的结构化结果及最终助手文本；在模型阶段和命令阶段分别点击停止后，界面恢复可输入且状态不误报。工具已产生副作用但最终生成失败时，页面明确提示副作用可能已经发生。
- AC12（覆盖 F18、N9）：完成一次纯文本轮、一次工具轮、一次失败轮和一次取消轮后，下一次上游请求只包含此前成功轮次的用户消息与最终助手回复；CLI 既有交互、Provider 配置格式和纯文本场景继续通过原有验证。
- AC13（覆盖 N1、N2、N4、N8、N9）：类型与依赖检查证明核心编排不依赖 React 或 Next.js 页面、客户端构建不包含工具执行与凭据读取代码、依赖清单没有新增运行时包，且未引入被禁止的 Agent 框架或托管执行能力。
- AC14（覆盖全部需求）：`npm run test`、`npm run lint`、`npm run typecheck` 和 `npm run build` 均以退出码 `0` 完成；开发服务器下使用真实浏览器和用户本地未入库的模型配置完成纯文本回复、六种工具调用、工具失败、命令非零退出、超时、取消、严格隔离拒绝及第二次工具调用终止场景，测试后无残留浏览器、服务器或子进程，输出与证据不含凭据。
