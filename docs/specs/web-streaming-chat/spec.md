# Web 流式对话 Spec

状态：已批准

## 背景

OrbitCode 已具备与 React、Next.js 解耦的 OpenAI 兼容 Provider、SSE 解析、内存会话和 CLI 交互入口，但当前网页仍是项目初始化展示页。用户希望在保留 CLI 的同时，增加一个可实际使用的 Web 对话界面，通过浏览器完成流式纯文本多轮对话，并为后续 Tool Calling、文件操作和 Agent 状态展示预留清晰的界面边界。

## 目标

- 将首页替换为可实际使用的单页聊天界面，而不是静态演示。
- 复用现有模型配置、流式 Provider 和对话语义，通过服务端安全调用真实模型。
- 在浏览器中实时显示模型增量、多轮上下文、取消、失败恢复和清空会话。
- 保持 Web、CLI 与核心对话逻辑相互解耦，CLI 行为不回退。
- 提供桌面与移动端均可用、风格统一且具备基本无障碍语义的界面。

## 假设

- 本阶段 Web 入口面向本机开发与个人使用，不提供身份认证，也不应直接部署到不受信任的公网；README 需要明确这一边界。
- Web 与 CLI 共用项目根目录未入库的 `.env` 和 `orbitcode.yaml`，浏览器不负责录入、存储或查看 API Key、base URL。
- 浏览器仅保存当前页面生命周期内的对话；刷新页面后历史清空。
- YAML 有多个 Provider 时，由用户在页面上选择一个安全公开的配置名称；切换 Provider 会清空当前对话，避免跨模型混用上下文。
- 回复按纯文本展示并保留换行，不把模型内容解释为 HTML 或 Markdown。
- 保留现有 CLI，不以 Web 入口替换或删除 CLI。

## 功能需求

- F1：首页展示 OrbitCode Web 对话工作区，包含品牌/状态区域、当前 Provider、消息区域、输入框和发送控制；首次进入时展示清晰的空状态与可直接开始对话的提示。
- F2：页面从服务端获取可用 Provider 的安全元数据。单配置自动选中；多配置允许按名称选择；配置缺失、非法或凭据不可用时显示可理解的配置错误且不允许发送。
- F3：用户可以输入多行纯文本；非空内容可通过发送按钮或 `Enter` 提交，`Shift+Enter` 插入换行；空白输入不会发起请求。
- F4：提交后立即显示用户消息和助手生成状态；模型文本通过服务端流式响应逐段追加，首个增量到达后立即显示，不等待完整回复。
- F5：每轮成功完成后保留用户与完整助手消息；后续请求按原顺序携带此前成功历史，使模型能够连续对话。
- F6：生成期间用户可以停止当前回复。停止会中止浏览器请求和上游模型请求，保留可辨识的取消状态，但本轮用户消息与部分助手回复不进入后续模型历史。
- F7：网络、HTTP、配置、协议、流截断和服务端异常显示脱敏、可理解的错误状态；错误轮次不进入后续模型历史，界面恢复可输入状态并允许重试。
- F8：用户可以清空当前对话；清空后消息区回到空状态，后续请求不再携带清空前历史。生成期间不可直接清空，须先停止或等待完成。
- F9：切换 Provider 时清空当前对话并更新后续请求目标；切换操作在生成期间禁用，且不会把某个 Provider 的历史发送给另一个 Provider。
- F10：消息区域在新增用户消息、流式增量和状态变化时跟随最新内容；用户主动向上滚动查看历史时，不强制抢回滚动位置，并提供回到底部的明显操作。
- F11：页面对发送中、停止中、配置不可用和请求失败提供明确状态；发送过程中防止重复提交，但输入内容与页面其他安全交互保持可预测。
- F12：Web 服务端只接受本阶段定义的纯文本消息与已存在的 Provider 名称，拒绝未知字段、非法角色、空内容、超长输入、过多历史或格式错误，并返回不包含内部堆栈、配置正文、响应正文及凭据的错误。
- F13：浏览器请求断开、用户停止或页面卸载时，服务端中止上游模型流并释放读取器、监听器及其他本轮资源。

## 非功能需求

- N1：核心对话和 Provider 模块不得依赖 React、浏览器 API 或 Next.js 页面代码；Web 与 CLI 仅作为不同入口调用共享核心。
- N2：API Key、Authorization、环境变量值、完整 YAML、上游错误正文和内部堆栈不得发送到浏览器、写入页面、控制台或日志。
- N3：浏览器到 Next.js 服务端使用真正的增量流式传输；服务端不得先缓冲完整模型回复再返回。
- N4：Web 请求与响应、UI 状态和消息使用 TypeScript 严格类型及运行时输入校验，不使用无必要的 `any` 或宽泛断言。
- N5：不新增运行时依赖；优先使用 React、Next.js、Fetch、ReadableStream、AbortController 和现有 SSE 能力完成闭环。
- N6：界面在常见桌面与窄屏移动视口可用，输入与控制不溢出；交互控件具备可访问名称、键盘焦点和足够的颜色对比度，并尊重减少动画偏好。
- N7：模型文本按纯文本渲染，任何 HTML、脚本或 Markdown 语法均不得作为可执行或富文本内容注入页面。
- N8：API 对单次消息长度、历史消息数量和请求体大小设置明确上限，避免本地误操作造成无界内存或模型请求。
- N9：页面首屏和静态外壳不依赖模型服务可用性；配置或模型故障只降级聊天功能，不产生 Next.js 错误覆盖层或整页崩溃。
- N10：保留现有 CLI 公开行为、配置格式及测试，不要求用户维护两套模型配置。

## 不做的事

- 不实现登录、用户系统、权限角色、CSRF 防护或面向公网的多用户部署。
- 不实现数据库、会话列表、跨刷新持久化、分享链接或云同步。
- 不实现 Markdown 渲染、语法高亮、代码块复制、附件、图片或语音。
- 不实现 Tool Calling、文件读写、命令执行、代码编辑、审批流程或 Agent 循环。
- 不实现上下文压缩、自动摘要、token 计数、费用统计或模型参数调节。
- 不修改 YAML 字段，不在网页中编辑 Provider、base URL 或 API Key。
- 不删除、弱化或重定向现有 CLI 功能。

## 验收标准

- AC1（覆盖 F1、F10、F11、N6、N9）：打开首页可看到完整聊天工作区、空状态、Provider 状态和输入区域；在桌面与移动视口无横向溢出，键盘焦点可见，页面控制台无错误。
- AC2（覆盖 F2、F9、F12）：单 Provider 自动选中；多 Provider 可切换且切换后历史清空；配置缺失、非法、凭据缺失或未知 Provider 时页面显示安全错误，请求不会到达模型服务。
- AC3（覆盖 F3、F11）：空白内容无法发送；`Enter` 提交非空文本，`Shift+Enter` 保留换行；生成期间不会产生第二个并发模型请求。
- AC4（覆盖 F4、N3）：可控服务至少分两批发送文本并延迟完成标记时，浏览器在完成标记前显示第一批文本，最终内容等于所有增量的顺序拼接。
- AC5（覆盖 F5、N1、N10）：完成两轮对话后，第二轮上游请求按顺序包含第一轮用户消息、第一轮完整助手消息和第二轮用户消息；CLI 相关测试继续通过，核心模块未反向依赖 Web 或 React。
- AC6（覆盖 F6、F13）：模型持续输出时点击停止，浏览器与上游请求均中止，界面显示取消状态并恢复输入；下一轮请求不包含被取消轮次的用户消息或部分助手回复。
- AC7（覆盖 F7、F12、N2、N9）：依次模拟网络失败、HTTP 非成功、畸形 SSE、流截断和内部异常，页面均显示脱敏错误、保持可操作且下一次成功请求不包含失败轮次；浏览器响应、DOM、控制台和测试输出不含哨兵凭据或上游正文。
- AC8（覆盖 F8）：至少完成一轮后点击清空，消息区恢复空状态，下一轮上游请求只包含清空后的新用户消息；生成期间清空控制不可用。
- AC9（覆盖 F10）：长对话中位于底部时流式输出自动跟随；用户向上滚动后增量不强制跳回底部，并可通过“回到底部”控制恢复跟随。
- AC10（覆盖 F12、N4、N8）：非法 JSON、未知字段、非法角色、空内容、超长消息、过多历史和不存在 Provider 均在上游请求前被拒绝，返回稳定的结构化安全错误。
- AC11（覆盖 F13）：停止、页面请求断开、成功、失败和开发服务器关闭后均无残留上游请求、读取器或测试监听端口，自动化测试可自行退出。
- AC12（覆盖 N5、N7）：依赖清单没有新增运行时包；包含 HTML 或脚本样式文本的模型回复在页面中仅显示为文字，不产生 DOM 注入或脚本执行。
- AC13（覆盖全部需求）：`npm run test`、`npm run lint`、`npm run typecheck` 和 `npm run build` 均退出码为 `0`；开发服务器下使用真实浏览器完成至少两轮流式对话、停止、失败恢复、清空和移动视口检查，测试后服务器与浏览器资源已清理。
