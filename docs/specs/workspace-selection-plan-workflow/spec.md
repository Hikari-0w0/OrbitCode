# Workspace 选择与 Plan 执行工作流 Spec

状态：已批准

## 背景

OrbitCode 当前把启动进程所在目录固定为唯一授权工作区。页面虽然支持 Plan/Do 模式，但工作区不可选择，Plan 模式只能通过斜杠命令切换，用户完成规划后还要手工切换模式并重新描述执行意图。对于把 OrbitCode 作为本地编程智能体使用的用户，这会把系统限制在 OrbitCode 自身仓库，也缺少“选择项目、只读探索、确认计划、再执行”的清晰闭环。

本阶段让本地服务公开一组由服务端预先授权的 workspace，用户可在页面中选择其一作为当前 Agent 的唯一文件与命令边界；同时增强 Plan 工作流，使模式状态、只读限制和显式执行动作更容易理解。设计保持本地优先，不让浏览器提交任意绝对路径，也不弱化现有路径穿越、敏感文件、符号链接和命令沙箱限制。

## 目标

- 用户能够从页面选择一个本地授权 workspace，并让后续读取、搜索、写入和命令都以该目录为唯一根边界。
- workspace 选择由服务端授权目录清单约束，浏览器只提交稳定标识，不获得扩大文件访问范围的能力。
- workspace 切换具有明确、可预测的会话重置行为，不会把一个项目的上下文或计划带入另一个项目。
- Plan/Do 模式提供可见控件并保留斜杠命令；Plan 始终只读，模型可通过普通多轮对话澄清需求并输出计划。
- 用户可对已完成的 Plan 回复执行显式的“按此计划执行”操作，系统在同一 workspace 和既有计划上下文中启动新的 Do 请求，不自动执行未确认计划。

## 假设

- OrbitCode 继续作为单用户、本机 Web 应用运行；workspace 目录由用户在未入库的本地服务端配置中预先登记，页面不负责浏览整台机器或注册任意路径。
- 每个 workspace 使用用户配置的唯一标识和显示名称。完整规范路径只在服务端用于校验和工具执行，不作为对话请求参数，也不发送给模型。
- 未配置 workspace 清单时，为兼容现有行为，OrbitCode 启动目录作为唯一默认 workspace；显式配置清单时，只允许清单中的目录。
- 一个页面会话同时只绑定一个 workspace。切换 workspace 会清空普通对话、未完成过程记录和可执行计划，并恢复 Do 模式；切换 Provider 或清空对话不改变当前 workspace。
- Plan 模式中的需求澄清使用普通助手回复与下一条用户消息完成，不新增结构化问题表单或会暂停同一 Agent 请求的交互工具。
- 计划保留在当前页面对话历史中，不额外写入项目文件或长期存储。Plan 模式不获得任何通用写入例外。
- “按此计划执行”是一次明确用户授权：仅对当前 workspace 中最新完成的 Plan 回复可用，触发后切换到 Do 并提交一条新的执行请求；不会跳过服务端模式校验、工具参数校验或 workspace 边界。

## 功能需求

- F1：服务端必须提供可用 workspace 目录清单。每项至少包含稳定唯一标识、用户可辨认的显示名称和可用状态；不得把 API Key、受保护文件内容或不必要的完整规范路径返回给浏览器。
- F2：未显式配置 workspace 清单时，系统必须把启动目录作为唯一默认 workspace，以保持现有部署可用；显式配置存在重复标识、空名称、非目录、不可访问目录或其他非法项时，必须在任何模型请求或工具执行前给出安全、可定位的配置错误。
- F3：页面必须明确展示当前 workspace，并允许用户在空闲状态选择另一个可用 workspace。模型响应或工具执行期间不得切换；不可用项不得成为当前选择。
- F4：workspace 发生实际切换时，页面必须清空当前对话历史、未完成或失败过程记录、Plan 执行动作和草稿，并恢复 Do 模式；选择当前项不得重复重置。刷新页面后使用服务端指定的默认 workspace 和 Do 模式。
- F5：每个聊天请求必须携带当前 workspace 的稳定标识。服务端必须根据自己的授权清单解析该标识并在请求时重新确认目录可用；未知、被移除、不可访问或格式非法的标识必须在创建 Agent 前被拒绝，且不得回退到启动目录或接受浏览器提供的原始路径。
- F6：服务端成功解析 workspace 后，所有文件读取、查找、搜索、创建、修改和命令执行都必须使用该 workspace 作为唯一根边界。相对路径、路径穿越、符号链接、敏感文件、原子写入、命令网络限制、环境过滤、超时和取消语义必须与现有安全约束一致。
- F7：页面必须提供持续可见、可点击的 Plan/Do 模式控件，并继续兼容严格独立的 `/plan` 与 `/do` 命令。模式切换本身不调用模型或执行工具，生成期间不可切换；页面必须同步显示当前模式及其工具范围。
- F8：Plan 模式下，服务端发给模型且实际允许执行的 workspace 工具只能是读取文件、查找文件和搜索代码。模型请求通用写入、修改、命令或其他非只读工具时，服务端必须无副作用地拒绝并返回结构化结果；提示词不能替代此权限检查。
- F9：Plan 模式允许模型通过普通最终回复提出澄清问题，用户后续回复继续保留在同一 workspace、同一模式的对话历史中；模型获得足够上下文后可输出文本计划。澄清或规划过程不应自动切换模式或产生 workspace 写入。
- F10：最新一条成功完成的 Plan 助手回复必须提供明确的“按此计划执行”操作。用户触发后，系统必须保持当前 workspace 和已有成功历史，切换到 Do 模式并提交一条新的执行请求，使模型能够依据刚才的计划自主执行；该操作在失败、取消、非最新回复或 workspace 已切换时不可用。
- F11：系统不得仅因计划生成完成、模型声称计划已获批准或页面进入 Plan 模式而执行写入或命令。除用户显式触发“按此计划执行”或在 Do 模式提交普通请求外，不得启动带副作用的工具。
- F12：workspace、Provider、模式、对话和进行中请求的页面状态必须保持一致：切换 Provider 会保留 workspace 但清空对话并恢复 Do；清空对话会保留 workspace 但恢复 Do；请求取消或失败不会改变 workspace，也不会把未完成回复变成可执行计划。
- F13：页面必须为 workspace 配置失败、清单加载失败、请求时 workspace 失效和网络失败显示可操作的安全提示；相关失败不得导致 Next.js 服务崩溃、泄露规范路径或凭据、污染后续对话历史，修复配置后应能重新加载清单并继续使用。

## 非功能需求

- N1：workspace 授权目录的解析、校验和请求级选择必须位于服务端 TypeScript 模块中；React 组件只维护不透明标识和展示状态，Agent 核心继续只依赖已经解析完成的 workspace 抽象。
- N2：浏览器提交的 workspace 标识、模式、Provider、消息和所有模型工具参数都视为不可信输入并进行严格运行时校验；服务端不得接受客户端提交的绝对路径作为授权依据。
- N3：不得为 workspace 选择弱化现有工作区边界。目录必须规范化并在每个聊天请求组装 Agent 前验证；工具仍只接受相对路径，并阻止越界、敏感文件和符号链接逃逸。
- N4：命令沙箱必须按当前请求选定的 workspace 生成隔离边界和能力探测缓存，不得沿用其他 workspace 的路径或授权结果；切换 workspace 后任何命令都不能访问上一个 workspace。
- N5：不新增运行时依赖，不引入 Agent 框架、桌面壳、服务端托管文件工具或浏览器文件上传作为 workspace 替代方案；优先复用 Node.js、现有配置解析、工作区边界和 Web API 能力。
- N6：workspace 完整规范路径不得写入模型对话、Agent 事件、工具结果、浏览器日志或错误提示；UI 只展示用户配置的名称及必要的非敏感说明。服务端日志和测试证据不得包含凭据或受保护文件内容。
- N7：workspace 和模式切换必须在桌面与窄屏页面中可辨认、可操作，并具备清晰的禁用状态、键盘焦点和无障碍名称；过程信息和执行计划操作不得与工具状态或停止原因相互覆盖。
- N8：核心依赖方向保持“页面和入口调用核心，核心调用模型与工具抽象”。workspace 目录选择、React 状态或 Next.js 请求对象不得进入 Agent Loop 的领域状态机。
- N9：workspace 清单大小、标识长度和显示名称长度必须有稳定上限；配置加载与请求解析不得产生无界内存或遍历整台机器的行为。
- N10：现有 Do 模式 Agent Loop、Plan 只读策略、多工具调度、取消、最大迭代、Provider 流处理和工具安全测试必须继续通过；新增行为需要可控临时目录和无真实凭据的自动化覆盖。

## 不做的事

- 不实现浏览器任意目录上传、拖拽目录授权、服务端原生系统目录选择器或运行时注册任意绝对路径；这些能力需要额外的平台、持久授权和威胁模型设计。
- 不同时挂载多个 workspace，不允许一次 Agent 请求跨 workspace 读取、搜索、写入或执行命令。
- 不实现最近 workspace 持久化、跨刷新恢复、数据库、用户账户、多租户、远程 workspace、Git 克隆或项目创建向导。
- 不实现结构化 `AskUserQuestion` 工具、同一 SSE 请求内暂停并等待用户输入、可编辑多选表单或 Agent 断点恢复；需求澄清通过普通多轮对话完成。
- 不把计划写入 workspace 或 OrbitCode 元数据目录，不实现计划文件浏览、版本、恢复或跨会话持久化。
- 不实现逐工具审批、命令确认、长期授权策略或自动批准。点击“按此计划执行”只授权启动一个正常 Do 请求，不跳过已有安全限制。
- 不让模型、计划文本或模式提示自动切换 workspace、Plan/Do 模式或触发执行。
- 不为 CLI 增加 workspace 选择或 Plan 执行控件；CLI 继续使用其启动目录和现有纯文本行为。

## 验收标准

- AC1（覆盖 F1、F2、F13）：分别在未配置 workspace、配置多个合法 workspace、重复标识、非法目录和不可访问目录条件下加载页面；系统依次展示启动目录默认项、合法可用清单或安全配置错误，错误发生在模型请求前，响应和日志不包含凭据或不必要的规范路径。
- AC2（覆盖 F3、F4、F12）：在 workspace A 中形成对话、草稿和完成的 Plan 回复后切换到 workspace B；页面显示 B，清空 A 的历史、草稿和执行动作并恢复 Do。切换 Provider 或清空对话保留 B，刷新恢复服务端默认 workspace。
- AC3（覆盖 F5、N2、N3）：正常聊天请求只提交 workspace ID 并成功绑定对应目录；伪造未知 ID、超长 ID、已移除 ID、不可访问目录以及额外绝对路径字段均在创建 Agent 和产生副作用前被拒绝，且绝不回退到启动目录。
- AC4（覆盖 F6、N3、N4）：在两个含同名文件的临时 workspace 中分别执行读取、搜索、写入和命令，结果始终来自当前选择；路径穿越、外部符号链接和敏感文件继续被拒绝，命令无法访问另一 workspace，切换后沙箱使用新的根边界。
- AC5（覆盖 F7、F8）：通过可见控件和独立斜杠命令往返切换 Plan/Do，模式切换不请求模型。Plan 请求中模型只看到三个只读 workspace 工具，伪造写入或命令调用返回无副作用权限拒绝；Do 恢复完整工具集。
- AC6（覆盖 F9、F11）：在 Plan 模式先提交含糊任务，模型以普通回复提出问题，用户补充信息后模型输出计划；整个过程保持同一 workspace 和 Plan 模式，文件与命令执行记录均无副作用，也不会因模型声称“开始执行”而自动进入 Do。
- AC7（覆盖 F10、F11、F12）：对当前 workspace 最新成功 Plan 回复点击“按此计划执行”，页面切换 Do 并发起新的请求，模型上下文包含此前计划且副作用只在该请求中发生。失败、取消、旧回复或 workspace 切换后的执行操作不可触发请求。
- AC8（覆盖 F12、F13）：请求期间 workspace 与模式控件禁用；取消或网络失败后仍选中原 workspace，未完成回复不进入成功历史且没有执行计划操作。workspace 在请求前失效时页面显示可恢复错误，修复后重新加载即可继续。
- AC9（覆盖 N1、N8）：类型与依赖检查证明浏览器只持有 workspace ID，服务端组装层把 ID 解析成 workspace 边界后再构造 Agent，Agent 核心未导入 React、浏览器、Next.js 或配置实现。
- AC10（覆盖 N5、N9、N10）：依赖清单无新增运行时包；workspace 数量、标识和名称上限均有自动化测试；现有 Agent Loop、Provider、Plan 权限、工具、命令沙箱、取消和 Web SSE 测试继续通过。
- AC11（覆盖 N6、N7）：真实浏览器在桌面和窄屏下可辨认当前 workspace、Plan/Do 状态、禁用状态和“按此计划执行”操作，键盘可访问且无控制台错误；浏览器请求、DOM、通知和测试输出不包含 API Key、受保护文件内容或 workspace 规范路径。
- AC12（覆盖全部需求）：`npm run test`、`npm run lint`、`npm run typecheck` 和 `npm run build` 均以退出码 0 完成；开发服务器下用两个安全临时 workspace 完成选择、隔离读取、Plan 澄清、计划确认、Do 执行、workspace 失效和取消闭环，测试后无残留服务器、浏览器、临时目录或子进程。
