# 项目指令、会话接续与长期记忆 Spec

状态：已批准

## 背景

OrbitCode 已具备 Web/CLI 共用运行编排、带修订号的会话保存、检查点、中断恢复和上下文压缩。当前提示组装提供自定义指令和长期记忆的扩展位置，但这些位置不代表项目文件加载、笔记提取与存储已经实现。现有保存流程也会保存取消、错误和达到上限的轮次，因此不能仅凭保存成功触发自动记忆。

本轮让新会话与恢复的旧会话获得项目约定、用户偏好和必要的历史背景，同时保持工具权限与会话一致性。检查点恢复对话状态，不恢复工作区文件；最终回复也不等于任务已经通过验收。

## 目标

本轮覆盖全部目标，分为三个依次交付、分别验收的部分：

1. 项目指令与恢复背景：安全加载指令，复用会话恢复与压缩，提供时间跨度提醒。
2. 长期记忆：正常回复保存后异步提取、校验和保存分级笔记，在后续请求中加载索引。
3. 会话清理：提供按 30 天规则预览和显式执行的清理能力。

两端使用同一套行为和存储语义，不复制 Agent Loop。

## 假设

以下默认值已随整份规格获批：

- “项目根目录”指会话绑定的 Workspace 根目录，不从启动目录或 Git 仓库位置另行推断。
- 指令冲突优先级为：系统安全约束与实际权限边界最高；当前用户明确要求优先于文件约定；项目级 `.orbitcode/instructions.md` 优先于根目录 `AGENTS.md`，两者均优先于用户级 `~/.orbitcode/instructions.md`。互不冲突的内容合并生效。
- `AGENTS.md` 的 include 边界为项目根目录；项目级 instructions 的边界为项目 `.orbitcode` 目录；用户级 instructions 的边界为用户配置目录。根文件计为深度 0，最多包含 5 层引用。
- 长时间中断定义为距上次成功保存的对话轮次结束时间至少 24 小时；时间跨度按真实经过时长计算。
- 自动记忆默认启用，但用户可以关闭；关闭后停止新提取任务和自动写入，不删除已有笔记。提取使用该轮已解析的模型配置，无额外工具权限。
- 自动笔记在校验通过后直接保存，不要求逐条审批；用户能检查、修改和删除。跨项目用户偏好必须有明确证据，无法判断作用域时只保存在项目级。
- 默认使用用户配置目录；显式隔离数据目录同时隔离用户级指令、记忆及任务状态，不回退读取日常用户配置。项目级资料仍来自会话明确绑定的 Workspace。
- 索引上限分别适用于用户级和各项目级索引：最多 200 行、25,000 UTF-8 字节，同时满足两项；多字节中文按字节计数。

## 功能需求

### 第一部分：项目指令与恢复背景

- F1：新会话首次运行、恢复旧会话后的首次运行及后续每轮开始时，加载三个约定来源并按上述优先级提供给 Agent。缺失文件视为无该层指令；文件读取失败须显示来源和安全诊断，阻止本轮模型执行，避免静默忽略项目约定。单纯浏览会话不调用模型。
- F2：指令支持独立行形式的 `@include <相对路径>`，路径相对于引用文件解析，按出现位置展开。只允许本地文件；拒绝绝对路径、URL、越界路径和通过符号链接逃出所属边界的引用。使用规范化真实路径的 visited 集合避免循环和重复展开，并限制深度、文件数量和累计体积。循环、重复引用可跳过并提示；越界、超深、引用文件缺失或读取失败使本轮加载失败，不向模型发送部分指令集合。被拒绝目标的内容不得读取或输出。不同根文件分别展开，保留来源层级。
- F3：加载的项目指令、include 内容不能扩大工作区、工具、网络或模式权限，不能改变系统安全约束。系统必须标明来源与优先级；遇到要求泄露凭据、越权执行或忽略系统约束的内容，仍由现有权限与执行校验拒绝相应动作，不能仅依赖提示词防护。
- F4：恢复旧会话保留原有 Provider/Workspace 绑定，复用现有修订检查、写入互斥、检查点及显式中断恢复入口。恢复前检查工具调用与结果是否配对；已记录调用但缺少结果时保留调用标识并记录“已中断、执行结果未知”，不得伪造成功、自动重放工具或回滚工作区。没有保存的执行信息不得从检查点臆造。无法安全恢复的损坏记录应阻止继续并给出可检查的错误。
- F5：恢复后的请求在发送前计入最新指令、记忆索引及时间提醒的上下文预算，必要时先执行已有压缩流程。压缩失败、容量不足和熔断沿用既有终止与恢复行为，不绕过保护。满足 24 小时阈值时，在接续轮次提供上次轮次时间、当前时间和间隔提醒，说明外部状态可能变化；不得据此自动推断文件已改变或操作已完成。重命名等元数据操作不重置此时间依据，缺少可信时间时明确未知而不编造。

### 第二部分：长期记忆

- F6：只有正常生成最终回复且该轮会话保存成功，才允许异步提交候选笔记提取任务。取消、错误、运行上限、未完成工具调用和保存失败均不触发。正常最终回复不要求任务验收成功；记忆必须区分用户陈述、工具观察和未验证推断，不将模型自述提升为项目事实。正常轮次首次保存失败、随后通过已有重试保存成功时可触发一次；重复保存、刷新与恢复不能重复产生笔记。
- F7：提取以已保存轮次的必要文本和证据为输入，仅使用无工具的模型调用，输出候选数据。提取不占用前台会话写锁等待模型，不延迟最终回复或改变该轮成功状态；设定有界的输入、输出、并发、超时和重试。失败可检查但不影响已保存对话，不无限重试。进程中断可导致尚未完成的后台任务放弃，本轮不承诺持久化任务队列；已提交笔记仍须完整且避免重复。用户关闭自动记忆或来源会话被清空、删除后，未完成任务不得继续写入。
- F8：笔记分类为用户偏好、纠正反馈、项目知识和参考资料，并独立标注用户级或项目级作用域。用户级只保存明确可跨项目复用的信息；项目事实、路径、项目专属纠正默认留在项目级。参考资料保留可核对的来源，不将链接内容视为已读取。临时任务进度、孤立日志、无依据推断、凭据和敏感认证内容不得成为长期笔记；仅有模型陈述不能证明项目事实。
- F9：用户级与项目级笔记分开存储，每条采用带 frontmatter 的 Markdown，包含稳定标识、类别、作用域、简要描述、创建及更新时间、来源轮次和验证性质。笔记正文与索引一致，索引仅包含简洁描述及受控引用。索引同时满足行数和字节上限；容量不足时保留已有有效数据，将无法加入的新候选标记为未收录，不截断为损坏文档或静默删除旧笔记。
- F10：模型可辅助识别重复、合并建议和冲突，但写入前必须由确定性校验检查结构、字段、长度、类别、作用域、来源、目标边界和凭据风险。模型不得决定任意写入路径或操作配置。相同候选不重复保存；合并保留来源，不能将较弱证据升级为已验证事实。有明确用户纠正时可替代冲突旧内容，否则不盲目覆盖。并发写入须避免丢失更新，写入失败后保持旧笔记和索引可读；人工修改后的版本不能被迟到任务无条件覆盖。
- F11：每次 Agent 模型请求前提供当前适用的用户级与绑定项目级记忆索引快照；本轮以作用域筛选，不增加语义检索。索引是可被纠正的背景资料，优先级低于当前用户要求及项目指令。正文不全量注入，Agent 确需读取时仅可通过受控只读能力访问当前作用域的索引条目；不得因此获得用户主目录或其他项目访问权。索引及按需正文都计入预算。缺失索引为空，损坏或不可读的记忆可带警告降级，不阻断正常对话；不得把未经校验的条目注入请求。
- F12：用户在 Web 和 CLI 均能查看加载来源、记忆提取及保存结果、容量或校验失败原因，以及开启/关闭自动记忆。用户能够检查、修改、删除笔记；可以复用本地 Markdown 编辑方式，不要求富文本编辑器。加载时识别人工变更并校验，下一轮刷新快照；自动提取不得仅因重新处理同一来源轮次而复活已删除笔记。修改配置或笔记本身不启动模型请求。

### 第三部分：会话清理

- F13：Web 与 CLI 提供只读清理预览：以会话最近持久化更新时间为依据，距当前时间至少 30 × 24 小时的会话进入候选。显示标识、标题、更新时间、到期依据及不能清理的原因；时间非法或来自未来时不自动判为过期。启动、列出会话或预览均不执行删除。
- F14：仅在用户明确选择并执行清理后删除候选；执行时重新检查期限、修订和活动状态。运行中、持有写租约、有待重试保存或待处理恢复的会话应跳过并说明原因。逐条报告成功、跳过和失败，允许检查部分成功。复用现有会话删除及其上下文引用清理语义，不删除工作区、指令、长期笔记或独立运行记录；来源会话删除后，已存在笔记保留来源标识并允许来源不可访问。

## 非功能需求

- N1：指令加载、记忆与清理编排由 Web/CLI 共用运行层负责，提示组装接入现有核心提示机制；核心不得反向依赖页面，不复制 Agent Loop、权限判断或会话恢复算法。
- N2：保持现有会话持久化格式与修订保护；旧会话缺少新增元信息时仍可安全打开。时间缺失和记忆为空均须有明确降级行为。
- N3：所有外部文本与模型候选均为不可信输入；目录限制覆盖路径穿越、符号链接和执行前目标变化。日志与诊断不得输出凭据、完整环境变量或越界文件内容。提取输入应尽量少，并执行凭据过滤；凭据检测不能被宣称为识别所有秘密的保证。
- N4：指令展开、索引、正文读取及后台提取均有资源上限；超过预算时给出可检查结果，不依赖模型自行遵守上限。具体工程限额在技术计划中统一定义，不能放宽本规格已明确的上限。
- N5：不新增 Agent 框架、服务端托管执行或文件能力；默认不新增运行时依赖。模型调用通过现有适配机制，并遵守同等凭据保护。
- N6：采用隔离目录和可控模型替身验证确定性边界；真实模型评估须另行明确授权，不因批准规格自动获得调用授权。

## 不做的事

- 向量数据库、向量索引、RAG 检索、团队记忆同步或跨设备合并。
- 将现有会话存储迁移为 JSONL，或另建会话恢复系统。
- 扫描子目录 AGENTS.md、全盘自动发现项目、远程 include、执行指令文件中的脚本。
- 重新设计压缩算法、工具审批或权限体系；记忆不能绕过既有边界。
- 自动重放中断工具、恢复文件快照、将旧摘要当作当前文件事实。
- 启动时无提示删除会话、定时自动删除、批量删除运行日志或长期记忆。
- 后台任务的跨重启必达保证、专用记忆模型管理或富文本笔记编辑器。
- 为历史全部会话自动补提取记忆，或仅因浏览旧会话调用模型。

## 验收标准

- AC1（F1、F3）：三个来源含冲突与非冲突规则时，新建及恢复会话的实际请求体现规定优先级；修改文件后下一轮生效。文件缺失可继续，读取失败不发送模型请求并报告来源。
- AC2（F2）：验证正常相对引用、重复与循环、深度 5/6 边界、数量/体积上限、缺失引用、绝对路径、URL、`..` 越界及符号链接越界；非法加载不发送部分指令，不读取被拒绝目标内容。
- AC3（F3、F11）：在指令和笔记中加入要求泄露凭据、执行越权命令或访问其他项目的文本，现有权限边界保持有效；普通项目约定仍能被加载。
- AC4（F4）：恢复存在无结果工具调用的会话，能观察到结果未知的中断标记且不发生工具重放；损坏记录阻止继续，修订冲突不覆盖较新状态，原会话绑定保持不变。
- AC5（F5）：恢复接近上下文上限的会话，新增指令与记忆计入预算并触发已有压缩；分别验证成功、失败、容量不足和熔断，不发送超预算请求。
- AC6（F5）：在 24 小时阈值前后及缺少时间的旧会话中恢复，提醒符合条件且不重复积累；重命名不改变轮次间隔，提醒不声称工作区状态已经得到验证。
- AC7（F6）：覆盖正常最终回复并保存、正常回复保存失败、取消、错误、超时、最大循环次数及未完成工具调用；只有满足条件的轮次产生提取任务。重试保存成功至多触发一次，重复刷新/恢复不重复生成笔记。
- AC8（F7）：通过慢响应、失败、无效响应、超时和进程中断替身验证后台处理有界；最终对话与保存状态不受影响，失败可查看，关闭自动记忆或删除/清空来源后无迟到写入。
- AC9（F8、F9）：四类笔记均可保存及检查，用户级跨项目可见，项目级不泄漏到其他项目；临时进度、无依据事实与测试凭据被拒绝，参考资料保留实际来源。
- AC10（F9）：验证 200/201 行、25,000/25,001 UTF-8 字节及中文多字节边界；超限候选显示未收录，旧索引及正文不被截坏或静默删除。
- AC11（F10）：重复候选、冲突候选、恶意路径、非法 frontmatter、并发提取、人工修改与写入中断均保持可检查结果；无丢失更新、越界写入或将未验证信息升级为事实。
- AC12（F11）：捕获实际请求，确认只注入当前作用域的有效索引，正文按需读取并计入预算；请求其他项目或未授权条目被拒绝，索引损坏可告警降级，记忆不被描述为更高优先级指令。
- AC13（F12）：在两端检查来源和任务状态、关闭自动记忆、人工修改及删除笔记；下一轮加载更新，同一旧来源不复活已删除内容，查看和修改操作不触发模型。
- AC14（F13）：在 30 天阈值前、等于阈值、超过阈值及非法/未来时间情况下预览；候选与原因准确，预览和启动前后会话数量不因清理改变。
- AC15（F14）：执行选定候选清理，同时模拟新修订、活动写入、待保存/恢复和部分失败；仅仍符合条件的会话删除，逐条结果明确，工作区、指令、笔记及独立运行记录保留。
- AC16（F1、F4、F6、F11、F12）：Web 新建会话生成已保存笔记，CLI 恢复并加载相同作用域背景，反向亦然；隔离数据目录不读取或写入日常用户级指令、记忆与任务状态。

## 审批关注点

全部目标纳入本轮；同项目指令优先级、include 边界、24 小时提醒、自动提取默认开启且直接保存、索引 25KB 的字节定义，以及后台任务不承诺跨重启必达，均为已批准的实施与验收基线。
