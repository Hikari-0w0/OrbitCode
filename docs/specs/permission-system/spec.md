# 五层权限系统 Spec

状态：已批准

## 背景

OrbitCode 已具备本地文件与命令工具、授权 Workspace 边界、敏感路径保护、macOS 命令沙箱，以及由 Plan/Do 模式控制的只读或完整工具范围。当前缺少统一的细粒度权限决策：无法用用户配置表达某类调用应允许、询问或拒绝，已知高危命令没有独立且不可覆盖的硬拦截，Web 端也不能在同一 Agent Loop 内暂停并等待用户确认。

本阶段建立由危险操作硬拦截、路径沙箱、可配置规则、权限模式和人在回路组成的五层防御。所有权限判断与工具执行均由服务端完成；权限失败作为结构化工具结果返回模型，使 Agent 能在安全边界内调整方案，而不是因一次拒绝而崩溃或无条件终止。

## 目标

- 在所有本地工具执行前经过同一个服务端权限入口，并以稳定顺序应用五层防御。
- 对已知高危命令和 Workspace 越界访问实施不可由配置、模式或人工批准覆盖的拒绝。
- 支持用户级、项目级和本地级 YAML 权限规则，并以一致、可解释的匹配和冲突合并语义得出决策。
- 提供严格、默认、放行三档权限模式，为没有显式规则匹配的工具调用给出统一默认决策。
- 当决策为询问时暂停当前 Agent Loop，在 Web 端完成一次、会话或持久授权后恢复原循环。
- 将规则拒绝、用户拒绝、危险命令和路径越界都表示为可供模型理解和纠正的结构化工具结果。

## 假设

- 权限模式与现有 Plan/Do Agent 模式是两个独立维度。Plan 模式禁止的副作用工具不会因权限模式、配置规则或人工批准而开放；Do 模式也仍受本规格全部权限层约束。
- 对没有任何显式规则匹配的调用：严格模式默认为 `ask`；默认模式对只读文件、查找和搜索调用默认为 `allow`，对写入、修改和命令调用默认为 `ask`；放行模式默认为 `allow`。
- 显式规则仅使用已注册工具的稳定名称，以及经参数校验后提取的命令或 Workspace 相对路径作为匹配对象。一个工具调用涉及多个权限目标时，每个目标都必须通过权限判断，不能用其中一个允许结果覆盖其他目标。
- `本次允许` 只绑定当前展示的工具调用及其确切参数；`本会话允许` 和 Web 端生成的 `永久允许` 都从当前调用生成精确匹配规则，不自动扩大为 glob。用户需要更宽的 glob 时，通过 YAML 配置显式编写。
- `拒绝` 只拒绝当前等待中的调用，不自动写入持久 `deny` 规则；长期拒绝通过 YAML 规则配置。
- Web 端的 `永久允许` 默认写入当前 Workspace 的本地级配置，并在确认界面明确展示保存层级。用户级和项目级规则可以通过各自 YAML 文件维护；后续技术计划可以在不改变权限语义的前提下补充持久层级选择能力。
- Web 端新增的永久精确 `allow` 与其他配置规则遵循同一合并算法；如果仍有匹配的 `ask` 或 `deny`，它不能覆盖更强规则。当前调用可由用户这次明确确认继续，但页面必须说明该持久规则未能消除后续询问；匹配 `deny` 的调用不会进入人工确认。
- 本会话指当前 Web 对话会话。清空会话、切换 Workspace、切换 Provider、刷新或关闭页面都会结束该会话并清除会话授权；授权不得泄漏到其他页面会话或 Workspace。
- 当前产品继续按单用户、本机 Web 应用设计，不在本阶段扩展到公网、多租户或分布式服务端会话。CLI 尚未接入工具执行，因此本阶段只要求 Web 工具 Agent 使用完整权限交互。
- 现有操作系统级命令沙箱、敏感文件保护、参数校验、超时和取消机制继续生效；五层权限系统是在这些安全能力之上增加统一决策，而不是替代或放宽它们。

## 功能需求

- F1：所有已注册本地工具在实际执行前必须经过统一的服务端权限决策；页面、模型、单个工具实现和调用入口不得绕过该决策直接触发文件或命令副作用。
- F2：系统必须在命令执行前应用不可配置覆盖的危险操作规则，拦截已知会破坏系统、磁盘、关键目录、进程可用性或安全边界的高危操作。命令通过组合、链式执行、子 shell 或等价包装包含被禁止操作时，也不能因外层命令看似安全而获准；命中后任何规则、权限模式或人工选择都不得放行。
- F3：所有文件工具提供的路径必须限制在当前用户授权的 Workspace 内。系统必须先校验和标准化路径，并结合真实文件系统解析现有目标、父目录及符号链接后判断边界；禁止使用容易把同名前缀目录误判为内部路径的字符串前缀比较。绝对路径、路径穿越、符号链接逃逸和解析后越界必须在文件访问前拒绝。
- F4：命令的工作目录必须解析到当前 Workspace 内，命令及其子进程继续受现有操作系统级 Workspace 隔离、敏感路径保护和网络禁用约束；权限规则或放行模式不得把命令执行范围扩大到 Workspace 外。
- F5：权限规则采用 `工具名(模式)` 表达匹配条件，每条规则的结果只能是 `allow`、`ask` 或 `deny`。模式必须支持不含通配符的精确匹配和 glob 匹配，并针对该工具经校验后的命令或规范化 Workspace 相对路径进行完整、确定性的匹配。
- F6：系统必须分别读取用户级、项目级和本地级 YAML 权限配置，将合法规则合并成统一集合。配置层级只决定读取和保存位置，不赋予规则优先级；配置缺失按空规则处理，格式错误、未知决策、无效工具名、非法模式或无法安全读取的配置必须在工具执行前给出可定位的安全错误，不能静默降级为更宽松权限。
- F7：一个调用匹配多条规则时必须合并所有匹配结果，固定采用 `deny` 高于 `ask`、`ask` 高于 `allow` 的优先级；规则出现在哪个配置层级、配置文件中的先后顺序或模式具体程度均不得改变该结果。
- F8：当没有显式规则匹配时，系统必须按当前权限模式给出默认决策：严格模式询问全部调用；默认模式允许只读文件、查找和搜索调用并询问写入、修改及命令调用；放行模式允许全部调用。权限模式只提供默认值，不能覆盖危险操作、路径沙箱、现有 Plan 限制或显式匹配规则。
- F9：Web 页面必须允许用户看见并切换严格、默认、放行权限模式，明确展示当前模式及其默认行为。客户端提交的模式视为不可信输入，最终生效模式必须由服务端校验并绑定当前会话；模式切换不能自动执行工具，也不能追溯性批准已拒绝或已经等待的调用。
- F10：当最终权限决策为 `ask` 时，系统必须在工具实际执行前暂停该调用及当前 Agent Loop，并向 Web 页面发送唯一授权请求。授权请求至少展示工具名称、经过安全处理但足以判断的调用参数、匹配或默认决策来源、风险说明、当前 Workspace 和拟授予的范围；页面不得自行计算最终权限或执行工具。
- F11：用户必须能够对等待中的授权选择本次允许、本会话允许、永久允许或拒绝。本次允许只恢复当前确切调用；本会话允许立即恢复当前调用，并在后续仅对相同精确调用满足 `ask` 确认；永久允许在服务端安全写入明确展示的配置层级后恢复当前调用，其后续效果仍服从全量规则合并；拒绝则不执行工具并恢复 Agent Loop。
- F12：每个授权决定必须绑定到唯一的等待请求和创建请求时已校验的确切参数。重复提交、过期决定、未知请求、已取消请求、会话或 Workspace 不匹配以及参数被替换的提交均不得执行工具或扩大授权。多个需要确认的调用必须分别可辨认并且只在各自获得有效决定后执行。
- F13：用户取消当前请求、清空或关闭会话、切换 Workspace 或 Provider、页面断开连接，或服务端收到取消信号时，所有尚在等待的授权都必须立即失效并结束等待，相关工具不得随后执行；Agent Loop 按既有取消语义终止并释放等待器、监听器和其他资源。
- F14：危险操作拒绝、路径越界、显式 `deny`、无效授权和用户拒绝都必须产生结构化、无副作用的工具失败结果，至少区分拒绝类别、提供安全说明并标明是否可通过调整参数或方案重试。除用户取消或既有安全停止条件外，这些失败不得直接终止 Agent Loop，模型必须能收到结果并选择替代工具、修改参数或向用户解释。
- F15：权限决策和工具执行必须保持先判定、后执行。被拒绝或等待授权的调用不得产生文件、命令或配置副作用；允许后的实际执行仍必须重新服从参数校验、Workspace 边界、危险操作硬拦截、超时、取消和工具自身执行约束。
- F16：持久授权只能由服务端写入权限配置。写入必须保持现有合法规则，避免部分文件或损坏配置，并在写入目标被替换、越界、成为符号链接、不可写或发生并发冲突时安全失败；持久化失败不得退化为本次允许，也不得执行原工具。
- F17：Web 页面必须持续展示授权请求从等待到允许、拒绝、取消或失效的状态，并在决定提交失败时给出可恢复提示。授权参数与风险信息使用安全文本或结构化视图展示，不解释为可执行内容，也不得包含 API Key、完整环境变量、受保护文件内容或不必要的绝对路径。

## 非功能需求

- N1：权限策略、规则匹配、模式默认值、授权等待与生命周期必须作为独立的严格类型 TypeScript 核心能力存在，不依赖 React 或页面组件；客户端只负责展示服务端事件和提交用户决定。
- N2：权限入口必须位于工具调度与实际执行之间并由所有 Web 工具调用复用。危险判断、路径判断和规则合并不得散落在 React 组件或复制到各个工具中形成不一致策略。
- N3：五层防御采用安全收紧顺序：现有工具可用范围与参数校验成立后，依次保证危险操作硬拦截和 Workspace 边界不可绕过，再合并显式规则，最后仅在无匹配规则时应用权限模式；`ask` 通过服务端人工确认解决，任何后层都不能放宽前层拒绝。
- N4：配置文件、规则模式、工具参数、命令文本、路径、授权标识和客户端决定均视为不可信输入，必须具有长度、数量和结构上限。畸形或超限输入不得造成无界匹配、事件循环阻塞、路径探测、命令执行或服务崩溃。
- N5：权限判定必须可解释。每个允许、询问或拒绝结果应能追溯到不可覆盖边界、匹配规则集合或权限模式默认值，但面向模型和浏览器的说明不得泄露用户主目录、配置绝对路径、内部堆栈或敏感内容。
- N6：授权等待必须支持取消且不无限占用资源；关闭流、请求中止和会话结束后不得残留可被迟到决定唤醒的等待项。未开始的工具保持无副作用，已经开始的工具继续遵循既有取消和副作用报告语义。
- N7：会话允许规则只存在于对应服务端会话状态中，并按 Workspace 隔离；永久规则的读取与写入必须位于服务端。浏览器状态、模型文本或普通对话历史都不能被当作授权事实来源。
- N8：实现不得新增 Agent 框架、托管执行能力或不必要的运行时依赖。优先复用 Node.js、现有 YAML 解析能力和已有安全 Glob 能力；确需改变依赖时必须在技术计划中单独论证。
- N9：新增权限系统不得削弱现有工具参数校验、敏感文件保护、原子文件写入、命令 Seatbelt 隔离、网络禁用、环境过滤、超时、取消、最大 Agent 迭代和结构化错误边界。
- N10：规则优先级、模式矩阵、危险操作变体、路径规范化与符号链接、授权生命周期、持久化冲突、拒绝后 Agent 恢复和 Web 交互必须能在不使用真实凭据的情况下自动化验证；页面行为还需通过真实浏览器检查。

## 不做的事

- 不实现网络请求权限规则、域名白名单或对现有命令网络沙箱提供例外。
- 不实现 CPU、内存、磁盘、Token、执行次数等资源配额。
- 不实现审计日志、审计查询、合规报表或长期保存的授权事件历史。
- 不新增删除、移动、重命名、目录管理或其他本地工具；现有工具仍是本阶段受控对象。
- 不实现用户账户、角色权限、多人审批、多租户隔离、远程授权推送或公网部署认证。
- 不允许用户为危险操作黑名单或 Workspace 路径沙箱添加例外，也不提供关闭这些硬边界的调试开关。
- 不自动把一次或会话授权概括为更宽的 glob 规则，不由模型代替用户提交授权决定。
- 不为 CLI 接入工具执行或交互式权限确认；CLI 当前纯文本行为保持不变。
- 不提供完整的权限规则图形化编辑器；Web 本阶段只展示待确认调用、权限模式和提交四种授权决定。
- 不承诺跨服务重启恢复等待中的授权或会话允许规则；持久授权只通过 YAML 配置保留。

## 验收标准

- AC1（覆盖 F1、F15、N1、N2、N3）：分别从正常 Web Agent、伪造客户端事件和直接工具调用路径触发文件或命令工具，只有经过同一服务端权限入口且最终允许的调用能够执行；拒绝和等待状态下目标文件、命令进程及权限配置均无变化，核心权限能力不依赖 React 或页面状态。
- AC2（覆盖 F2、F14、N5、N9）：用安全替身测试已知高危操作的直接形式、带参数形式、命令链、子 shell 和等价包装；全部在进程启动前得到不可覆盖的结构化危险操作拒绝。为同一调用添加 `allow` 规则、切换放行模式或提交人工允许后仍不能执行，随后 Agent 可读取拒绝结果并给出替代方案或最终说明。
- AC3（覆盖 F3、F4、F14、N9）：在临时 Workspace 中分别请求普通相对路径、绝对路径、`..` 穿越、与根目录同前缀的相邻目录、内部符号链接、外部符号链接和不存在写入目标；只有解析后仍位于根内的目标通过。命令工作目录和子进程也不能越界，所有越界拒绝均无副作用且可返回模型继续处理。
- AC4（覆盖 F5、F6、N4）：三层配置分别包含精确规则、glob 规则和不匹配规则时，系统只对已注册工具及其规范化目标产生确定匹配；缺失配置按空集合处理。重复键、YAML alias、未知工具、非法决策、非法或超限模式和不可读配置都在工具执行前成为安全、可定位的配置错误，不静默放宽权限。
- AC5（覆盖 F7、N3、N5）：让同一调用跨一个或多个配置层分别匹配 `allow`、`ask` 和 `deny` 的全部组合及不同文件顺序；结果始终满足 `deny > ask > allow`，与层级、顺序和精确或 glob 的具体程度无关，并能安全说明参与决策的来源。
- AC6（覆盖 F8、F9、N7）：在无匹配规则条件下逐一切换三种权限模式并调用只读、写入、修改和命令工具；严格模式全部进入确认，默认模式只允许只读并确认副作用调用，放行模式默认允许全部。Plan 模式中的写入或命令在三种权限模式下都保持拒绝，伪造或非法模式也不能改变服务端生效状态。
- AC7（覆盖 F10、F11、F12、F17）：触发一个需要确认的调用时，页面展示唯一请求、工具名、安全参数、风险、Workspace、决策来源和授权范围；四种选择分别产生仅本次执行、当前会话对相同精确调用满足确认、服务端写入持久精确允许和当前调用拒绝。重复、过期、跨会话、跨 Workspace、参数不一致或未知授权提交均不能执行工具。
- AC8（覆盖 F11、F16、N7）：在没有其他匹配规则时选择永久允许，对应本地级 YAML 保留既有合法规则并新增当前精确允许规则，重新加载后同一调用无需询问；仍有匹配 `ask` 时，当前已确认调用可继续，但页面提示后续仍会询问。模拟不可写文件、符号链接替换、并发修改和写入失败时配置保持有效，原工具不执行，也不隐式降级为本次或会话允许。
- AC9（覆盖 F12、F13、N6）：同一模型响应产生多个需确认调用时，每个请求均与自己的调用和参数绑定；分别允许和拒绝后只有获准调用执行且结果顺序可解释。在等待期间执行停止生成、清空会话、切换 Workspace、切换 Provider、断开页面和服务端取消，所有等待项都失效，迟到决定无效，且没有残留工具进程、等待器或监听器。
