# 跨平台命令沙箱

Web、交互 CLI、非交互 CLI 和子执行共用 `CommandSandbox`。macOS 使用 Seatbelt，Linux 使用 bubblewrap；其他平台或隔离探测失败时返回 `sandbox-unavailable`，不降级为裸 shell。

## 默认能力

- 默认允许联网，包括包源、外部开发接口及本机开发服务；没有新增命令白名单。
- 工作区保持真实路径，文件修改可直接被文件工具和 Git 观察；包安装、编译、测试和长驻服务使用相同文件树。
- 可显式授权额外可写的构建或缓存目录；默认不授权，其他未授权目录继续隔离。
- 保留 stdout、stderr、退出码、信号、超时、取消及输出截断信息。命令总时限包含能力探测等待与文件扫描；共享探测另有5秒上限，取消一个等待者不取消其他调用者的探测。长驻进程仍由当前轮的进程控制器管理，轮结束时回收其进程组。
- 两个平台的单次命令与受管进程均使用 `/bin/bash --noprofile --norc -o pipefail -c`，不读取个人 shell 配置。管道返回最右侧非零退出码，避免测试失败被末尾的 `tail` 掩盖；未开启 `errexit`，分号、`|| true`、嵌套 shell 或项目脚本仍可覆盖内部失败，整个 shell 退出0不等于测试通过。主动截断管道导致的 SIGPIPE 也可能返回非零；验证命令宜直接执行，完整输出按需保存到工作区日志。
- 子进程使用最小环境，不继承模型凭据、完整服务端环境、SSH agent 或 Docker socket。HOME 与临时缓存按命令隔离；需要持久缓存或虚拟环境时放在 Workspace 内，并显式指定工具的缓存路径或激活环境。

## Linux 安装与运行

使用发行版的系统软件包安装 bubblewrap，例如 Debian/Ubuntu：

```bash
sudo apt-get install bubblewrap bash
```

当前寻找固定路径 `/usr/bin/bwrap`。Node/npm 等项目依赖按正常方式安装；不增加 npm 运行时依赖，也不使用 Agent 框架。

Linux 镜像需要提供 `/bin/bash`；macOS 使用系统自带 Bash。缺少所需执行器时能力探测不能通过，不回退到可能隐藏管道失败的 shell。

Linux 主机必须允许非特权 user namespace，以及 PID、mount、IPC 等隔离功能。AppArmor、seccomp、管理员策略或外层容器都可能阻止这些能力；安装 bwrap 并不等于探测一定通过。调整系统策略后重新启动 OrbitCode，让能力探测重新执行。

Docker 默认策略可能阻止嵌套 namespace 或新的 proc 挂载。本仓库验证容器使用：

```bash
docker run --rm \
  --security-opt seccomp=unconfined \
  --security-opt systempaths=unconfined \
  <已准备好的运行镜像> <启动命令>
```

这些选项放宽的是外层验证容器策略，以便内部 bwrap 建立隔离，并不等于 Docker 的默认安全策略已经支持此用法。部署时应由管理员按系统条件提供适当策略；不要为了通过探测直接授予 Agent `--privileged` 或挂载 Docker socket。

运行镜像应包含所需工具链；本后端复用所在 Linux 环境的系统工具，不会自动创建题目容器、安装工具链或把宿主机命令转发至容器。整个 CLI 在既有 Linux 容器中运行时，文件工具与命令工具才会自然使用同一工作区。

## 可选配置

在“设置 → 运行偏好 → 命令安全与沙箱”保存配置。Web、交互CLI、非交互CLI均读取同一托管设置；使用 `--data-dir` 时读取该隔离目录自己的设置。每轮开始时固定沙箱配置，子Agent、独立Skill及后台子任务继承该轮实例，修改设置只影响下一轮。

| 配置 | 默认值 | 可调整范围与作用 |
| --- | --- | --- |
| 命令网络 | allow | allow/deny，允许时不预设域名白名单；只作用于命令，不影响模型宿主请求 |
| 默认命令时限 | 30000ms | 100–86400000ms，不能超过最长时限 |
| 最长命令时限 | 120000ms | 100–86400000ms；仍受本轮剩余总时限、取消与进程回收约束 |
| 临时目录 | isolated | isolated每条命令独立并清理；workspace使用 `.orbitcode-tmp` 跨命令保留；两者均通过 `$TMPDIR` 使用 |
| 安全扫描容量 | 250000项 | 1000–5000000项；提高容量不跳过依赖目录、敏感文件与硬链接检查 |
| 额外只读工具链目录 | 空 | 最多32个绝对目录，其bin加入命令PATH；原有路径校验仍生效 |
| 额外可写构建目录 | 空 | 最多32个已存在的具体目录；不能与系统、Node运行时、只读工具链、工作区或设置目录重叠 |
| 命令格式预检 | strict | strict沿用格式启发式拒绝；off关闭JSON文本、整体引号、冗余cd等格式拒绝，直接交给shell执行 |
| 命令读取.npmrc | blocked | public-only允许不含认证信息的普通公开配置只读访问；每条命令重新检查，认证配置保持保护 |
| 文件工具偏好 | true | false允许模型自行选择专用文件工具或shell管道，不改变路径授权 |
| 命令长度 | 8192字符 | 128–65536字符；系统自身的argv限制仍可能更低 |
| 命令输出容量 | 每路128KiB | 每路1KiB–16MiB；仍返回截断标记，不改变模型上下文策略 |
| 受管进程数量 | 4 | 1–64，仍在本轮结束时回收 |
| 每个进程日志容量 | 128KiB | 1KiB–16MiB，保留游标与截断信息 |
| 默认/最长就绪等待 | 10000/30000ms | 各100–1800000ms，默认不超过最长；仍受本轮取消和时限约束 |

“保存命令评测预设”会直接保存：允许联网、默认120秒/最长900秒、扫描100万项、工作区临时目录、关闭格式预检、开放公开.npmrc、关闭文件工具偏好、命令32768字符、命令输出与进程日志各1MiB、最多16个进程、默认60秒/最长300秒就绪等待。额外目录保留当前填写值，不预设授权目录或网络域名白名单。该按钮不修改上方的模型轮数、单轮总时限或任务组请求预算。

托管设置 `settings-v1.json` 可包含以下字段（旧设置无需迁移；目录与文件权限要求不变）：

```json
{
  "commandSecurity": {
    "network": "allow",
    "defaultTimeoutMs": 120000,
    "maxTimeoutMs": 900000,
    "temporaryDirectory": "workspace",
    "maxScanEntries": 1000000,
    "readOnlyRoots": [],
    "writableRoots": [],
    "commandPreflight": "off",
    "npmrcAccess": "public-only",
    "preferFileTools": false,
    "maxCommandChars": 32768,
    "outputLimitBytes": 1048576,
    "maxProcesses": 16,
    "processLogBytes": 1048576,
    "defaultReadyTimeoutMs": 60000,
    "maxReadyTimeoutMs": 300000
  }
}
```

上例仅展示安全字段，应合并进已有设置，不是完整设置文件。`run_command` 的参数上限和工具描述使用本轮实际配置，包括联网状态、命令预算和临时目录模式，避免模型在禁网状态下反复尝试下载。

凭据文件、用户记忆和未授权目录不提供整体关闭开关。`.npmrc`公开模式只影响命令沙箱，文件工具仍沿用受保护路径规则；公开模式不修改或删减原文件。检测到认证字段、环境插值、凭据URL、疑似密钥或敏感注释时，整份配置继续保护；只支持普通文件。Linux将已检查的公开内容作为只读快照挂载，macOS通过只读规则开放原路径；同用户外部进程在命令期间修改授权文件不属于隔离保证。私有包应由评测器预先安装依赖，不把认证配置交给Agent。

额外可写目录会同时开放该目录的读取和写入，应使用本次评测专用的构建/缓存目录，不能授权gold、题目数据或原始克隆目录。工作区与额外可写目录共享扫描预算及敏感inode集合，跨目录硬链接不能绕开已识别的凭据保护。

workspace临时目录不允许符号链接；其内容不会自动删除，应按需清理并加入项目忽略规则。评测评分补丁须排除 `.orbitcode-tmp` 等运行产物。提高扫描容量会增加扫描时间和内存，仍有命令总时限约束。

还可在启动进程环境中覆盖以下两个选项，**环境变量优先于托管设置**，适用于固定评测环境；其他设置继续沿用托管值。配置由用户管理，不新增模型可调用的设置工具。

```bash
# 默认就是 allow，无需设置。
export ORBITCODE_SANDBOX_NETWORK=allow

# 可选：授予额外工具链目录只读权限，并将其 bin 目录加入命令 PATH。
export ORBITCODE_SANDBOX_READ_ROOTS='["/opt/venv", "/opt/rust"]'
```

`ORBITCODE_SANDBOX_NETWORK=deny` 显式关闭命令网络；不影响 OrbitCode 自身请求模型。禁网模式下不能通过宿主机端口探测检查隔离网络内的服务，通常开发服务应保留默认联网模式。

额外只读目录必须已存在且不与 Workspace 重叠，不允许授权整个 `/`、用户目录根、`/etc`、`/tmp` 等大范围目录。子目录可以按需授权，例如具体的虚拟环境或工具链安装目录。目录内的所有内容都属于主动授权的可读数据，不能包含私人凭据；“只读”不等于“保密”。

环境覆盖只从传入的进程环境读取，不从目标题目自己的 `.env` 读取沙箱策略。主 Agent、子 Agent 和独立 Skill 继承同一个本轮沙箱实例。

## 隔离与生命周期边界

两端启动命令前共用安全扫描，覆盖依赖和构建目录、敏感文件硬链接、敏感符号链接在工作区内的真实目标。无法完成扫描时拒绝执行，不跳过无法验证的目录。macOS 使用 Seatbelt 的目录/文件拒绝规则；Linux 使用挂载遮蔽。

macOS 会阻止通过进程参数与其他进程查询接口读取未隔离父进程的环境，保留自身查询；包含敏感文件的祖先目录不能通过改名绕开保护，同目录普通文件仍可读取。

macOS 的生命周期管理使用进程组：主进程正常退出、超时或取消时，回收同组普通后代，即使后代关闭输出或忽略 TERM。主动创建新会话或进程组的后代不保证被回收，CLI 被强杀时也不提供内核级父死亡联动。脱组进程仍受继承的 Seatbelt 文件、进程查询与网络规则约束。需要强制回收任意后代时，应在支持 PID namespace 的 Linux 环境运行整个 CLI。

Linux 的具体边界：

- 从空挂载空间开始，只读映射系统运行库、当前 Node 运行时、公开的 DNS/CA 配置和明确授权的额外工具链。
- Workspace 可读写；`/tmp`、`/var/tmp`、HOME、设备和 proc 使用独立视图。沙箱在临时目录创建同名文件不会修改宿主对应路径。
- 使用独立 user/PID/IPC/UTS namespace、清空 capabilities、新会话和父进程死亡联动，防止读取宿主进程环境并回收命令后代。默认网络共享，仅显式禁网时隔离网络 namespace。
- 每次命令启动前重新扫描 Workspace，遮蔽已有敏感文件、受保护目录和 `.orbitcode` 目录；扫描涵盖依赖与构建目录，同时遮蔽已发现的敏感文件硬链接别名。超过250000个目录项或无法完成扫描时拒绝执行，不静默漏扫。
- Linux 的遮蔽基于本次启动时的文件树，不提供任意未来路径名称的内核拒绝规则。不要在命令运行期间，由外部进程向新的未遮蔽路径写入凭据或其他秘密；用户级运行数据应放在 Workspace 外。额外工具链也必须保持为可信只读内容。
- 当前不提供每条命令的 CPU、内存、磁盘或进程数量配额；仍有现有超时、输出限额与长驻进程数量限制。需要资源配额时在外层容器/cgroup 配置，避免对正常开发任务新增过紧的默认限制。

这保护的是本地工具执行边界，不能替代针对内核漏洞、同用户外部恶意进程、硬件侧信道等威胁的完整安全方案；默认联网也不是网络防泄漏策略。

## 验证

macOS 执行 `npm test` 运行本机回归。Linux 专项包含真实 bwrap、安全边界、联网/禁网、工具链、短命令与长驻进程、CLI 持久化和导出测试；模型端使用本地 OpenAI 协议替身，不调用真实模型：

```bash
npm run test:linux-sandbox
```

该命令需要 Docker，会准备独立测试镜像（默认 `node:24-bookworm-slim`）、安装仅用于验证的 Git/C++/Python/bubblewrap 工具链，依次运行 root 与普通 UID 用例，再以显式禁止 namespace 的 seccomp 策略验证拒绝执行，不依赖某个 Docker 版本的默认策略。测试镜像仅包含测试 bundle 和仓库内置角色/Skill 资源，不包含 `.env`、用户配置或目标评测题数据。

可以传入已有的兼容 Debian Node 镜像以复用本地工具链：

```bash
npm run test:linux-sandbox -- <本地基础镜像标签>
```

显式启用公网 DNS/TLS 与真实 npm 包安装补测，或指定另一架构：

```bash
ORBITCODE_SANDBOX_PUBLIC_NETWORK_TEST=1 npm run test:linux-sandbox
ORBITCODE_SANDBOX_TEST_PLATFORM=linux/amd64 npm run test:linux-sandbox
```

公网补测仅在临时工作区安装固定版本的测试包，不修改 OrbitCode 依赖；默认自动化测试使用本地包，避免依赖公网可用性。指定不同架构需要 Docker 的相应运行支持，成功构建镜像本身不代表沙箱或 CLI 验收通过。

Linux 用例在 macOS 的普通测试中显式跳过，不能把这些跳过项称为 Linux 验证通过；以专项容器测试结果为准。原生 Linux 上也可在满足条件后定向运行这些测试文件。

## 环境文件与 macOS 目录兼容选项

`environmentFileAccess` 默认 `blocked`，设为 `allow` 后，命令可读写工作区及额外可写目录中的 `.env`、`.env.*`。这会开放目录内已有环境文件的内容，适用于无私人凭据的隔离评测目录；专用文件工具仍保持原配置文件保护，其他凭据、保护目录和关联硬链接仍受保护。

`macosAncestorDirectoryAccess` 默认 `metadata`，设为 `read` 后允许打开授权路径的祖先目录本身，用于兼容 Bun 等需要逐级打开目录的运行时。可能看到祖先目录中的名称，但不开放其未授权子树文件内容，也不放开进程信息读取。Linux 不使用此选项。

两项均可在“设置 → 运行偏好 → 命令安全与沙箱”保存，命令评测预设启用 `allow` / `read`。旧设置缺少字段时沿用默认保护，配置从下一轮生效。复现、实际验证和限制见 [运行摩擦改善](evals/friction-improvements-2026-10-28.md)。

## 调度时限、失败处理与短目录

命令最长时限会贯通共享Runtime与外层调度器，不再被调度器固定压为120秒；命令参数、本轮总时限和取消仍能提前结束。受管进程就绪等待使用本轮配置预算。

`temporaryDirectory: short` 为工作区创建系统临时目录下的专属0700短路径，用于Unix socket与跨命令缓存。命令通过 `$TMPDIR` 访问，npm、pnpm、Bun和XDG缓存指向其中cache子目录。只授权该目录，兄弟目录和整个系统临时目录不开放。短目录需按需清理，评测预设默认使用此模式。

工具失败策略属于运行偏好 `toolFailurePolicy`：strict保留原停止预算，exact仅对相同参数重复失败停止，warn只提醒。旧设置保持strict，独立评测入口使用warn，仍受运行总预算和权限边界约束。`process_status` 可通过wait_ms/wait_for等待新日志或退出，减少sleep轮询。详见[调度预算与局部对照](evals/budget-limits-repair-2026-10-28.md)。
